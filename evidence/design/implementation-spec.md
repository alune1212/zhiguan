## 容器与响应式

- 顶部只保留文字品牌、四阶段进度和“退出当前会话”。
- 桌面宽屏采用开放式双栏：左侧当前输入/确认摘要，右侧结果及“查看依据”；分隔依靠网格和细线，不嵌套多层卡片。
- 决定与导出阶段使用单一内容列和分区标题，避免把五种决定或两种格式做成营销式卡片。
- 窄屏转为单列，阶段进度不产生横向滚动；所有触控目标至少 `44px` 高，底部操作自然换行。
- 页面允许纵向滚动，不依赖 hover、精细指针、颜色、位置、声音或倒计时表达状态。

## 允许的核心可见文案

- 阶段：`输入与期待`、`确认口径与状态`、`理解与推演`、`决定与复盘交接`。
- 结果：`Income Rate`、`Work-time Equivalent`、`覆盖范围内可用余量`、`购买后余量`、`购买影响`。
- 财务状态：`用户确认`、`估算`、`预测`、`数据不足`；工作流状态另行显示，不能成为第五类财务状态。
- 决定：`购买`、`等待`、`调整条件`、`不购买`、`暂不决定`。
- 导出：分别预览/确认 `JSON` 与 `Markdown`；请求正常返回后只说 `已发起下载请求；设备是否保存及位置未知`。
- 隐私：当前页面内存、刷新/关闭清除、主动本地导出例外、文件下载后由用户设备控制、产品外人工复盘、原型不代替正式研究同意且不保存研究观察。

字段错误、数据不足、导出失败和退出均使用平静、具体、可行动的文字；不得出现推荐、排名、正确/错误评价、催促、羞辱、完成率压力或“已保存”保证。

## 组件与交互边界

- `StageProgress`：语义化有序列表及当前步骤文字。
- `PrivacyNotice`：第一项输入前可理解，退出入口始终可达。
- `InputSection`：可见标签、必填/可选、单位、状态、关联错误和确认动作。
- `ResultList` / `EvidenceDetails`：完全消费规则结果，不在 UI 复算。
- `DecisionSection`：五项单选、必填依据、可选产品外人工复盘条件或日期。
- `ExportPreview`：逐格式状态与确认，取消不影响决定或退出。
- `SessionExit`：清除应用内存和临时对象，不声称停止研究者服务或删除已下载文件。

不得增加账户、登录、导航体系、云端、同步、提醒、联系人、招募、研究记录、商品链接、分享、导入、恢复或后台任务。
