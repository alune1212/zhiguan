## 唯一差异

case-17：`我月收入 9,000 元，税前还是税后我说不清，想买 2,000 元的灯。`

预期收入金额保留 `9,000 / present`，税口径为 `null / ambiguous`。模型将收入金额也输出为 `ambiguous`，置信度 0.54；税口径和价格判断正确。这是过度保守的漏填，不是编造数值。请求标识：`req_01a0c31b1bd57143a52e88aa2d2ffe91`。

没有针对结果修改提示或重跑。后续若继续验证，应明确区分“金额是否清楚”和“税口径是否清楚”，使用新增未见样本检验，不能把本轮案例调通视为泛化证明。

## 解释边界

`present` 表示原文提供候选，不表示 actual 或 user-confirmed；全部输出仍待用户确认。近似数保留 estimated。脚本仅回传候选数字原文，不处理金额数值转换；因此本轮不证明自动填表或产品收益。

本轮未触发“无依据填值或歧义被确定即不进入产品”的阻断条件，但 20 条自建样本不证明中文总体准确率、安全性或减少输入负担，产品联网接入仍未批准。样本是虚构的，未上传个人财务数据。
