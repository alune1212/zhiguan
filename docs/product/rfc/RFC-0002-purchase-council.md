新宪法全文就是本 PR 中的 [PRODUCT.md](../../../PRODUCT.md)。下面不另抄一份，只说明相对 0.2.0 保留、改写和删除了什么。按当时的修订规则，改变产品定义、循环、隐私边界和北极星必须先有 RFC；这次是按该规则做的最后一次全文重写。1.0.0 生效后，以后的改法以新宪法第 6 节为准。

## 动机与偏离

负责人确认：产品方向偏了。

0.1.0 把产品收成一条可以复盘的价值判断。[品牌指南](../../design/brand.md) 写过，实时数字可以吸引注意，品牌要帮用户完成理解、推演、决定和复盘。[RFC-0001](RFC-0001-income-understanding.md) 把「看懂收入」收成一次可以独立完成的使用，月度价值闭环用户数不再作为每项功能的前提。[PRD-0003](../prd/PRD-0003-income-dashboard.md) 随之把首页做成收入动态看板：今日累计、本月累计、每秒速率，计算在 `src/domain/income.ts`。

这条路径已经实现，自动检查和合成数据下的浏览器主路径也通过了。负责人现在的判断是：用户停在跳动的数字上，没有进入购买决定。这正是当初要避开的结果。收入理解仍然有用，它不再是产品本身。

新的核心场景也已由负责人确认。用户犹豫一笔购买，例如一台不便宜的吸尘器。用户输入价格、类别、预计使用频率和想买的理由。系统用已保存的收入资料做一张事实卡。一组可编辑的人物讨论这张卡，给出倾向、理由、风险和「如果……就买 / 就等 / 就先不买」。用户自己选现有五种决定。

| 用户拥有数据和决定权，包括查看、导出、更正、删除，以及只收集这笔讨论需要的数据 | 原则 2。外发改为每份新载荷预览确认，最小化仍在 |
| 五种证据状态；不够就写数据不足；不用零、旧值或猜测填补 | 原则 3 |
| 每个数字可解释 | 原则 3。解释路径收成事实卡 |
| 不羞辱、不操纵、不制造焦虑；不排名；不做人生总分 | 原则 4，以及「明确不做」 |

| 负责人是 Alune | 元数据 |

已实现的收入计算、本地资料、购买快照和 Jev 填表识别都还在。本 RFC 不回滚这些代码。

## 相对 0.2.0 改了什么

| 0.2.0 | 1.0.0 | 原因 |
| --- | --- | --- |
| 类别是个人价值流（Personal Value Flow） | 类别是购买决策讨论 | 七阶段框架已经不能描述现在要做的事 |
| 七项用户任务并列，收入理解可以单独算一次完整使用 | 核心任务是一笔购买犹豫 | 负责人确认首页看板没有带来决定 |
| 北极星是看懂收入；月度价值闭环用户数留作长期观察 | 北极星是用户自己收下的购买讨论。循环是决定 → 回访 → 共享真实回访 | 闭环留在路线图的后两段，不拿阶段一当完整闭环 |
| 收入看板数据不得离开设备；模型例外只有 ADR-0007 的字段识别 | 收入绝对值可以发给模型。每次发送前全文预览并确认。应用不记日志 | 负责人明确允许。边界改到 [ADR-0009](../../adr/ADR-0009-llm-purchase-discussion.md)，不写进原则的空话 |
| 九条原则、十问准入、六个月复审、完整 RFC 模板 | 六条原则。只有不兼容的边界变化才写一页短 RFC | 一个人维护的仓库，套完整仪式仍没拦住方向偏离 |
| 历史可追溯单列为宪法第 5.8 节 | 事实卡带规则版本；旧收藏仍不按新资料改写。细节在 ADR 和 PRD | 要求还在，不再占宪法篇幅 |
| 低输入负担单列为原则 | 阶段一要填哪些字段，写在 PRD-0004 | 输入清单会变，原则不必跟着改 |

首页在 1.0.0 正文里当时没有写死。2026-11-11 负责人已决定：首页改为「讨论这笔购买」，原来的秒薪看板降为收入资料页，不删除。要求见 [PRD-0004](../prd/PRD-0004-purchase-council.md)。

## 相对 0.2.0 删除什么

- **七阶段循环**（采集、统一、理解、推演、决定、复盘、学习）不再作为产品结构。决定和回访留在新循环里，其余阶段不再单独立项。
- **宪法里的对象清单**：收入流、订阅、物品、目标、情景、价值维度等。需要时由具体 PRD 定义字段，不在宪法里预留一套未实现的模型。
- **月度价值闭环用户数（MVLU）**。定义留在 RFC-0001，不再作为现行指标。没有测过，也不为了测它去建账户或行为上报。
- **「收入不得发送给模型」** 这一条总禁令。Jev 填表路径仍按 ADR-0007，不发送完整资料。购买讨论路径改按 ADR-0009。
- **功能准入十问、六个月复审清单、决策最低记录模板。** 阶段一的验收改由 PRD-0004 承担。

RFC-0001 保持原状，作为 0.2.0 的历史决定。它的宪法效力由 1.0.0 替代。

## 对原则、循环、对象和指标的影响

愿景从「看见资源流向」收成「在一笔购买前看清自己的数字，听完不同说法，自己决定」。品牌承诺没改。

非目标里，记账、投资、导购、排名、人生总分、监控和强行货币化仍然拒绝。新写明的拒绝是：模型不计算、讨论不裁决、阶段一不做回访和公开分享。

核心对象不再由宪法枚举。阶段一的事实卡、人物和综合结果见 [PRD-0004](../prd/PRD-0004-purchase-council.md)。

指标只保留北极星的定性定义。不设人数目标，不把模型调用算成价值。证据状态沿用五种，指标文件已改指向 1.0.0。

## 数据、隐私与误导

负责人决定：购买讨论可以把收入绝对值发给模型服务商。这覆盖了「看板数据不得出设备」的旧边界，也比 ADR-0007 更宽。ADR-0007 继续约束 Jev 填表，不负责这次讨论。

同时收紧的是过程，不是把数据再藏回去：

- 每次载荷变化都先给用户看全文，确认后才发送；
- 应用不记录请求正文和响应正文；
- 密钥只在服务端；
- 服务商是否留存，预览里照实说明，本产品不替服务商承诺删除；
- 用户不确认，仍然可以看事实卡并自己做五种决定。

误导风险单独列出：

| 风险 | 阶段一怎样处理 | 仍可能发生 |
| --- | --- | --- |
| 人物措辞让人焦虑或感到被羞辱 | 提示约束，加上一份施压用语表。命中的句子用户看得到，但不进入下一轮 | 换一种说法仍可能施压 |
| 人物顺着用户说 | 第一轮互不可见。至少一位反对角色。综合必须写下分歧；反对意见缺失时写明缺失 | 反对角色也可能同意购买 |
| 模型编造数字 | 数字只能来自事实卡的引用字面量。对不上的句子不进入后续讨论 | 中文数量说法靠规则拦截，拦不住就整句退出后续讨论 |
| 收入离开设备 | 全文预览、可拒绝、应用不记日志 | 服务商和托管平台可能留下连接或内容，预览必须说明 |

没有广告、佣金或购买导流。倾向不是商家建议。

## 备选方案

1. **看板继续做首页，只加一个购买入口。** 开发少，但没有改掉「只看数字、不做决定」。不采用。
2. **在 0.2.0 上打一块补丁，保留七阶段、对象清单、月度价值闭环用户数，以及收入不得出设备。** 负责人本轮要求全文重写。那些结构已经不是现行产品。不采用。
3. **上多智能体框架，让人物自己调用计算工具。** 数字会不可复算。阶段一用一次并行调用加结构化输出，计算留在现有代码。不采用框架。
4. **让模型直接给出买或不买。** 与品牌承诺冲突。不采用。
5. **只发送工时比例，不发送收入绝对值。** 能少暴露一些数据。负责人选择允许绝对值，并用预览确认换取人物可以说清楚的金额。不采用只发比例。
6. **直接做账户和公开回访。** 阶段三才需要账户、审核和备案。阶段一不做。

服务商和保管密钥的服务已由负责人定在 PRD-0004：DeepSeek，以及一个小型 Hono 服务。本 RFC 不另写一份，也不写入任何模型价格。

## 已有数据、接口和文档

没有用户迁移。本地资料格式 `zhiguan-local-backup@1` 和购买快照 `@1`、`@2` 都不在本 PR 里修改。人物设定和讨论记录若要落地，必须用新的本地格式或单独的存储键，并仍能读入旧备份。这一点写在 ADR-0009。讨论完成后自动保存，是后来写进 PRD-0004 的要求。

本 PR 不改应用代码，因此打开应用的行为与改这些文档之前一致。

文档同步见文末清单。归档的 OpenSpec 和 RFC-0001 保持历史原文。

## 怎样算这次改方向是对的，以及何时退回

阶段一没有上线数字。本 RFC 生效只说明方向成立，不说明功能已验证。

阶段一上线后，用负责人自己的使用和明确范围内的反馈看三件事：用户能不能看懂事实卡和倾向的差别，五种决定是不是自己选的，有没有人把讨论体验成被评判。不新增行为上报。没有这些观察，就不宣称方向已被验证。

退回：

- 本 PR 合并前若否定方向，关闭 PR，不合并。
- 合并后、写讨论代码前若否定方向，把 PRODUCT.md 恢复为 0.2.0 正文，并在版本记录写明恢复。
- 讨论功能已经可用之后若要停：关掉讨论的外发路径，事实卡和五种决定可以留下。是否把宪法改回去，另写一页短 RFC。
- 出现下列任一情况，先停外发，再改文案或校验：预览可以被跳过；应用记下请求或响应正文；未通过事实卡校验的数字进入了下一轮；人物输出被用户读成必须执行的裁决；讨论明显在羞辱或制造焦虑。

复审日见文首。1.0.0 不再要求每六个月一次固定复审。
