# 值观产品术语表

**版本：** 1.0.0
**更新日期：** 2026-11-11

本术语表统一中文名称与稳定英文术语。界面可以根据语境使用中文。API、数据字典、指标和文档中的英文术语保持一致。改变产品边界的术语，按 PRODUCT.md 第 6 节处理。

现行类别是「购买决策讨论」。下表增补阶段一用语。0.2.0 的「个人价值流」「七阶段价值循环」「月度价值闭环用户数」只用于阅读旧文档，不再是现行宪法术语。

| 中文术语 | 稳定英文术语 | 定义与使用边界 |
| --- | --- | --- |
| 购买决策讨论 | Purchase decision discussion | 现行产品类别。用户为一笔犹豫中的购买查看事实卡，并听取一组人物的讨论。 |
| 亲友团 | Purchase council | 用户可编辑的一组人物。出厂模板包括家人、伴侣、朋友、「5 年后的你」，以及默认关闭的上司。 |
| 事实卡 | Fact card | 由代码写出的确定性 JSON。每小时收入和工时等价沿用现有购买计算；一个工作日的收入、日成本和单次成本按 PRD-0004 的公式计算。人物只能引用卡上的数字字面量。 |
| 倾向 | Leaning | 综合给出的方向：更倾向现在买、再等等、这次先不买、先换个条件，或没有形成倾向。倾向不是裁决，也不预选五种决定。 |
| 改变条件 | Change condition | 「如果……就买 / 就等 / 就先不买 / 就换条件」。说明倾向在什么条件下会不同。 |
| 反对角色 | Pushback persona | 至少一位人物负责提出再等等或不买的理由，避免讨论只顺着用户说。 |

## 仍在使用的术语

这些词描述已经实现的资料、看板和购买计算，或 1.0.0 仍然使用的证据状态。

| 中文术语 | 稳定英文术语 | 定义与使用边界 |
| --- | --- | --- |
| 值观 | Zhiguan / 值观 | 产品与品牌名称；不要写成 ZhiGuan、Zhi Guan 或“值观记账”。 |
| 决定记录 | Decision Record | 用户自己选择的五种决定之一，以及当时写下的依据。 |
| 回访 | Review | 阶段二里，用户在购买之后记下使用和自己的判断，并和当时的讨论对照。 |
| 事实 | Actual | 由明确来源、时间和口径支持的已发生数据；仍可被更正。 |
| 用户确认 | User-confirmed | 用户明确核对或批准的数据；确认不等同于外部事实证明。 |
| 估算 | Estimated | 根据已知输入和明确假设推导的近似值；必须展示假设。 |
| 预测 | Forecast | 对未来结果的情景或模型推断；必须展示范围、依据和不确定性。 |
| 数据不足 | Insufficient-data | 缺少必要来源、口径或覆盖范围，无法安全得出结论。 |
| 基础资料 | Saved Profile | 用户主动保存、供后续复用的收入与作息等稳定条件；当前只在同一浏览器保存。 |
| 收入看板 | Income Dashboard | 已实现的今日、本月与每秒收入估算。它不是现行产品本身，也不进入事实卡的今日累计。 |
| 当月日历工作时间 | Monthly Scheduled Work Time | 根据选定时区、周作息和日期覆盖得出的当月计划工作秒数。 |
| 单次工作时间覆盖 | One-off Work-time Override | 旧购买页里，用户为一次比较选择的平均作息或直接月工时。阶段一的事实卡不使用这项覆盖。 |
| 购买收藏 | Purchase Favorite | 用户主动保存的购买输入、比较口径和计算快照；基础资料改变后不按新规则重算。 |
| 收入速率 | Income Rate | 在明确周期和工作量口径下，收入相对于时间的速率。事实卡里的每小时收入沿用它。 |
| 工作时间等价 | Work-time Equivalent | 把一个金额按收入速率换算为时间。不是人生价值换算。 |
| 固定成本 | Fixed Cost | 用户为本笔讨论填写的月固定支出。不填则余量为数据不足。 |
| 单次使用成本 | Cost per Use | 事实卡上的购买价格除以预计使用次数。算不出时为数据不足。不代表体验价值。 |
| 可解释性 | Explainability | 用户能理解结果的来源、口径、计算、假设和限制。 |
| 数据主权 | Data Sovereignty | 用户能查看、导出、更正、删除自己的资料，并在每份新载荷发送前确认。 |
| 来源与证据 | Provenance | 数据来自用户、导入、计算或外部资料的记录，包括授权、时间、口径和变更历史。 |
| 对话输入 | Conversational Input | 已实现的 Jev 填表。模型只做有界识别，不等于购买讨论。 |
| 待确认摘要 | Pending Summary | 对话或手动输入整理后的同一份可编辑草稿；整体确认前不等于用户已确认数据。 |
| 最少上下文 | Minimal Context | Jev 填表为理解当前回答而发送的当前问题和必要字段。不包含完整事实卡。 |
| 证据状态 | Evidence Status | Actual、User-confirmed、Estimated、Forecast 或 Insufficient-data。 |
| 价值判断 | Value Judgment | 用户基于自身优先级对结果的理解。产品提供证据，不替用户定义。 |

## 0.2.0 历史术语

只用于阅读旧文档。它们不是现行宪法里的对象或阶段。

| 中文术语 | 稳定英文术语 | 定义与使用边界 |
| --- | --- | --- |
| 个人价值流 | Personal Value Flow | 0.2.0 及以前的类别名。 |
| 价值循环 | Value Loop | 0.2.0 的七阶段结构。现行循环是决定 → 回访 → 共享真实回访。 |
| 记录 | Capture | 七阶段之一。用户或授权来源提供一项资料。 |
| 统一口径 | Normalize | 七阶段之一。换算货币、周期和时间，使记录可比较。 |
| 理解 | Understand | 七阶段之一。呈现关系，不自动产生价值判断。 |
| 推演 | Simulate | 七阶段之一。对尚未发生的选择做情景比较。 |
| 学习 | Learn | 七阶段之一。按用户认可的口径调整工具，不对人格下结论。 |
| 收入流 | Income Stream | 旧对象。一种收入来源及其金额、周期和税口径。 |
| 时间投入 | Time Input | 旧对象。用户愿意纳入比较的时间。 |
| 成本项 | Cost | 旧对象。一次性或周期性金钱成本。 |
| 固定成本负担 | Fixed Cost Load | 旧指标。固定成本相对于收入或余量的关系。 |
| 净积累 | Net Accumulation | 旧指标。可确认收入减去可确认成本，不是总资产。 |
| 目标 | Goal | 旧对象。宪法 1.0.0 不再单列目标。 |
| 购买推演 | Purchase Simulation | 旧说法。现行任务是购买讨论，不把「目标影响」当作必填维度。 |
| 情景 | Scenario | 旧对象。尚未执行的假设组合。 |
| 订阅 | Subscription | 旧对象。周期性付费的服务。 |
| 物品 / 服务 | Possession | 旧对象。用户拥有或使用的物品、权益。 |
| 价值维度 | Value Lens | 旧对象。用户自己命名的比较视角。 |

## 用词规则

- “价值”不等于价格、收益或使用频率；必须说明价值由谁定义、依据是什么。
- “回本”不得作为默认目标或唯一成功标准。用户若自己要看，也只是一个可解释的算法，不是价值判断。
- “实时”只描述刷新方式，不暗示数据真实、完整或具有决策意义。
- “智能建议”必须说明证据来源、假设和不确定性；数据不足时应使用“无法判断”或同等明确表达。
- 任何指标、图表和叙述都必须同时给出时间范围、口径与证据状态。
