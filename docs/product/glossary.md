# 值观产品术语表

**版本：** 0.1.0
**更新日期：** 2026-08-20

本术语表统一中文名称与稳定英文术语。界面可根据语境使用中文，但 API、数据字典、指标和文档中的英文术语应保持一致。若新增术语改变产品边界，应先通过 RFC。

| 中文术语 | 稳定英文术语 | 定义与使用边界 |
| --- | --- | --- |
| 值观 | Zhiguan / 值观 | 产品与品牌名称；不要写成 ZhiGuan、Zhi Guan 或“值观记账”。 |
| 个人价值流 | Personal Value Flow | 产品类别；描述个人时间、收入、成本、目标、拥有和结果之间的可解释流动。 |
| 价值循环 | Value Loop | Capture → Normalize → Understand → Simulate → Decide → Review → Learn 的完整循环。 |
| 记录 | Capture | 用户或授权来源提供一项事件、口径、目标、拥有或结果；不等于系统已验证。 |
| 统一口径 | Normalize | 明确货币、周期、时间、工作量和计算规则，使不同记录可比较。 |
| 理解 | Understand | 从有来源的数据中呈现关系、影响和余量；不自动产生价值判断。 |
| 推演 | Simulate | 对可能选择建立情景比较；情景不是事实，也不是保证的预测。 |
| 决定记录 | Decision Record | 用户保存的选择、不选择、理由、依据与后续复盘入口；是产品对象“决定”的稳定名称。 |
| 复盘 | Review | 在之后的时间回看输入、结果、偏差和用户自己的判断。 |
| 学习 | Learn | 更新用户认可的口径或偏好；不是暗中改变排序或操控行为。 |
| 事实 | Actual | 由明确来源、时间和口径支持的已发生数据；仍可被更正。 |
| 用户确认 | User-confirmed | 用户明确核对或批准的数据；确认不等同于外部事实证明。 |
| 估算 | Estimated | 根据已知输入和明确假设推导的近似值；必须展示假设。 |
| 预测 | Forecast | 对未来结果的情景或模型推断；必须展示范围、依据和不确定性。 |
| 数据不足 | Insufficient-data | 缺少必要来源、口径或覆盖范围，无法安全得出结论。 |
| 收入流 | Income Stream | 一种收入来源及其金额、周期、有效时间和税前/税后口径。 |
| 时间投入 | Time Input | 用户愿意纳入比较的工作或其他时间，必须说明范围、口径和证据状态。 |
| 成本项 | Cost | 一次性或周期性金钱成本，包含金额、币种、发生时间和持续性。 |
| 收入速率 | Income Rate | 在明确周期和工作量口径下，收入相对于时间的速率；不默认等于时薪。 |
| 工作时间等价 | Work-time Equivalent | 把一个金额按用户选定的收入/工作时间口径换算为时间；不是人生价值换算。 |
| 固定成本 | Fixed Cost | 用户在指定周期内预计重复发生、相对稳定的成本；周期变化须保留历史。 |
| 固定成本负担 | Fixed Cost Load | 指定周期内固定成本相对于可用收入或可用余量的关系；分子、分母和周期必须可见。 |
| 净积累 | Net Accumulation | 在明确时间范围与口径下，可确认收入减去可确认成本后的余量；不是总资产或财富排名。 |
| 目标 | Goal | 用户主动定义的金额、时间、体验或选择余量目标；目标不必须是财务目标。 |
| 购买推演 | Purchase Simulation | 购买前比较价格、工作时间、目标影响、使用假设和可用余量的情景。 |
| 情景 | Scenario | 尚未执行的假设组合，与真实记录隔离并标明预测时间、范围和不确定性。 |
| 订阅 | Subscription | 在周期性付费下持续提供某项服务或权益的安排；价值由用户定义并可复盘。 |
| 物品 / 服务 | Possession | 用户拥有、租用、使用、转让或记录的实体物品、数字物品或服务权益。 |
| 单次使用成本 | Cost per Use | 在明确拥有成本与使用次数口径下计算的近似成本；不代表体验价值。 |
| 可解释性 | Explainability | 用户能理解结果的来源、口径、计算、假设和限制。 |
| 数据主权 | Data Sovereignty | 用户能知道、控制、导出、更正、删除和撤回授权数据。 |
| 输入负担 | Input Burden | 为获得长期价值而要求用户提供、维护和修正信息的时间与认知成本。 |
| 来源与证据 | Provenance | 数据来自用户、导入、计算或外部资料的记录，包括授权、时间、口径和变更历史。 |
| 价值维度 | Value Lens | 用户主动启用或命名的比较视角，如时间、体验、便利、关系或目标；系统不得强加统一权重。 |
| 证据状态 | Evidence Status | 记录或指标所属的 Actual、User-confirmed、Estimated、Forecast 或 Insufficient-data 类别。 |
| 价值判断 | Value Judgment | 用户基于自身优先级对结果的理解；产品提供证据，不替用户定义。 |

## 用词规则

- “价值”不等于价格、收益或使用频率；必须说明价值由谁定义、依据是什么。
- “回本”只可作为用户自定义的一个情景指标，不得作为默认目标或唯一成功标准。
- “实时”只描述刷新方式，不暗示数据真实、完整或具有决策意义。
- “智能建议”必须说明证据来源、假设和不确定性；数据不足时应使用“无法判断”或同等明确表达。
- 任何指标、图表和叙述都必须同时给出时间范围、口径与证据状态。
