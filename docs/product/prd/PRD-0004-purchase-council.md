# PRD-0004：购买决策亲友团（阶段一）

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted。2026-11-11 随 RFC-0002（PR #5）生效。功能尚未实现 |
| 负责人 | Alune |
| 范围 | 一个用户、一笔购买、一次本地讨论。不含回访和公开分享 |
| 依据 | [PRODUCT.md](../../../PRODUCT.md) 1.0.0、[ADR-0009](../../adr/ADR-0009-llm-purchase-discussion.md) |

阶段一让用户带着自己的数字，听一组人物讨论一笔犹豫中的购买，然后自己做决定。计算沿用 `src/domain/income.ts` 与 `src/domain/calculation.ts` 的确定性结果。模型不计算。

## 用户任务

用户不想为了一台吸尘器先学记账，也不想只看每秒收入一直跳。用户希望写下价格和为什么想买，看到这笔钱相当于多少工作时间、一个工作日的收入大概是多少、买完这个月还剩多少（算得出的时候），再听几个立场不同的人用这些数字说话。听完以后，买不买仍然自己选。

### 用户故事

1. 用户填写价格、类别、预计使用和想买的理由后，能看到一张由已保存收入资料算出的事实卡，此时还没有请求模型。
2. 用户可以改人物的名字、关系、性格、在意的事和对钱的态度，也可以先用家人、伴侣、朋友和「5 年后的你」。
3. 每份新载荷发给模型之前，用户能看到即将发送的全文，包括这一轮综合会收到什么。不确认就不发送，事实卡和五种决定仍然可用。同一份载荷失败后的重试不再问一次。
4. 第一轮里每个人独立回答，谁也看不到别人的发言。只有用户要求时，才进行第二轮互相应答。
5. 用户读到倾向、理由、风险和改变条件。页面不把倾向写成裁决，也不替用户勾选五种决定。
6. 人物说出事实卡上没有的数字时，那一句会标出来，并且不会进入后面的讨论。

## 输入

比较货币仍是 CNY。月收入使用已保存的看板资料，按到手收入进入事实卡，不再另问税前税后。没有有效资料时，先走现有的收入设置，不在讨论页里平行做一套收入表单。

讨论页收集：

| 输入 | 是否必须 | 说明 |
| --- | --- | --- |
| 购买价格 | 必须 | 沿用现有金额解析。用户可标明这是大概数，则证据为 estimated，否则为 user-confirmed |
| 类别 | 必须 | 自由文本，最长 40 字。阶段一不建词表 |
| 想买的理由 | 必须 | 最长 500 字。超长时请用户改短，不截断后发送 |
| 使用频率 | 可选 | 「每天」或「每周」多少次。暂不提供「每月」，避免悄悄按 30 天换算 |
| 预计持有天数 | 可选 | 正整数。没有默认天数 |
| 本月固定支出及是否已完整覆盖 | 可选 | 规则与 PRD-0001 的余量相同。不填则余量为数据不足，不阻塞其余结果 |
| 储蓄或应急金 | 可选 | 一个金额。不填则事实卡不出现该字段，不按零发送 |

价格缺失、为零、为负或超限时，不生成讨论。其余可选项缺失只让依赖它们的事实卡字段变为数据不足。

阶段一的事实卡只用已保存的日历资料：当月计划工作秒数和工作日。不把旧购买页的平均作息或直接月工时覆盖带进这张卡。

## 事实卡

格式标识：`zhiguan-purchase-fact-card@1`。它是讨论的内部契约，不是给别人交换的公开文件。每个数字都带证据状态、公式或不足原因，并保留现有精确有理数。展示舍入沿用 ADR-0002。

| 字段 | 来源 | 证据 | 算不出时 |
| --- | --- | --- | --- |
| 月收入 | 已保存资料里的到手月收入 | 用户保存过则为 user-confirmed | 没有有效资料则整张卡不可用 |
| 每小时收入 | `calculateDecision` 的 `income-rate`。月工时取 `calculateIncome` 的当月计划工作总秒数 | estimated。作息换算的工时保持估算 | insufficient-data |
| 一个工作日的收入 | 月收入 ÷ 当月计划工作日数。工作日指日历上计划工作秒数大于 0 的日期，不用「今日已过去的收入」 | estimated | 工作日数为 0 时 insufficient-data |
| 工时等价 | `work-time-equivalent`：购买金额 ÷ 每小时收入 | 与现有购买结果的状态规则一致 | insufficient-data |
| 本月可用金额 | `available-margin` | 与 PRD-0001 相同 | 未提供完整固定支出时 insufficient-data |
| 买完后本月还剩 | `purchase-after-margin` | 可计算时为 forecast | 同上 |
| 单次使用成本 | 购买价格 ÷ 持有期内的预计使用次数 | estimated | 缺频率或缺持有天数时 insufficient-data |
| 持有日成本 | 购买价格 ÷ 预计持有天数 | estimated | 缺持有天数时 insufficient-data |
| 储蓄或应急金 | 用户本页填写 | user-confirmed，或用户标明大概时为 estimated | 不填则字段缺省，不是 0 |
| 购买价格 | 本页输入，同时是工时等价的分子 | 与输入表相同 | 无效则整张卡不可用 |
| 使用频率的次数 | 本页输入 | user-confirmed，或用户标明大概时为 estimated | 不填则字段缺省，不是 0 |
| 预计持有天数 | 本页输入 | 同上 | 不填则字段缺省，不是 0 |

持有期内的使用次数：

```text
每天 n 次：次数 = 持有天数 × n
每周 n 次：次数 = 持有天数 × n / 7
```

除法保留有理数，公式写在卡上。不把「今日收入估算」或每秒收入放进事实卡。

引用白名单 `citations` 由代码生成。它包含本卡实际展示的计算结果，也包含输入区里展示的价格、频率次数和持有天数。展示是 `62.50` 时，`62.5` 和 `62` 都不在白名单里，除非它们本身就是另一项的展示值。启用人物姓名中的数字一并列入，避免「5 年后的你」被当成编造金额。数据不足或用户没填的字段没有展示数字，也就没有引用项。

比较前先规范化，再做精确匹配：去掉千分位逗号、货币符号（`¥`、`￥`）和紧跟在数字后面的单位（元、块、小时、天、次、%）。然后与白名单里的展示字符串完整相等。`1,000` 在价格展示为 `1000` 时通过。`62.5` 在展示为 `62.50` 时不通过。

合成形状示例（不是测试夹具，实现以代码结果为准）。税后月收入 10000 元、月工时 160 小时、价格 1000 元时，现有购买计算的每小时收入是 62.50 元，工时等价是 16.00 小时：

```json
{
  "format": "zhiguan-purchase-fact-card@1",
  "currency": "CNY",
  "ruleset": "zhiguan-income-calendar@1",
  "hourlyIncome": { "display": "62.50", "unit": "元/小时", "evidence": "estimated" },
  "workTimeEquivalent": { "display": "16.00", "unit": "小时", "evidence": "estimated" },
  "citations": ["10000", "62.50", "16.00", "1000"]
}
```

真实的卡还要带上工作日收入、余量、日成本、单次成本的状态和公式。示例故意写短，避免把未计算的余量填成 0。

## 人物

每个人物包含：`id`、姓名、关系、性格、在意什么、对钱的态度、`stance`（`ordinary` 或 `pushback`）、是否启用。每个文本字段最长 80 字。

启用人数至少 1、至多 5，其中至少一位是反对角色。默认四位启用，上司关闭：

| 姓名 | 默认 | 立场 | 性格 | 在意什么 | 对钱的态度 |
| --- | --- | --- | --- | --- | --- |
| 家人 | 启用 | ordinary | 直接，关心日子稳不稳 | 钱能不能留出余地 | 先看余量和急用，不评价人 |
| 伴侣 | 启用 | ordinary | 一起商量，不替对方做主 | 会不会挤掉已经想做的安排 | 看这笔钱在共同生活里占什么位置 |
| 朋友 | 启用 | ordinary | 说实话，但不比较 | 会不会真的用，买了开不开心 | 不拿别人的消费当标准 |
| 5 年后的你 | 启用 | pushback | 只看以后这件东西还在不在用 | 使用假设和工时 | 用事实卡上的成本和工时提出反对，反对的是这笔开销的假设 |
| 上司 | 关闭 | ordinary | 只谈工作是否用得上 | 和工作相关的用途 | 与工作无关时说明自己没有工作上的理由，不引申到人品 |

这些句子是可编辑的起点。用户可以改内容、关闭、更换谁来反对，也可以新增到五人上限。默认文案可以改，上表是阶段一出厂文本。上司默认关闭、由「5 年后的你」默认反对，仍是待负责人确认的暂定。

人物设定的保存方式见 ADR-0009：不塞进现有 `@1` 备份字段。

## 讨论怎么进行

1. 代码先在本地生成事实卡。用户此时还没有发送任何内容。
2. 用户确认人物。不满足「至少一位反对角色、启用人数在 1 到 5」时，不能进入预览。
3. **第一轮。** 公共部分相同：事实卡、类别、理由、本轮指令。另加这一位人物自己的设定。不包含其他人物的设定或发言。请求同时发出。谁也读不到别人的结果。
4. **第二轮，可选。** 只在用户点击「让他们回应彼此」后发生。公共部分仍是事实卡、类别、理由和本轮指令，另加自己的设定、自己第一轮里通过校验的发言，以及其他人物通过校验的发言。不包含被挡下的句子，也不包含其他人物的设定。这是一份新载荷，发送前重新预览。
5. **综合。** 在本轮可用发言齐了之后生成。综合不加入新的用户数据。它只读已经在本轮预览里说明过的事实卡、类别、理由、启用人物的设定，以及本轮通过校验的发言。被挡下的句子不进入综合。一次确认同时覆盖本轮的人物请求和这次综合；预览里要列出综合会收到这些部分。反对角色没有可用发言时，综合必须写明反对意见这次没有可用文本，不得补写一段反对。

第一轮每个人的结构化输出：

| 字段 | 要求 |
| --- | --- |
| `personaId` | 与请求中的人物一致 |
| `points` | 短句列表。只引用白名单中的数字字面量。数据不足的项用文字说明不足，不补数字 |
| `pushback` | 仅反对角色必填：写出再等等或不买的理由。其他人物省略 |

综合的结构化输出：

| 字段 | 要求 |
| --- | --- |
| `leaning` | `lean-buy`、`lean-wait`、`lean-skip`、`lean-adjust`、`unclear` 之一 |
| `reasons` | 主要理由 |
| `risks` | 风险情景 |
| `changeConditions` | 至少一条，句子里同时有「如果」和「就买」「就等」「就先不买」或「就换条件」 |
| `disagreements` | 分歧点。反对角色与其他人不同时，这里必须点出。没有可用反对文本时，写明缺失 |

界面对应的倾向用词只允许：更倾向现在买、更倾向再等等、更倾向这次先不买、更倾向先换个条件、这轮没有形成倾向。`lean-skip` 对应「更倾向这次先不买」。不使用「应该买」「值得买」「建议购买」「不值得」。

`leaning` 不写入决定，也不预选单选框。用户随后自己选择：现在买、再等等、换个条件再看、这次不买、还没想好，并可以写下自己的依据。依据留在本地，不自动进入模型载荷。

## 数字校验与措辞

数字校验不依赖模型自觉，是阶段一的验收项。

只校验金额、时长、比例和次数。单位是：元、块、小时、天、次、%。「一个」「这次」「第一轮」「一台」这种不带上述单位的说法不校验。

1. 扫描人物发言和综合的理由、风险、条件、分歧。
2. 阿拉伯数字先按上一节去掉千分位、货币符号和紧跟的单位，再与某条 `citations` 完整相等。
3. 中文数字只在后面跟着上述单位时才校验。阶段一识别紧挨单位的零到十、两、百、千、万，以及两万、十二这种简单组合。换算结果不在白名单里，或认不出这种组合，该句视为未授权。「一台」「一个」后面不是上述单位，不校验。
4. 未授权的句子仍显示给用户，并标明「这句里的数字对不上事实卡，不参与后续讨论」。该句不进入第二轮，也不进入综合的输入。
5. 一个人的句子全部被挡下时，这个人在后续轮次中没有可用发言。

正例和反例（价格展示为 `1000`、工时展示为 `16.00`、每周次数展示为 `3` 时）：

| 句子 | 结果 |
| --- | --- |
| 相当于 16.00 小时 | 通过 |
| 这台吸尘器 | 通过 |
| 一个工作日 | 通过 |
| 你每周用 3 次 | 通过 |
| 1,000 元 | 通过 |
| 大概两万块 | 拦截 |
| 62.5 元（展示值是 62.50） | 拦截 |

施压用语至少拦截这些说法：浪费、败家、月光、穷鬼、配不上、丢人、没出息、乱花钱、太冲动、冲动消费、别人都有、再不买就亏、你这种收入。命中的句子用户看得到，并标明「这句可能在施压」，同样不进入后续讨论。列表不声称穷尽所有伤害性说法。不自动改写成另一套教训。

系统指令还要写明：只使用事实卡上的数字字面量；算不出就说数据不足；不下达买或不买的命令；不评价人格；反对角色必须给出再等等或不买的理由。指令是约束，上面的校验才是验收。

## 界面流程

从现有应用能进入「讨论这笔购买」。首页是否改成这个入口，本 PRD 不决定。

1. 没有有效收入资料时，进入现有设置，不打开模型。
2. 填写本页输入，本地显示事实卡：数字、单位、证据状态、公式或不足原因。
3. 编辑人物。
4. 预览全文。预览包含事实卡、将发给每个人物的公共部分和「只附带该人物自己的设定」、综合将收到的部分、类别、理由、服务商名称和主机名、本轮请求次数，以及「对方收到后是否保留，本产品不能替对方删除」。不包含密钥。一次确认覆盖本轮人物请求和综合请求。
5. 确认后发送第一轮。每个人物单独显示等待、完成或失败。综合使用同一次确认。
6. 用户可以要求第二轮。第二轮是新载荷，再次预览后才发送。确认同样覆盖该轮的综合。
7. 显示综合。附近有一句固定说明：这是倾向，不是决定。
8. 用户选择五种决定之一。
9. 「保存这次讨论」是单独动作。不点击就不写入本地。未保存时刷新可能丢失，界面要说明。

键盘、窄屏、辅助技术和减少动态时，填写、读事实卡、预览、确认、阅读发言、选择决定和保存仍然可以完成。预览不是一段不能选中的图片。

## 失败、等待和费用

- 密钥缺失或服务不可用：事实卡和五种决定可用，讨论标明不可用。不自动重试。
- 一位人物超时或失败：保留其他人的发言。不由模型补写这个人的话。用户可以在同一份已确认载荷上重试这个人。
- 综合失败：第一轮发言仍然留着，用户仍可做决定。
- 修改价格、频率、持有天数、收入资料或人物后，旧发言和旧综合失效，需要新的预览。
- 预览写明本轮请求次数：第一轮是每位启用人物一次，再加一次综合；第二轮同样。费用由服务商收取。界面不标价格，仓库不记录单价。
- 取消预览、关闭页面，都不自动补发。

## 建议中的实现方式

下面是建议，不是本 PRD 的验收锁。

保持 React、Vite、TypeScript 和 Bun。模型调用用 Vercel AI SDK，或一个普通的 OpenAI 兼容客户端，加上 zod 做结构化输出。不用多智能体框架。密钥放在小后端：扩展 `scripts/jev_server.py`，或另写一个很小的 Hono / Node 服务。模型例子是 DeepSeek 或 Qwen。服务商选择和费用见 ADR-0009，不在这里定死。

## 不在本阶段

30 天、90 天、一年的回访；按类别和价格带共享真实回访；账户、审核、生成式人工智能备案；商品排名；模型自己做算术；改写 ADR-0007 的 Jev 行为；删除收入看板；把看板降级或升成首页；默认持有天数；模型价格；关不掉的提醒。

回访和共享只出现在路线图里。阶段一若连讨论都不主动保存，阶段二会没有可对照的原文。保存做成可选，就是为了留下这个口，而不是提前做回访界面。

## 验收

1. 有效资料和有效价格下，不发送请求也能看到事实卡。每小时收入和工时等价与同一输入下的现有购买计算结果一致。今日已过去的收入和每秒收入不出现在卡上。
2. 未填固定支出时，两项余量是数据不足，卡片上没有余量数字。未填持有天数时，日成本和单次成本是数据不足。未填储蓄时，载荷里没有储蓄字段，也没有 0。
3. 启用人物不是 1 到 5 人，或没有反对角色时，不能进入预览。
4. 不确认预览时，讨论请求数为 0。预览文本包含月收入的展示数字和服务商名称，不包含密钥。
5. 第一轮的每个请求都不包含其他人物的发言，也不包含其他人物的设定。第二轮在用户要求并再次确认之前不发送。第二轮包含其他人物通过校验的发言，仍不包含其他人物的设定。
6. 金额、时长、比例、次数对不上白名单时，以及施压用语表中的说法，会在界面标出，并且不出现在下一轮或综合的输入里。「相当于 16.00 小时」「这台吸尘器」「一个工作日」在对应数字已入卡时不被当成未授权数字。「大概两万块」会被挡住。
7. 综合只使用规定的五种倾向用词，其中包括「更倾向这次先不买」。出现「应该买」或同等裁决句时，该句按未通过校验处理。倾向不改变五种决定的选中状态。
8. 反对角色失败或发言被全部挡下时，综合标明反对意见没有可用文本，不另造一段反对。
9. 服务失败时，事实卡仍在，用户仍可选择五种决定。不自动连续重试。
10. 未点击保存时，讨论不写入 `zhiguan-local-backup@1`，也不写入新的本地文档。点击保存后，清空和导出能覆盖到这份新数据；导入旧 `@1` 备份不破坏原有资料。
11. 键盘、窄屏、减少动态下，事实卡、预览、确认、发言、决定和保存可以完成。

## 未决问题

与 RFC-0002 相同。其中影响本文件暂定的是：首页位置、默认持有天数、是否在实现时就做主动保存、服务商与小后端的选型、Jev 入口去留、上司默认关闭、默认反对角色、类别词表，以及储蓄字段要不要拆开。未决项在负责人改口之前，按本文件的暂定实现；首页位置没有暂定，实现时保留现有首页，并提供进入讨论的入口。
