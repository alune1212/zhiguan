# PRD-0002：单个数字目标进度

| 项目 | 内容 |
| --- | --- |
| 状态 | Retired（2026-09-01） |
| 范围 | 历史：一个用户定义的数字目标、一个当前进度快照 |
| 交付 | 历史：现有单页应用中的独立 Goal 区域（已撤下） |

2026-09-01，按本规格末尾回滚条件撤下独立 Goal 区域及其导出：用户确认它增加了输入负担，且未帮助购买任务。本文件保留为 Retired 历史记录，不代表当前实现、研究结果或市场结论。

## 用户任务

用户希望用最少输入看见一个目标已经完成多少、还差多少，并知道结果依赖哪些确认或估算；不需要先建立目标历史、计划或提醒。

## 输入与结果

输入只有目标名称、目标值、当前值、用户定义单位，以及目标值和当前值各自的 `user-confirmed` / `estimated` 证据状态。目标值必须大于零，当前值可以为零或超过目标值；两个数最多保留两位小数并使用同一单位。

应用输出：

- 完成比例 = 当前值 ÷ 目标值 × 100%；超过目标时保留超过 100% 的真实关系。
- 剩余差距 = max(目标值 − 当前值, 0)；达到或超过目标时为零。

计算使用整数最小单位与有理数，不经过浮点数。任一必需输入无效、缺失或没有证据状态时，Goal 结果整体显示 `insufficient-data`；任一数值为 `estimated` 时，结果保持 `estimated`。Goal 不参与购买计算，缺少 Goal 也不影响购买决策流程。

## 产品边界

- Goal 只存在当前页面内存，用户可修改、清空并主动下载独立 JSON。
- 页面展示输入、公式、单位、证据状态、假设、限制、不足原因和修正路径。
- 不把截止日期或预计时间加入输入；界面明确标注该时间口径未采集，因此不预测完成时间，也不加入历史、提醒、同步、排名、评分或行动建议。
- 单位由用户定义；应用不猜测它代表金钱、时间、体验或其他价值。
- 输入负担固定为四个短字段和两项证据状态；购买工作台与 Goal 可独立使用。

## 验收

1. 正常输入能显示完成比例、剩余差距和证据状态。
2. 全空或非法输入显示 `insufficient-data`，不填零、不保留旧结果。
3. 当前值超过目标时完成比例可以超过 100%，剩余差距为零。
4. 提交前不显示 Goal 结果；修改输入后旧结果和导出立即失效，重新提交后恢复。
5. 用户主动触发后得到只包含当前 Goal 快照的 JSON；页面不联网、不持久化。
6. 键盘和窄屏可以完成输入、查看结果、导出和清空。

若该区域增加输入负担却没有帮助用户理解目标，删除独立 Goal 区域和对应导出即可回滚，不影响购买决策计算。该回滚条件已于 2026-09-01 触发并执行，购买决策计算保持不变。
