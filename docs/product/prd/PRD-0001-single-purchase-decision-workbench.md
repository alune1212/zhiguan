## 1. 问题与机会

### 1.1 用户问题

当前优先验证的用户是有相对稳定收入、以知识工作为主、不希望维护复杂账本，且正在考虑一项真实购买的个人。当他们尝试判断一项购买时，可能只能看到价格，或依靠零散心算把价格与收入、工作时间、固定成本和个人期待联系起来，难以同时回答：

- 这项价格按自己的收入和工作时间口径对应多少时间；
- 当前输入是用户确认、近似估算还是不足以判断；
- 固定成本覆盖充分时，购买可能怎样改变同周期、已确认覆盖范围内的可用余量；
- 除金额外，自己希望这项购买带来什么；
- 当时为什么购买、等待、调整、不购买或暂不决定，之后如何复盘。

上述问题来自 [`PRODUCT_STRATEGY.md`](../../../PRODUCT_STRATEGY.md) 和 [`ROADMAP.md`](../../../ROADMAP.md) 的阶段假设，不是已经证实的用户需求。仓库当前没有真实用户研究、运行时产品数据或可运行应用，证据状态为 `insufficient-data`。

### 1.2 为什么现在做

[`PRODUCT_STRATEGY.md`](../../../PRODUCT_STRATEGY.md) 将“收入与工作时间 → 个人口径与收入速率 → 固定成本与可用余量 → 单一购买情景 → 决定 → 复盘”定义为优先验证的最短个人价值闭环；[`ROADMAP.md`](../../../ROADMAP.md) 的 Now 阶段要求用少量输入验证这条闭环，而不是先做完整记账、目标系统、订阅、同步或 AI。

当前治理基线、数据状态、指标定义和架构约束已经建立；本 `PRD-0001`、[`ADR-0001`](../../adr/ADR-0001-delivery-form-and-technology-stack.md)、[`ADR-0002`](../../adr/ADR-0002-calculation-and-rules.md) 与 [`ADR-0003`](../../adr/ADR-0003-export-contract.md) 均已批准，[`build-single-purchase-decision-workbench`](../../../openspec/changes/build-single-purchase-decision-workbench/proposal.md) 的 proposal、specs、design 与 tasks 已创建但尚待 Alune 批准。PRD 把 Experiment Issue #1 中已确认的研究边界转成可验收需求，OpenSpec 将其收束为实现计划；当前进度仍不授权初始化框架或实现代码。

### 1.3 成功的用户结果

目标用户在一个真实但允许近似的购买场景中，可以：

1. 用用户选择的同一比较周期内的收入和工作小时建立自己的收入速率口径；
2. 看懂购买价格对应的工作时间，并知道来源、公式、单位、证据状态和限制；
3. 在固定成本覆盖充分时理解购买对同周期、已确认覆盖范围内可用余量的情景影响，在覆盖不足时看到明确的 `insufficient-data`；
4. 把数字与自己填写的价值期待并列考虑；
5. 记录购买、等待、调整条件、不购买或暂不决定，以及当时依据；
6. 在产品外的人工回访中比较当时预期与后来结果，并确认或修正自己的判断依据。

成功不等于产品替用户给出购买结论，也不等于页面访问、停留时长、点击或积极评价。

## 2. 产品对齐

| 对齐项 | 填写 |
| --- | --- |
| 产品宪法原则 | 价值由用户定义；用户拥有数据和决定权；每个数字可解释；事实、用户确认、估算、预测和数据不足分开；低输入负担；不羞辱、不操纵；解释辅助而不替代判断 |
| 价值循环阶段 | 原型内只实现 `Capture → Normalize → Understand → Simulate → Decide`；研究协议在产品外人工完成 Review 与 Learn，以验证整条假设链路。研究协议跨越七个阶段不等于原型具备完整产品能力 |
| 目标用户 | 有相对稳定收入、以知识工作为主、不希望维护复杂账本，且正在考虑一项真实购买的个人；仍是待验证假设 |
| 用户任务（JTBD） | 当我正在考虑一项购买时，我想把价格放回自己的收入、工作时间、固定成本覆盖和价值期待中理解，以便形成自己的决定并知道之后如何复盘 |
| 支持的长期价值 | 时间、金钱、已确认覆盖范围内的可用余量、个人期待和选择依据之间的可解释关系 |
| 北极星指标关系 | 研究“证据 → 理解/推演 → 用户决定/不决定 → 人工复盘”能否成立；不直接测量或宣称正式 MVLU |
| 相关路线图项 | 从 `Now` 中选取收入口径与工作时间口径、Income Rate、Work-time Equivalent、固定成本与可用余量、单一购买场景、决定记录、复盘入口和五类证据状态进行验证；本实验通过也不代表 `Now` 全部完成 |

本切片暂不纳入 Goal，是为了缩小变量并验证购买决策的最短链路，不是对 Goal 长期价值的否定，也不能据此宣称任何路线图阶段已经完成。

### 2.1 产品假设

**如果**有稳定收入、正在考虑一项真实购买的知识工作者，能够在纯客户端研究原型中自愿输入同一比较周期的收入、工作小时、购买价格、可选固定成本汇总，以及自己期待购买带来的结果，

**那么**他们可以在不维护完整账本的前提下，解释收入速率、工作时间等价和证据状态，形成购买、等待、调整、不购买或暂不决定，并在之后完成一次有依据的人工复盘，

**因为**金额只有与用户自己的时间口径、已确认覆盖范围内的可用余量和价值期待相连，才可能从孤立数字变成可解释、可复盘的判断材料。

验证方法为两个小批次、每批 3–4 名目标用户的形成性研究。第一批发现阻塞问题，只修正本 PRD 范围内的问题；第二批验证修正并完成人工回访。样本不用于统计性市场结论。

### 2.2 非目标

本 PRD 明确不解决：

- Goal、订阅、物品、完整交易账本、全量固定成本录入或资产视图；
- 账户、身份认证、应用后端、业务 API、数据库、浏览器持久化、同步或跨设备恢复；
- 文件导入、自动或批量导出、已导出文件重新导入、公开分享、通知、自动提醒、后台任务或分析埋点；
- AI、自动建议、购买推荐、价值评分、排名或“值得/不值得”结论；
- 跨币种换算、投资、交易、财务建议或正式产品生产部署/公开发布；
- PWA、原生应用、完整设计系统或将研究原型直接作为正式产品基础；
- 正式 MVLU、留存、市场规模、产品市场匹配或生产级数据主权验证。

产品负责人已于 `2026-08-21` 确认：本期提供用户主动触发的一次性本地导出，同时保持零应用后端、零产品数据上传、零浏览器持久化、无导入和无分享。导出是数据主权的最小出口，不是历史记录、备份、同步或跨会话恢复；精确格式与安全实现仍须由 ADR 批准。

同日进一步确认以下产品口径：

- 允许通过受控静态托管分发原型；静态托管不是应用后端，但其基础设施访问元数据必须披露、最小化、限期删除，无法满足边界时改为本地分发；
- 用户为每个会话选择一个周、月、年或自定义比较周期，所有收入、工时和固定成本输入使用同一周期；不要求精确起止日期，不自动跨周期换算；
- 每个会话选择一种 ISO 4217 币种，不做换汇；界面可以优先展示 CNY，但产品合同不永久锁定为 CNY；
- Income Rate 与 Work-time Equivalent 可以使用税前或税后收入，但必须持续显示口径；只有税后收入可以进入覆盖范围内可用余量及其购买影响计算，税前收入时这些结果为 `insufficient-data`。

## 3. 用户场景与流程

### 3.1 主流程

正式研究准入在原型之外完成，不计入下面的四步核心流程。四步是验收时统一使用的宏观阶段，后续十个条目是其子步骤：

| 核心阶段 | 包含内容 | 对应价值循环 |
| --- | --- | --- |
| 1. 输入与期待 | 输入购买场景、个人口径和价值期待 | Capture |
| 2. 确认口径与状态 | 校验比较周期、单位、币种、覆盖范围和证据状态，并由用户确认或修改 | Normalize |
| 3. 理解与推演 | 查看 Income Rate、Work-time Equivalent、可安全展示的余量情景及详细依据 | Understand、Simulate |
| 4. 决定、导出与复盘交接 | 记录用户自己的决定和依据，允许带走当前会话快照，并把复盘安排交接到产品外研究流程 | Decide；基础信任出口；为产品外 Review、Learn 提供入口 |

```text
研究说明与隐私边界
        ↓
输入购买场景、个人口径与价值期待
        ↓
检查同一比较周期、单位、币种、税口径与证据状态
        ↓
用户逐项确认或返回修改
        ↓
查看收入速率、工作时间等价与可用结果
        ↓
展开“查看依据”检查公式、假设和限制
        ↓
比较购买与暂不购买/等待情景
        ↓
记录决定状态及一句依据或待确认条件
        ↓
可选：本地导出当前会话快照
        ↓
选择人工复盘条件或日期
        ↓
产品外回访：比较预期与结果，确认或修正判断依据
```

0. **产品外研究准入**：参与者在获得原型访问前完成正式研究知情同意、退出/撤回说明，以及对“仅记录第 5.1 节封闭字段脱敏研究观察”的单独授权。当前 `RESEARCH-0001 0.1.0` 不采集原话、录音、录像或截屏；若未来修订协议允许其中任一项，必须另行、默认关闭地取得可选授权。原型内的会话边界确认不能替代这些步骤。
1. **进入与告知**：用户看到实验目的、原始会话数据只在当前浏览器内存处理、刷新/关闭即清空、用户主动本地导出例外、受控静态托管可能产生的最小访问元数据、产品外脱敏研究观察边界、不默认录音录像，以及随时退出的说明。
2. **输入场景**：用户选择周、月、年或自定义比较周期，并输入一组属于该周期的收入金额、税前/税后口径、对应工作小时和一种 ISO 4217 币种；输入一项当前购买价格，并确认是否把它作为所选周期的一次性成本进行情景推演；可以选填同周期固定成本汇总、覆盖状态和不含交易明细的覆盖说明；必须填写一句个人价值期待。原型不要求精确起止日期，也不自动跨周期或跨币种换算。
3. **标记状态**：用户为收入、工作小时、购买价格和固定成本选择“我确认的输入”或“近似输入”。近似输入保持 `estimated`，不能因为点击确认升级为 `user-confirmed` 或 `actual`。
4. **确认口径**：系统展示输入摘要、比较周期、币种、单位、状态和固定成本覆盖范围。比较周期不一致、值无效或字段不足时，阻止依赖该字段的计算并解释如何修正。
5. **理解与推演**：系统展示能够安全计算的 Income Rate、Work-time Equivalent 和固定成本覆盖充分时的同周期覆盖范围内可用余量/购买情景影响。每个结果同时展示状态和“查看依据”。
6. **检查依据**：用户展开详细依据，查看输入、公式、单位、比较周期、规则版本、生成时点、关键假设和数据不足原因，并可返回修改后重算。
7. **记录决定**：用户选择 `购买 / 等待 / 调整条件 / 不购买 / 暂不决定`，并填写一句当时依据或尚待确认条件。系统不评价选择好坏。
8. **本地导出**：用户可以在当前会话主动打开导出入口，预览将包含的敏感字段并确认后，分别下载自描述的 JSON 数据和 Markdown 可读摘要。文件只在浏览器本地生成，不上传、不自动生成；用户可以取消或跳过。
9. **约定复盘**：用户根据决定选择复盘条件或日期。该选择只存在于当前会话内存；除用户明确将当前快照导出到本地文件外，原型不持久化、上传或自动发送该信息。研究联系方式和安排在产品外、与原始财务输入分离管理。
10. **人工回访**：研究者使用脱敏研究编号，只按第 5.1 节封闭字段记录是否完成复盘、结果类别、价值期待关系是否变化，以及用户是否确认或修正判断依据。除另行取得原话引用授权外，不保存自由文本或完整原话；回访观察不自动进入原型。

### 3.2 例外与失败流程

| 场景 | 行为与安全降级 |
| --- | --- |
| 缺少收入或工作小时 | Income Rate、Work-time Equivalent 和依赖结果为 `insufficient-data`；指出缺少字段，不使用默认工时 |
| 收入、工作小时或固定成本不属于同一比较周期 | 不自动跨周期换算或猜测；要求用户调整为同一比较周期后再计算 |
| 金额、工作小时为零、负数、非有限值或超出实现限额 | 不计算；显示字段级错误，不在日志中写入原始值；具体语法、精度和限额见 [ADR-0002](../../adr/ADR-0002-calculation-and-rules.md) 第 5.1.2 节 |
| 购买价格缺失或无效 | Work-time Equivalent 与购买情景结果为 `insufficient-data`；Income Rate 仍可展示 |
| 固定成本未填写、覆盖为部分或未知 | Income Rate 和 Work-time Equivalent 仍可展示；同周期覆盖范围内可用余量及其购买影响为 `insufficient-data` |
| 固定成本标记为完整但未填写覆盖说明 | 不接受“完整”状态；要求用户用非交易明细的一句话说明包含范围 |
| 收入选择税前口径 | Income Rate 和 Work-time Equivalent 仍可展示，并持续标明“税前”；覆盖范围内可用余量及其购买影响为 `insufficient-data`，说明需要税后收入，不能把支出从税前收入中直接扣除 |
| 用户未确认购买价格计入所选比较周期 | Work-time Equivalent 仍可展示；购买后的同周期余量及差异为 `insufficient-data`，不擅自分摊或指定比较周期 |
| 任一关键输入为近似值 | 输入保持 `estimated`；非未来派生结果按保守规则为 `estimated`，未来情景保持 `forecast` 并展示近似输入基础 |
| 用户修改已确认输入 | 立即把依赖结果标为待重算；重新确认后生成新结果；旧值不得继续参与计算，但以最小确认/修订事件留在当前内存供导出，刷新、关闭或退出后全部清除 |
| 用户刷新、关闭页面或主动退出 | 清除当前浏览器内存状态；不存在恢复、同步或服务端副本 |
| 当前会话没有任何用户输入 | 导出入口不可用并说明“暂无可导出内容”；不生成空白或误导性文件 |
| 用户取消导出 | 不生成文件、不清除或改变当前会话，也不记录分析事件 |
| 导出生成失败或浏览器拒绝下载 | 不显示成功状态；使用非敏感错误说明并允许重试，当前会话保持不变；不得通过网络或日志兜底发送内容 |
| 静态资源加载失败或计算异常 | 停止展示依赖结果，使用非敏感错误说明；不使用旧值或猜测结果；不自动上报原始输入 |
| 用户不愿填写固定成本或价值期待 | 固定成本允许跳过并局部降级；价值期待是验证核心假设的必要字段，不愿填写时可以退出实验，不施加压力 |
| 用户选择暂不决定 | 视为有效的 Decide 状态；仍可填写待确认条件并约定复盘 |

### 3.3 无障碍与可理解性

- 四步核心流程在目标桌面和移动视口均可完成，不依赖悬停、精细指针或横向滚动。
- 所有表单控件具有可见标签、程序化名称、错误关联和清晰的必填/可选说明。
- 键盘可以完成输入、返回修改、展开依据、选择决定和退出；焦点顺序与视觉顺序一致，焦点样式可见。
- 导出入口、格式选择、敏感提示、取消、失败与成功反馈均可由键盘和读屏理解，不依赖浏览器下载动画或颜色提示。
- 状态、错误和不确定性同时使用文字和结构表达，不以颜色、图标、动画或位置作为唯一提示。
- 数字同时显示单位、比较周期和币种；读屏顺序不会把金额、单位和证据状态拆成无法理解的片段。
- 支持减少动态偏好；本期不使用滚动数字、闪烁、庆祝粒子或无法暂停的动画。
- 文案使用平静、具体、非评判表达，不使用“应该买”“浪费”“失败”“不自律”等措辞。
- 低带宽或静态资源失败时不显示残缺旧结果；加载状态和失败状态可理解。

### 3.4 首轮支持矩阵与性能预算

- 正式支持桌面 Chrome（macOS 与 Windows）、macOS Safari 和 iOS Safari 的验收时当前稳定版；交付形态 ADR 必须记录实际测试的浏览器、操作系统和设备版本。
- 桌面端必须完成完整键盘路径；VoiceOver 在 macOS 与 iOS 上完成手工验收。Firefox、Android 和 NVDA 不属于首轮正式支持范围，不得据此宣称全面跨平台兼容。
- 在 ADR 固定的目标设备、网络配置和最大允许会话数据下，首个可用界面不超过 `3s`，输入后的计算与状态更新不超过 `100ms`，导出预览不超过 `500ms`，单一格式生成不超过 `1s`。
- 上述数字是固定实验室条件下的工程验收预算，不是用户价值指标；不得为测量它们加入真实用户性能遥测、分析事件或会话追踪。

### 4.4 不变约束

- 产品提供证据和解释，不替用户定义价值或作出购买决定。
- 所有关键数字保持 `actual / user-confirmed / estimated / forecast / insufficient-data` 的稳定语义；本实验不产生产品内 `actual` 财务记录。
- 近似输入的用户确认不改变其 `estimated` 原始状态；未来情景不改变其 `forecast` 状态。
- 关键输入缺失时不能用零、平均值、默认 160 小时、旧值或猜测补齐。
- 除用户明确触发的本地文件下载外，原始会话数据和派生财务结果只存在于当前浏览器内存，不外发、不持久化、不进入普通日志、分析事件、截图或研究记录；经单独授权的封闭字段脱敏研究观察属于产品外研究层，必须与前述数据隔离。
- 用户可以修改、退出并通过刷新/关闭清除原型数据；本期不承诺历史或恢复。已下载的本地文件由用户控制，原型必须明确说明无法替用户撤回、同步或删除该文件。
- 不增加 Goal、账户、同步、通知、AI、完整账本或其他 Next/Later 能力。
- 若实现需要改变上述契约，必须暂停并重新判断 PRD、RFC 与 ADR，而不是用实现细节绕过。

| 复盘条件或日期 | 用户 | `user-confirmed` | 产品外安排人工回访 | 是 | 原型内仅当前页面；产品外安排只进入联系方式/同意存储，不进入观察存储 | 刷新、关闭或退出删除；可随会话快照导出；产品外安排按联系方式保留规则删除 |
| 本地导出文件 | 原型根据当前会话生成，所有者为用户 | 每个字段保留其原状态；文件本身是生成时点快照，不获得产品财务 `actual` 状态 | 用户带走当前输入、解释和决定 | 是，高敏感 | 浏览器下载完成后由用户及其设备控制；原型不留副本 | 用户自行保管或删除；原型不能撤回、恢复、同步或删除已下载文件 |
| 静态托管访问元数据（仅在无法关闭日志时） | 托管基础设施 | 基础设施层 `actual`；不属于产品财务状态 | 受控分发、安全和故障诊断；不得用于分析用户行为或二次使用 | 是，包含 IP、User-Agent、访问时点 | 最多 7 天；项目账户仅 Alune 可查看；托管方只能按已披露的基础设施运营/安全目的受约束处理；不与研究编号或原型输入关联 | 到期删除并在招募前演练 readback；无法证明托管方访问、用途和删除边界时改为本地分发 |
| 第 5.1 节定义的封闭字段脱敏研究观察 | 研究者/参与者反馈 | `actual` 或 `user-confirmed`，按字段来源区分 | 判断实验是否通过 | 可能敏感，但不得包含或可重建原始会话数据 | 与联系方式分开的加密存储，仅 Alune 访问；实验最终结论后最多 30 天；无默认备份 | 按研究编号更正；撤回后 7 天内删除适用记录并重算尚可关联的聚合；只长期保留不可识别的聚合结论 |

#### 5.1.1 本地导出合同

- **触发与范围**：至少存在一项已提交到当前稳定会话状态的用户输入时开放导出入口；该输入可保持 `user-confirmed` 或 `estimated`，只有未确认草稿、默认值或旧结果不计入。只在用户明确选择格式并再次确认后生成；允许分别下载 JSON 与 Markdown，也允许取消。导出包含当前会话的当前快照，不虚构未保留的修订历史，不导出产品外研究同意、研究编号、联系人或脱敏观察。
- **机器可读 JSON**：至少自描述 `schema_name`、`schema_version`、导出生成时点及时区、原型构建版本、规则版本、快照范围、状态字典和字段字典；每个 schema 字段显式出现，未填写值使用 `null` 与独立的“未提供”可用性说明，不能省略后被误读为零；每项当前输入与结果保留值、来源、数据状态、单位、币种、比较周期、税前/税后口径、确认/生成时点、依赖输入、公式或规则、假设、限制和 `insufficient-data` 原因；包含价值期待、决定、决定依据、复盘条件及本次会话已确认的修订事件。字段结构、UTF-8 编码、MIME、文件名和版本兼容已由 `Accepted` 的 [`ADR-0003`](../../adr/ADR-0003-export-contract.md) 固定；运行时证据仍属于后续原型验收。
- **用户可读 Markdown**：与 JSON 覆盖同一语义范围，以可读标题、状态/字段说明和表格展示当前输入、结果、来源、状态、单位、比较周期、公式/规则、版本、假设、限制、不足原因、本次会话修订摘要、价值期待、决定及复盘条件；不得为了简洁省略 `estimated`、`forecast` 或 `insufficient-data`。
- **历史声明**：两种文件都明确这是“当前会话当前快照”，`history_scope` 仅覆盖本次会话已确认的修订，不包含过去会话、未确认按键过程或实际执行结果。修订事件至少记录字段、前后值与状态、确认时点、触发者和依赖结果失效；JSON 与 Markdown 中同一字段、状态和修订语义必须一致。
- **离线自包含**：两种文件使用 UTF-8，必须在断网时独立可读，不依赖运行中的原型、外部 schema/URL、远程字体、脚本、图片或只有内部系统才能解释的 ID。文件名不得包含收入、购买内容、价值期待、决定依据或其他自由文本。
- **敏感性与用户控制**：确认界面列出将导出的敏感类别，并说明下载后文件进入用户设备，原型无法撤回、删除或控制其后续分享。导出不是公开分享、研究提交、备份保证或跨会话恢复。
- **本地与失败边界**：内容在当前浏览器内存中生成，不发送网络请求，不写 Cookie、Web Storage、IndexedDB、Cache Storage、URL、剪贴板、服务端、普通日志或分析事件。导出请求/取消/失败/成功是交互状态，不得复用五类财务证据状态。取消不生成文件；两种格式分别报告结果，任一生成或下载失败都不得笼统显示“导出完成”，也不得清除会话或通过网络兜底；重试只能由用户再次触发。临时对象、下载 URL、非敏感错误码和资源限额已由 `Accepted` 的 [`ADR-0003`](../../adr/ADR-0003-export-contract.md) 固定；运行时证据仍属于后续原型验收。

### 5.2 数据状态与状态转换

本实验要求实现五类状态的完整语义，但不产生产品内 `actual` 财务记录：

1. **用户确认（`user-confirmed`）**：用户明确表示某项输入是其当前确认的值或范围，并完成确认步骤。未确认编辑不算 `user-confirmed`。
2. **估算（`estimated`）**：用户选择“近似输入”，或非未来派生结果依赖任一 `estimated` 关键输入。用户确认理解或采用估算时，估算本身仍保持 `estimated`。
3. **预测（`forecast`）**：所有面向未来的购买情景结果。即使全部输入为用户确认，结果仍保持 `forecast`；若依赖估算，详细依据同时展示估算输入。
4. **数据不足（`insufficient-data`）**：缺少关键输入、比较周期不一致、值无效、固定成本覆盖不足、可用余量只有税前收入口径或规则执行失败，导致无法安全计算特定结果。
5. **实际（`actual`）**：仅用于有可追溯来源的已发生事实。本实验不收集凭证或持久化实际财务记录，因此不得把用户输入、计算或研究回访自动标为产品内 `actual`。脱敏研究过程中的“是否完成步骤”等观察事件可由研究者记录为研究层 `actual`，不得与产品财务状态混用。

保守传播顺序：

- 缺少任一结果所需的关键输入，结果为 `insufficient-data`；
- 结果描述未来购买情景，结果为 `forecast`；
- 非未来结果依赖任一 `estimated` 输入，结果为 `estimated`；
- 非未来结果的全部关键输入均为 `user-confirmed` 时，结果为 `user-confirmed`；
- 本实验不把任何产品财务结果升级为 `actual`。

以下矩阵是实现和验收必须覆盖的优先级规则；从上到下匹配，前一行优先于后一行：

| 前置条件 | 结果状态 | 必须同时展示 |
| --- | --- | --- |
| 任一必需输入缺失、无效、周期/币种冲突，情景缺少购买周期归属，或可用余量计算只有税前收入 | `insufficient-data` | 缺少或冲突的具体字段、修正路径；税前收入可继续支持的 Income Rate / Work-time Equivalent；不得因结果“面向未来”而降为 `forecast` |
| 输入有效、结果面向未来，且至少一个依赖输入为 `estimated` | `forecast` | 结果的预测性质，以及每个估算依赖；不得只显示 `estimated` |
| 输入有效、结果面向未来，且全部依赖输入为 `user-confirmed` | `forecast` | 情景假设和“不是承诺/建议” |
| 输入有效、结果不面向未来，且至少一个依赖输入为 `estimated` | `estimated` | 具体估算依赖 |
| 输入有效、结果不面向未来，且全部依赖输入为 `user-confirmed` | `user-confirmed` | 输入确认时点和来源 |
| 研究层存在 `actual` 观察事件 | 不改变任何产品财务状态 | 研究层与产品层隔离；不得把研究者观察传播成产品内 `actual` |

用户修改输入后，所有依赖结果立即失效并等待重新确认、重算。原型仅在当前内存记录已确认的最小修订事件供导出，旧值不再参与计算，也不提供应用内历史浏览；刷新、关闭或退出后全部清除。任何跨会话保留“当时看到的结果”的需求都转入后续持久化 PRD/ADR。

### 5.3 计算与解释

以下为产品语义与概念公式；具体数值合同已由 [ADR-0002](../../adr/ADR-0002-calculation-and-rules.md) 固定。实际实现与运行证据仍须按该 ADR 第 9.2 节验收，本节不把计划写成已通过。

| 结果 | 输入 | 口径/规则版本 | 状态 | 用户可见解释 | 数据不足时 |
| --- | --- | --- | --- | --- | --- |
| Income Rate | 同一比较周期收入金额 ÷ 对应工作小时 | `purchase-decision-rules@1.0.0`；单一 ISO 4217 币种；工作小时大于零；不跨周期换算；保留精确有理数，按 `min(4, max(currencyMinorUnit, 2))` 位展示 | `user-confirmed`、`estimated` 或 `insufficient-data` | “按你确认的比较周期和工作小时口径计算”；展示分子、分母、税前/税后、单位、周期和近似性质；不直接称为真实时薪 | 说明缺少收入、工时、周期匹配或有效值；不使用默认工时 |
| Work-time Equivalent | 购买价格 ÷ Income Rate | `purchase-decision-rules@1.0.0`；与 Income Rate 同币种；直接使用原始精确输入；主单位固定为小时并展示 2 位小数，精确非零但舍入为 `0.00` 时显示 `<0.01 小时`；不换算工作日 | `user-confirmed`、`estimated` 或 `insufficient-data` | “这只是按所示收入口径得到的工作时间视角，不代表体验或人生价值”；展示价格、速率、税口径、公式、单位和输入状态 | Income Rate 或价格不可用时停止；Income Rate 仍可单独展示（如适用） |
| 同周期覆盖范围内可用余量 | 同周期税后收入金额 − 同周期固定成本汇总 | `purchase-decision-rules@1.0.0`；只接受税后收入；固定成本覆盖为“完整”且有覆盖说明；按货币最小单位精确计算与展示；不是总资产、正式净资产或 Net Accumulation | `user-confirmed`、`estimated` 或 `insufficient-data` | 明确写“按你确认的税后收入和固定成本覆盖范围”；展示覆盖说明及未纳入范围 | 收入为税前、固定成本缺失/部分/未知或缺少覆盖说明时显示 `insufficient-data`，不把未知成本或税费当零 |
| 购买情景后的覆盖范围内可用余量 | 同周期覆盖范围内可用余量 − 购买价格 | `purchase-decision-rules@1.0.0`；用户确认购买属于所选周期；不自动分摊；按货币最小单位精确计算与展示；与真实记录隔离 | `forecast` 或 `insufficient-data` | 明确写“这是可调整情景，不是承诺或购买建议”；展示周期归属、税后基线、变化、输入状态和限制 | 任一关键输入、税后收入、完整覆盖或周期归属不足时停止，不展示确定数值；Work-time Equivalent 可独立展示 |
| 购买与暂不购买/等待差异 | 购买情景结果与当前可见基线的差异 | `purchase-decision-rules@1.0.0`；精确值固定为购买价格的相反数并按货币最小单位展示；不预测市场价格、收入或实际购买时间变化 | `forecast` 或 `insufficient-data` | 只描述本次输入下的算术差异，允许修改假设；不评价选择 | 缺少安全基线时说明只能查看 Work-time Equivalent，不能判断余量影响 |

所有结果必须同时提供：

- 简明观察和可展开的详细依据；
- 输入集合、输入状态和用户确认时点；
- 公式、单位、币种、比较周期和税前/税后口径；
- 规则版本、生成时点、假设、限制和不足原因；
- 返回修改、重新确认和重算入口。

第 7 节概念样例与 [ADR-0002](../../adr/ADR-0002-calculation-and-rules.md) 共同形成已批准的计算合同；实现必须同时满足精确公式、输入限额、展示舍入、时间上下文和 `purchase-decision-rules@1.0.0`。在第 9.2 节运行证据完成前，相关验收仍只能保持“计划”，不能判定通过。

### 5.4 隐私与安全影响

- 原始收入、工时、固定成本、购买价格、价值期待、决定理由和计算结果属于敏感数据；除用户明确触发的本地导出外，只能存在于当前浏览器内存。
- 除加载静态原型资源外，不发起包含原始会话数据或派生财务结果的应用请求。用户主动下载的本地文件是唯一允许的产品数据出口；经单独授权的封闭字段脱敏研究观察可以由研究者在产品外手工记录，但不得由原型自动发送。
- 除用户主动下载的文件外，不把原始会话数据或派生财务结果写入 Cookie、localStorage、sessionStorage、IndexedDB、Cache Storage、URL 查询参数、剪贴板、服务端、普通日志、分析事件、错误上报、截图或录屏。
- 静态资源、依赖和托管方案不得夹带第三方分析、字体追踪、会话重放或外部模型调用；具体供应链和托管边界由 ADR 决定。
- 如果采用静态托管，优先关闭访问日志；无法关闭时只允许保留 IP、User-Agent、访问时点等必要基础设施元数据，最多 7 天、不与研究编号或原型输入关联，并在研究说明中披露。项目账户仅 Alune 可查看；托管方若因基础设施运营或安全而处理这些元数据，必须受合同/配置约束、不得二次使用，并在交付形态 ADR 中给出管理员访问、用途和删除 readback；无法证明任一边界时改用本地分发。
- 错误界面和开发日志只允许记录合成错误码、规则版本和非敏感技术上下文，不得插入原始输入或完整派生结果。
- 研究联系方式、正式同意记录和撤回状态在产品外单独管理，不进入原型，不与原始会话数据关联；脱敏观察只使用研究编号。
- 当前 `RESEARCH-0001 0.1.0` 不录音、录像、截屏或保存原话。未来若修订协议允许任一额外内容，必须先批准独立存储、访问、保留、删除和用途合同，再取得与参与原型和脱敏观察授权分离的可选同意；拒绝不影响参与资格。
- 联系方式/同意与封闭字段观察必须使用两个独立加密存储，仅 Alune 访问；随机研究编号与联系人映射只存在于前者。任何逐人记录、映射表和真实联系信息都不得进入仓库、Issue、原型或默认云同步。
- 参与者撤回后立即停止联系，并在 7 个自然日内删除适用的可关联记录；联系方式/同意映射在最后一次计划回访后 30 天内删除，逐人脱敏观察在实验最终结论后 30 天内删除，只保留不可识别的聚合结论。具体工具、删除演练和无默认备份证明必须在 `RESEARCH-0001` 批准前完成。
- 用户可以在当前会话返回修改，或通过刷新、关闭和退出清除原型数据。上述动作不删除已下载文件；导出前后都必须明确提示该副本由用户自行管理。

### 5.5 长期输入成本

- **首次设置**：只选择一个比较周期并输入该周期的收入、税前/税后、工作小时、一种币种、一项购买价格、其周期归属和一句价值期待；固定成本汇总可选，填写时补充一句覆盖说明。不要求精确日期或跨周期换算。
- **持续维护**：原型不保存数据，不要求日、周或月维护，不提供连续打卡或提醒。
- **人工复盘**：用户自行选择适合决定的复盘条件或日期；研究者在产品外联系。联系方式和复盘安排不得与原始财务数据关联。
- **预计耗时**：当前为待验证指标，不预设未经证实的分钟目标；研究只记录输入轮次分档、耗时分档、首次阻塞阶段和主动修正次数。
- **降低负担**：不要求交易明细、工资单、商品链接、凭证、完整固定成本或所有生活维度；允许近似输入并明确标注。
- **导出负担**：导出完全可选，不阻塞 Decide 或人工复盘；入口复用当前会话数据，不要求二次录入或账户。
- **暂停与撤回**：用户可以在任何步骤退出；产品外提供撤回研究记录授权的联系路径和处理说明。不愿填写价值期待或不授权脱敏观察时不继续实验，也不使用催促或羞辱文案。

### 5.6 研究治理与责任边界

- `RESEARCH-0001` 是独立研究协议，负责正式同意、封闭字段 schema、两类加密存储、访问、保留、撤回、删除、静态访问元数据披露、研究日历和结果记录；本 PRD 继续定义不可放宽的产品与数据边界。
- Alune 兼任产品、数据/隐私、设计/可理解性和工程正式评审角色，并对所有门禁结论承担最终责任；AI 只能提供审查证据，不能作为签字主体。
- 在 `Recruitment Authorized` 前，必须由一名待指定的独立人类挑战者复核 `RESEARCH-0001`，并检查原型的网络、浏览器存储、托管日志和删除演练证据。关键意见未解决时不得招募；非关键意见必须解决或由 Alune 书面记录接受风险的理由。
- 仓库只允许保存研究协议、封闭字段 schema、合成示例和不可识别的聚合结论；不保存逐人记录、联系人、同意映射、原始财务输入、自由文本或未脱敏证据。

## 6. 指标与实验

所有研究指标在实验开始前为 `insufficient-data`。实际观察开始后，每条记录按其来源分别标注 `actual` 或 `user-confirmed`；不把研究指标状态传播为产品财务数据状态。

统一分母 `N_started` 为第二批中已完成正式研究同意和脱敏观察授权、并开始核心阶段 1 的参与者数。所有比率必须同时报告分子、`N_started`、各阶段中止/缺失数和撤回数，不能只在完成者中重算。参与者撤回时，只要逐人记录仍可通过研究编号关联，就在 7 个自然日内删除其适用记录并重算分母和聚合；同时报告撤回前后分母及变更理由。逐人记录和映射已按期删除后，只保留研究说明中预先披露、不能重新关联个人的聚合结论。

统一核心通过集合 `C_core` 为**同一组**第二批去重研究编号，且每个编号同时满足：完成理解检查并能说明来源、公式、状态和不确定性；能把决定/不决定与自己的价值期待关联；完成 Decide；完成人工复盘并产生结果/反馈类别、修正判断依据，或有依据确认无需修正。总体通过要求 `|C_core| ≥ 3`。各单项比率仍按 `N_started` 报告，不能把不同参与者在不同指标上的通过结果拼成 `C_core`。

| 指标 | 类型 | 定义/分母 | 数据来源 | 目标/阈值 | 解释限制 |
| --- | --- | --- | --- | --- | --- |
| 核心通过案例 | 实际 | `|C_core| ÷ N_started`；同时报告从开始到各阶段的流失 | 封闭字段脱敏研究观察 | `|C_core| ≥ 3`，且报告完整分母与流失 | 不等于 MVLU、留存或市场需求规模；不得跨参与者拼接 |
| 解释任务完成率 | 实际 | 未经诱导、能用自己的语言说明至少一个结果的来源、公式、状态和不确定性的人数 ÷ `N_started` | 预定义布尔检查项 | `C_core` 中每个案例均通过；全体结果和缺失如实报告 | 不以复述界面文案或研究者提示后的回答算通过 |
| 价值期待关联率 | 用户确认 + 实际观察 | 能说明决定/不决定与自己填写的价值期待有何关系的人数 ÷ `N_started` | 参与者回答后的封闭检查项 | `C_core` 中每个案例均通过；全体结果和缺失如实报告 | 不保存价值期待或回答全文，不把省钱、储蓄或使用率自动视为更有价值 |
| 复盘质量率 | 用户确认 + 实际观察 | 在实验截止前完成回访，并产生结果/反馈类别、判断依据修正，或有依据确认无需修正的人数 ÷ `N_started` | 封闭字段脱敏回访观察 | `C_core` 中每个案例均通过；同时报告应回访、已联系、完成和缺失人数 | 接受邀请、点击或按时出现不能单独算完成 |
| 输入负担 | 实际 | 对 `N_started` 全部案例报告首次有效理解前的输入轮次分档、耗时分档、首次阻塞阶段和主动修正次数，包括中止案例 | 封闭字段脱敏研究观察 | 当前不设未经验证的分钟目标；按阶段检查反复阻塞 | 更快不自动等于更有价值，不收集原始财务值、按键流或精确操作时间戳 |
| 关键隐私/信任失败数 | 实际 + 用户确认 | 所有技术演练和研究会话中的关键事件计数；按第 6 节严重级别判定 | 技术验证与脱敏事件代码 | 两批均为 0；任一关键事件立即暂停 | 轻微困惑与关键失败分开记录，不能用平均分掩盖严重事件 |

实验分两批进行：

1. **第一批（3–4 人）**：识别阻塞性理解、信任、输入负担和交互问题。只允许修正本 PRD 内的文案、顺序、解释和局部交互，不得加入非目标能力。
2. **门间评审**：记录第一批证据和修订；若修订改变数据语义、核心对象、隐私边界或历史契约，暂停并判断 RFC/ADR，不直接进入第二批。
3. **第二批（3–4 人）**：使用修订后的固定版本验证，并对愿意继续参与者完成人工复盘。
4. **到期决策**：第二批最后一次计划回访完成后 7 个自然日内记录继续、修订、停止或转入新 PRD/RFC/ADR 的结论。具体招募与回访日历必须在招募前写回 Issue #1。

停止、暂停与恢复规则：

- **关键隐私/信任事件**：未经用户明确导出操作，原始会话数据或派生财务结果发生网络外发、持久化或泄漏；导出文件遗漏/篡改数据状态、来源或关键限制，夹带研究/遥测字段，或被描述为已匿名/可由原型撤回；产品财务状态被错误显示为 `actual` 或其他更确定状态；用户无法更正或清除会话数据；界面替用户作决定，或出现明确羞辱、恐吓、操纵性输出。任一事件立即暂停分发和研究，不等待达到数量阈值。
- **恢复门槛**：Alune 是事件处理与实验决策 DRI，并兼任产品、数据/隐私、设计和工程正式评审角色。只有完成根因分析、修复、受影响范围与副本处置、与事件相关的原型验收组和研究治理组 AC 复验，并由独立人类挑战者复核相关隐私/安全证据后，Alune 才能书面决定恢复；未解决关键意见时必须终止本实验。
- **范围失效信号**：同一批至少 2 名相互独立的参与者明确表示，若不加入完整账本、Goal、账户、持久化、同步、提醒或 AI 就无法形成有用决定，记录为范围失效。第一批出现时停止进入第二批并回到问题研究；第二批再次出现，或解决方案必须越出本 PRD，终止当前切片并另起 Issue/RFC/PRD。
- **价值链未成立**：第二批到期时 `|C_core| < 3`，判定本轮未通过并停止进入实现扩张；不得用不同参与者的单项通过结果、完成者分母或临时延长招募掩盖。
- **其他系统性阻塞**：如果输入负担、可理解性或反焦虑问题在本 PRD 范围内修订后仍在下一批重复出现，由 Alune 记录“继续修订、退回研究或终止”的决定及证据；任何扩大范围的方案必须走新的门禁。

### 8.2 数据迁移/回填

无。原型不保存产品数据，不导入、不回填，也不从第一批向第二批迁移用户输入。研究批次只使用脱敏研究记录；其保留和删除规则必须在招募前批准。

### 8.3 回滚与恢复

- **首次构建**：如果尚无上一批已验证版本，回滚等于立即停止分发、撤下或禁用访问，并向已受邀参与者标明暂不可用；不得为了维持会话而继续使用有问题的构建。
- **代码/静态资源**：后续批次可恢复到上一批已验证的 commit、构建产物和规则版本；具体托管回滚由 ADR 定义。
- **配置/依赖**：访问控制、托管日志、构建配置或依赖发生问题时，同时回滚到对应的已验证配置锁定与依赖清单；不能只替换页面文件。
- **规则**：若计算或状态规则有误，立即停止实验，不允许继续展示错误结果；修正规则并更新版本后重新完成全部验收。
- **产品数据**：无持久化数据，无需恢复。若意外产生任何副本，视为隐私事件，立即暂停、定位、删除并验证不可恢复。
- **本地导出文件**：原型无法召回或删除用户已经下载的文件。若导出内容或 schema 有误，立即停用导出和构建、发布清晰说明并重新验收；不得声称代码回滚会修复既有文件。
- **研究记录**：按批准的研究记录规则删除或更正；规则未批准前不得招募。
- **停止条件**：按第 6 节的关键事件、恢复门槛和范围失效规则执行；不能以回滚成功替代事件复盘和重新批准。

### 8.4 上线后复盘

- 第一批最后一次会话后，由 Alune 汇总脱敏证据，决定仅修正本 PRD 范围内的问题、暂停或升级门禁。
- 第二批最后一次计划回访完成后 7 个自然日内，记录指标状态、用户反馈、信任事件、输入负担和假设结论。
- 结论只能是继续进入新的产品级 PRD/ADR、在本研究范围内再验证、停止该切片或退回问题研究；不得把研究原型直接升级为正式产品。
- 结果链接回 Issue #1 和本 PRD；所有外部结论明确样本、时间窗、证据状态和不能推出的内容。
