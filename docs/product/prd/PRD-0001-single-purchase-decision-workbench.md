# PRD-0001：单次购买决策工作台

| 项目 | 内容 |
| --- | --- |
| 状态 | 现有单次购买工作台规格；对话输入改造已完成本机实现与验证。当前收入看板已按 [PRD-0003](PRD-0003-income-dashboard.md) 接入首页，资料复用与新日历口径已通过自动检查及合成数据下的浏览器主路径验收，真实用户体验与回滚仍待验证 |
| 负责人 | Alune |
| 范围 | 一个用户、一个比较周期、一个购买场景 |
| 交付 | React + TypeScript + Vite 单页应用 |

## 用户任务

用户不想维护完整账本，也不想先自行统计每月工时，但希望在购买前把收入、工作时间、固定成本、购买价格和自己的期待放在一起理解，并留下自己的决定。

## 购买分析流程

本节记录单次购买工作台原有的内存态和 52 周 / 12 月作息估算，不再定义首页主入口。当前从收入看板进入购买分析时，按 PRD-0003 默认复用基础资料及当月日历工时，并允许用户主动选择单次平均作息或直接月工时覆盖；新收藏和快照格式按 ADR-0008 执行。旧 @1 文件和历史验证保持不变。

进入购买分析页默认显示一句话输入；用户主动发送后，本机服务调用 TypeSafe/Jev 整理当前回答。代码按必要缺项每次提出一个固定问题，允许用户回答不知道、跳过或使用快捷项。用户可随时切到手动入口，两种方式共用同一份草稿。所有待确认内容汇总为可编辑摘要，用户整体确认一次后查看结果，不再逐字段确认或返回表单二次确认。

首次发送前说明处理范围；请求只包含当前回答、当前问题和理解该回答所需的最少相关字段或原文片段，不带完整表单、全部聊天记录、价值期待或决定理由。页面打开、手动填写和快捷按钮不调用 Jev。识别或服务失败时保留回答和草稿，可主动重试或转手动，不自动重试。会话只存于浏览器内存；刷新、关闭或清空重填后不恢复。输入变化会使已确认结果及导出失效，并清除旧决定、理由及 `reviewCondition`；价值期待独立保留，用户需重新确认并选择决定。

## 输入

比较口径固定为 CNY、月度，不提供币种或周期选择。用户可以填写：

- 月收入和收入税口径；
- 平时作息：不预选，提供每周 5 天 × 每天 8 小时、每周 6 天 × 每天 8 小时两个快捷项，以及填写每周平均上班天数和每日平均工作小时数的“自己调整”；
- 直接填写每月工作时间的次级入口，保留原有“每月工作时间”字段；
- 购买价格及其是否已确认计入当前月份；
- 可选的月固定支出总额与覆盖状态；余量只能使用用户明确确认的完整覆盖范围；
- 个人价值期待；
- 主要通过一句话提供收入、税口径、购买价格和工作时间信息；Jev 可按用户明确提供的依据整理作息、直接月工时及用户主动开启余量后补充的固定支出、覆盖和本月付款信息。用户已提供的信息不得重复追问；未提及的信息不得猜测补齐。完整支持规则与上下文范围见 [ADR-0007](../../adr/ADR-0007-conversational-input.md)。
- 随时可用的手动填写入口和少量固定快捷选项；两者更新同一份草稿，明确快捷选项本地处理，不调用 Jev。
- 一个“我填写的数字里有大概数”的统一选择；它只影响用户直接填写的数字，开启时这些字段为 estimated，关闭时为 user-confirmed；由对话来源识别出的约数及作息换算月工时始终为 estimated。该开关不得提升已识别约数的证据状态。点击“确认并查看结果”即整体确认本次输入，导出仍按收入、工时、固定支出和购买金额分别保留 evidence 状态。

作息估算按「每周天数 × 每天小时 × 52 ÷ 12」计算，在进入现有月度计算前按 half-up 归一化到小数点后三位；每日小时包含经常发生的加班，不含通勤和休息，不逐月调整节假日、请假或临时加班。周天数须大于 0 且不超过 7，日小时须大于 0 且不超过 24；非法或不完整作息只让依赖工时的结果降级，不补零、旧值或猜测。直接填写月工时沿用原有精度和证据语义。

收入、工作时间来源或购买价格缺失、为零、为负、超限或口径冲突时，不得猜测或继续生成受影响的确定结果。月固定支出是渐进可选输入，可以为零；未填写、未提供或未确认完整覆盖时，只让余量结果降级，不阻塞收入速率和工作时间等价。

## 结果

| 结果 ID | 导出标签 | 含义 |
| --- | --- | --- |
| `work-time-equivalent` | 这笔钱相当于多少工作时间 | 购买价格对应的工作时间 |
| `income-rate` | 每小时收入 | 按已确认周期和工作时间计算的收入速率 |
| `available-margin` | 本月可用金额 | 税后收入减去完整固定支出后的余量 |
| `purchase-after-margin` | 买完后本月还剩 | 将购买价格计入本月后的情景余量 |
| `purchase-impact` | 这笔购买减少的余量 | 购买后余量减去购买前余量的差异，不重复计算固定支出 |

确认后，界面先显示工作时间结论，再补充每小时收入。工作时间如果来自作息换算，结果仍以小时展示且保持 estimated；直接填写月工时保留原有精度和证据语义。只有用户主动开启余量后，才显示余量结果；在此之前已提供的固定支出或付款信息可以保留待核对，但不会自动开启余量。单独填写价值期待不触发余量结果。购买影响只保留在 JSON 导出中。金额使用整数分精确计算，中间除法保留有理数，展示时再舍入。

每个界面结果用中文句子说明含义、单位和状态；无法计算时说明不足原因与修正动作。“怎么算出来的”说明公式和适用的税口径，结果区统一说明计算边界。完整的依赖字段、证据状态、原因码、精确值和规则来源保留在导出中；页面文案以 `docs/design/purchase-page-copy.md` 为准（相对仓库根目录）。

固定支出覆盖不完整或收入为税前口径时，两项余量和购买影响保持 insufficient-data；税前收入仍可用于每小时收入和工作时间。购买归属本月未确认时，只影响购买后余量和购买影响。两者可计算时固定为 forecast；它们不是承诺，也不是系统建议。

产品定义的证据状态只有以下五类：

- actual：有来源、时间和口径的已发生数据；
- user-confirmed：用户主动核对或批准；
- estimated：按明确假设得到的近似；
- forecast：针对未来的情景；
- insufficient-data：不足以安全得出结论。

当前页面的直接填写输入只产生 user-confirmed 或 estimated，不声明为 actual；作息换算的工时始终为 estimated。estimated 依赖不会变成 actual；作息估算不污染不依赖工时的余量状态；可计算的未来购买保持 forecast；缺失或冲突只影响依赖它的结果。

## 决定与导出

用户可在可选区填写个人价值期待，并在结果后选择购买、等待、调整条件、不购买或暂不决定，填写自己的依据。当前不采集复盘条件或日期，也不提供提醒或研究记录。界面不推荐、不评分、不排名、不催促。

用户点击确认查看结果后，可以导出当前确认会话的 JSON；即使结果全部不可用或尚未选择决定，也可以导出，缺失值与不足原因如实保留。导出是本地文件操作，不上传；文件进入设备后由用户控制。

导出保持 `zhiguan-purchase-decision@1`、现有 `inputs.work_hours`、证据字段和五项结果含义不变；`inputs` 增加 `work_time_basis`，记录作息输入方式、原始每周天数和每日小时，以及包含公式、52 周、12 个月、3 位小数、half-up 和两条时间范围假设的换算规则。直接填写月工时或尚未选择作息时，原始作息字段和换算规则为空；旧记录不反推作息，不建设兼容框架。

不保存确认时间、决定变更历史或输入快照历史；`exported_at` 只表示生成导出的时间。任何输入来源发生变化时，旧结果和导出入口失效，并清除旧决定、理由及 `reviewCondition`，防止将它们关联到新输入。用户重新整体确认后，如未重新选择决定，导出中的决定为 `null`。用户独立填写的价值期待不随输入变化清除。

## 信任边界

- 单页、客户端内存态；核心流程不提供账户、数据库或云端服务。只有用户主动发送对话时，浏览器才将当前回答、当前问题和理解所需的最少相关字段或原文片段发送到本机回环 Python 服务，由服务调用 TypeSafe/Jev；首次发送前披露处理方和范围。页面打开、手动操作或点击快捷项不发送请求；公开部署和多人服务不在当前范围。
- 不写 Cookie、Web Storage、IndexedDB 或分析事件。
- 请求不携带完整表单、全部聊天记录、价值期待、决定理由、结果或密钥；服务端按问题白名单裁剪上下文，密钥从 `.env` 加载，服务不记录请求或模型响应正文。对话原文与会话内部状态不进入导出；已发往服务商的请求无法由本地撤回，也不对其保留政策作承诺。
- 不使用远程字体、第三方数据同步或后台任务。
- 不收集身份、联系人、研究记录或完整财务账本。
- 不把用户的决定包装成系统建议；结果必须可追溯、可修正。
- 键盘、窄屏、辅助技术和减少动态路径必须可完成。

## 不在当前范围

完整记账、投资或财富建议、订阅/物品长期记录、账户、同步、提醒、AI 建议、自由文本生成、导入、分享、研究招募、研究存储和公开发布。AI 能力限于本 PRD 和 ADR-0007 规定的单次购买对话识别；追问与快捷选项由代码控制。

## 验收

1. 空白会话默认提供一句话入口；用户可用一句话提供多项信息，缺失时只追问一个必要问题并可跳过。对话与手动入口共用草稿，可编辑摘要后整体确认一次即显示结果；核心信息足够后不因余量字段未填而阻塞结果。
2. CNY 示例：税后月收入 10000、工作时间 160 小时、购买价格 1000 时，界面优先显示工作时间 16.00 小时，再显示每小时收入 62.50 元；用户未主动开启余量时不展示余量卡片，即使描述中提到固定支出也不自动开启；导出中的余量结果保持 insufficient-data。
3. 税后收入和固定支出有效且覆盖已确认时，购买前余量为收入减固定支出；购买后余量为购买前余量减购买价格，购买影响为两者差异，不把固定支出重复当作购买影响。购买归属本月未确认时，购买后余量和购买影响为 insufficient-data；可计算时两者状态固定为 forecast，不能伪装成事实。
4. 缺失、冲突或非法输入让受影响结果保持 insufficient-data，不显示零值、旧值或猜测；近似输入得到的可用当前结果保持 estimated，可用未来结果仍为 forecast，界面说明它们也是大概值；作息换算工时始终为 estimated，不因取消“我填写的数字里有大概数”而提升为 user-confirmed。
5. 选择每周 5 天 × 每天 8 小时或每周 6 天 × 每天 8 小时，以及自定义作息时，按每周天数 × 每天小时 × 52 ÷ 12 计算，并在现有月度计算前以 half-up 归一化到小数点后三位；直接填写月工时仍按原有精度计算。
6. 每个界面结果能展开查看计算公式及适用口径；不足原因与修正动作出现在结果或字段错误中，计算限制在结果区统一说明；JSON 保留依赖、证据状态、原因码、规则来源和精确值，并增加 `inputs.work_time_basis` 的作息依据。
7. 五种决定都能独立完成；页面保留可选的价值期待和依据，不采集复盘条件或日期，也不替用户判断。
8. 打开页面、纯手动填写、快捷按钮、确认、计算和导出不调用 Jev；用户主动发送前能看到处理范围。请求仅携带当前回答、当前问题与理解该回答所需的最少相关上下文，不含完整表单、全部对话、价值期待和决定理由。页面不使用浏览器持久化；刷新、关闭和退出清除内存会话，对话原文不进入 JSON。
9. 用户主动触发后能得到包含当前会话的 JSON 文件，且 evidence 仍按数字字段保留；取消或失败不会伪装成成功。
10. 键盘、窄屏和减少动态设置下，输入、结果、决定、导出和退出仍可完成。
11. Jev 能按用户提供的依据整理收入、税口径、价格、作息和直接月工时；只有用户主动开启余量后才追问固定支出、覆盖或付款信息。明确改口可更新已知值；歧义在一次澄清后仍未解决时保留不足状态。失败时保留草稿并可重试或转手动；快捷项、手动流程不调用 Jev。输入变化后旧结果及导出失效，旧决定、理由及 `reviewCondition` 不随新输入导出。
