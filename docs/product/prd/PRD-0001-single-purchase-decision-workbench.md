# PRD-0001：单次购买决策工作台

| 项目 | 内容 |
| --- | --- |
| 状态 | 当前开发规格 |
| 负责人 | Alune |
| 范围 | 一个用户、一个比较周期、一个购买场景 |
| 交付 | React + TypeScript + Vite 单页应用 |

## 用户任务

用户不想维护完整账本，但希望在购买前把收入、工作时间、固定成本、购买价格和自己的期待放在一起理解，并留下自己的决定。

## 当前流程

输入 → 确认口径 → 理解结果 → 记录决定。

应用只处理当前浏览器内存中的会话。刷新、关闭或清空重填后不恢复。修改输入后隐藏结果、决定和导出入口，重新确认后再显示；已有决定和理由仍保留在当前会话中，尚未与每次确认的输入绑定为独立记录。

## 输入

比较口径固定为 CNY、月度，不提供币种或周期选择。用户可以填写：

- 月收入、收入税口径和月工作时间；
- 购买价格及其是否已确认计入当前月份；
- 可选的月固定支出总额与覆盖状态；余量只能使用用户明确确认的完整覆盖范围；
- 个人价值期待；
- 一个“这些数字里有大概数”的统一选择；开启时四个数字字段为 estimated，关闭时为 user-confirmed；点击“确认并查看结果”即确认本次输入，导出仍按收入、工时、固定支出和购买金额分别保留 evidence 状态。

收入、工作时间或购买价格缺失、为零、为负、超限或口径冲突时，不得猜测、换算或继续生成受影响的确定结果。月固定支出是渐进可选输入，可以为零；未填写、未提供或未确认完整覆盖时，只让余量结果降级，不阻塞收入速率和工作时间等价。

## 结果

| 结果 ID | 导出标签 | 含义 |
| --- | --- | --- |
| `work-time-equivalent` | 这笔钱相当于多少工作时间 | 购买价格对应的工作时间 |
| `income-rate` | 每小时收入 | 按已确认周期和工作时间计算的收入速率 |
| `available-margin` | 本月可用金额 | 税后收入减去完整固定支出后的余量 |
| `purchase-after-margin` | 买完后本月还剩 | 将购买价格计入本月后的情景余量 |
| `purchase-impact` | 这笔购买减少的余量 | 购买后余量减去购买前余量的差异，不重复计算固定支出 |

确认后，界面先显示工作时间结论，再补充每小时收入。当前固定支出字段非空，或支出覆盖、购买月份确认任一有值时，才显示两项余量结果；单独填写价值期待不触发余量结果。购买影响只保留在 JSON 导出中。金额使用整数分精确计算，中间除法保留有理数，展示时再舍入。

每个界面结果用中文句子说明含义、单位和状态；无法计算时说明不足原因与修正动作。“怎么算出来的”说明公式和适用的税口径，结果区统一说明计算边界。完整的依赖字段、证据状态、原因码、精确值和规则来源保留在导出中；页面文案以 `docs/design/purchase-page-copy.md` 为准（相对仓库根目录）。

固定支出覆盖不完整或收入为税前口径时，两项余量和购买影响保持 insufficient-data；税前收入仍可用于每小时收入和工作时间。购买归属本月未确认时，只影响购买后余量和购买影响。两者可计算时固定为 forecast；它们不是承诺，也不是系统建议。

产品定义的证据状态只有以下五类：

- actual：有来源、时间和口径的已发生数据；
- user-confirmed：用户主动核对或批准；
- estimated：按明确假设得到的近似；
- forecast：针对未来的情景；
- insufficient-data：不足以安全得出结论。

当前页面的自填输入只产生 user-confirmed 或 estimated，不声明为 actual。estimated 依赖不会变成 actual；可计算的未来购买保持 forecast；缺失或冲突只影响依赖它的结果。

## 决定与导出

用户可在可选区填写个人价值期待，并在结果后选择购买、等待、调整条件、不购买或暂不决定，填写自己的依据。当前不采集复盘条件或日期，也不提供提醒或研究记录。界面不推荐、不评分、不排名、不催促。

用户点击确认查看结果后，可以导出当前确认会话的 JSON；即使结果全部不可用或尚未选择决定，也可以导出，缺失值与不足原因如实保留。导出是本地文件操作，不上传；文件进入设备后由用户控制。

当前不保存确认时间、决定变更历史或输入快照历史，`exported_at` 只表示生成导出的时间。旧决定可能随重新确认的输入一起导出，尚不能追溯它最初对应的输入；这是相对于 PRODUCT.md 确认和变更可追踪要求的实现缺口，不代表该要求被取消。

## 信任边界

- 单页、客户端内存态；不提供账户、API、数据库或云端服务。
- 不写 Cookie、Web Storage、IndexedDB 或分析事件。
- 不使用外部网络、远程字体、第三方数据同步或后台任务。
- 不收集身份、联系人、研究记录或完整财务账本。
- 不把用户的决定包装成系统建议；结果必须可追溯、可修正。
- 键盘、窄屏、辅助技术和减少动态路径必须可完成。

## 不在当前范围

完整记账、投资或财富建议、订阅/物品长期记录、账户、同步、提醒、AI、导入、分享、研究招募、研究存储和公开发布。

## 验收

1. 用户能从空白会话完成三个核心数字和收入税口径，点击确认后查看两个核心结果并记录一个决定；固定支出可以稍后补充。
2. CNY 示例：税后月收入 10000、工作时间 160 小时、购买价格 1000 时，界面优先显示工作时间 16.00 小时，再显示每小时收入 62.50 元；固定支出、覆盖确认和本月付款确认均未填写时不展示余量卡片，导出中的余量结果保持 insufficient-data。
3. 税后收入和固定支出有效且覆盖已确认时，购买前余量为收入减固定支出；购买后余量为购买前余量减购买价格，购买影响为两者差异，不把固定支出重复当作购买影响。购买归属本月未确认时，购买后余量和购买影响为 insufficient-data；可计算时两者状态固定为 forecast，不能伪装成事实。
4. 缺失、冲突或非法输入让受影响结果保持 insufficient-data，不显示零值、旧值或猜测；近似输入得到的可用当前结果保持 estimated，可用未来结果仍为 forecast，界面说明它们也是大概值。
5. 每个界面结果能展开查看计算公式及适用口径；不足原因与修正动作出现在结果或字段错误中，计算限制在结果区统一说明；JSON 保留依赖、证据状态、原因码、规则来源和精确值。
6. 五种决定都能独立完成；页面保留可选的价值期待和依据，不采集复盘条件或日期，也不替用户判断。
7. 除加载静态页面资源外，页面不外发会话数据，也不使用浏览器持久化；刷新、关闭和退出清除内存会话。
8. 用户主动触发后能得到包含当前会话的 JSON 文件，且 evidence 仍按数字字段保留；取消或失败不会伪装成成功。
9. 键盘、窄屏和减少动态设置下，输入、结果、决定、导出和退出仍可完成。
