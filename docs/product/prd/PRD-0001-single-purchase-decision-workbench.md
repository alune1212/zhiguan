# PRD-0001：单次购买决策工作台

| 项目 | 内容 |
| --- | --- |
| 状态 | 当前开发规格 |
| 负责人 | Alune |
| 范围 | 一个用户、一个比较周期、一个购买场景 |
| 交付 | React + TypeScript + Vite 单页应用 |

## 用户任务

用户不想维护完整账本，但希望在购买前把收入、工作时间、固定成本、购买价格和自己的期待放在一起理解，并留下自己的决定。

## 当前流程

输入 → 确认口径 → 理解结果 → 记录决定。

应用只处理当前浏览器内存中的会话。刷新、关闭或退出后不恢复。

## 输入

用户可以填写：

- 固定的 CNY 月度比较口径；
- 月收入、收入税口径和月工作时间；
- 购买价格及其是否已确认计入当前月份；
- 可选的月固定支出总额与覆盖状态；余量只能使用用户明确确认的完整覆盖范围；
- 个人价值期待；
- 一个“这些数字里有估算值”的统一选择；开启时四个数字字段为 estimated，关闭时为 user-confirmed；点击“确认并查看结果”即确认本次输入，导出仍按收入、工时、固定支出和购买金额分别保留 evidence 状态。

收入、工作时间或购买价格缺失、为零、为负、超限或口径冲突时，不得猜测、换算或继续生成受影响的确定结果。月固定支出是渐进可选输入，可以为零；未填写、未提供或未确认完整覆盖时，只让余量结果降级，不阻塞收入速率和工作时间等价。

## 结果

| 结果 | 含义 |
| --- | --- |
| 每小时收入 | 按已确认周期和工作时间计算的收入速率 |
| 这笔钱相当于多少工作时间 | 购买价格对应的工作时间 |
| 覆盖范围内可用余量 | 收入减去已覆盖固定成本后的余量 |
| 购买后余量 | 将购买价格计入当前周期后的情景余量 |
| 购买影响 | 购买后余量减去购买前余量的差异，不重复计算固定支出 |

界面先显示前两个核心结果；用户开始补充余量信息后，才显示可用余量和购买后余量。与购买价格重复的“购买影响”不占用界面，但继续保留在 JSON 导出中。金额结果使用精确的最小货币单位计算；当前 CNY 月度实现使用整数分。每个界面结果用中文显示含义、单位、公式、状态和不足原因；折叠说明交代依赖、口径、限制与修正方式，精确值和规则来源保留在导出中。

固定支出覆盖不完整或购买尚未确认归属当前月份时，受影响的余量显示 insufficient-data。购买后余量和购买影响是未来情景，状态为 forecast；它们不是承诺，也不是系统建议。

证据状态只有以下五类：

- actual：有来源、时间和口径的已发生数据；
- user-confirmed：用户主动核对或批准；
- estimated：按明确假设得到的近似；
- forecast：针对未来的情景；
- insufficient-data：不足以安全得出结论。

estimated 依赖不会变成 actual；未来购买保持 forecast；缺失或冲突只影响依赖它的结果。

## 决定与导出

用户可在可选区填写个人价值期待，并在结果后选择购买、等待、调整条件、不购买或暂不决定，填写自己的依据。当前不采集复盘条件或日期，也不提供提醒或研究记录。界面不推荐、不评分、不排名、不催促。

用户点击确认查看结果后，可以导出当前确认会话的 JSON。导出是本地文件操作，不上传；文件进入设备后由用户控制。

## 信任边界

- 单页、客户端内存态；不提供账户、API、数据库或云端服务。
- 不写 Cookie、Web Storage、IndexedDB 或分析事件。
- 不使用外部网络、远程字体、第三方数据同步或后台任务。
- 不收集身份、联系人、研究记录或完整财务账本。
- 不把用户的决定包装成系统建议；结果必须可追溯、可修正。
- 键盘、窄屏、辅助技术和减少动态路径必须可完成。

## 不在当前范围

完整记账、投资或财富建议、订阅/物品长期记录、账户、同步、提醒、AI、导入、分享、研究招募、研究存储和公开发布。

## 验收

1. 用户能从空白会话完成三个核心数字和收入税口径，点击确认后查看两个核心结果并记录一个决定；固定支出可以稍后补充。
2. CNY 示例：收入 10000、工作时间 160 小时、购买价格 1000 时，界面显示每小时收入 62.50 元、工作时间 16.00 小时；未开始填写固定支出时不展示余量卡片，导出中的余量结果保持 insufficient-data。
3. 固定支出覆盖已确认时，购买前余量为收入减固定支出；购买后余量为购买前余量减购买价格，购买影响为两者差异，不把固定支出重复当作购买影响。购买归属当前月份未确认时，购买后余量和购买影响为 insufficient-data；可计算时两者状态固定为 forecast，不能伪装成事实。
4. 缺失、冲突、非法或近似输入按上述状态降级，不显示零值、旧值或伪精确结果；固定支出缺失只影响余量结果。
5. 每个界面结果能展开查看口径、公式、依赖、限制和修正方式；JSON 保留规则来源和精确值。
6. 五种决定都能独立完成；页面保留可选的价值期待和依据，不采集复盘条件或日期，也不替用户判断。
7. 除加载静态页面资源外，页面不外发会话数据，也不使用浏览器持久化；刷新、关闭和退出清除内存会话。
8. 用户主动触发后能得到包含当前会话的 JSON 文件，且 evidence 仍按数字字段保留；取消或失败不会伪装成成功。
9. 键盘、窄屏和减少动态设置下，输入、结果、决定、导出和退出仍可完成。
