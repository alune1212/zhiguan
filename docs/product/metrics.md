# 值观指标定义

**版本：** 1.0.0
**更新日期：** 2026-11-11

本文件定义产品结果的表达口径，不设置未经验证的数值目标，也不存储真实用户数据。收入看板已通过自动检查及合成数据下的浏览器主路径验收；真实用户体验反馈仍待验证。购买讨论尚未实现。指标帮助用户理解自己的选择，不用于财富排行、行为操控或人生总分。

## 1. 证据状态

每个指标必须带一个证据状态。状态描述的是数据来源与确定程度，而不是好坏等级：

| 状态 | 英文标识 | 使用条件 | 展示要求 |
| --- | --- | --- | --- |
| 实际 | `actual` | 有来源、时间和口径明确的已发生数据 | 展示来源、时间范围和可更正入口 |
| 用户确认 | `user-confirmed` | 用户主动核对或批准的记录 | 记录确认时间与用户可撤回/修改状态 |
| 估算 | `estimated` | 由已知输入按明确假设推导的近似值 | 展示假设、计算方法和近似性质 |
| 预测 | `forecast` | 针对未来的情景或模型推断 | 展示范围、依据、有效期和不确定性 |
| 数据不足 | `insufficient-data` | 缺少必要来源、口径或覆盖范围 | 不输出确定性结论，说明缺少什么 |

状态不是自动升级的：导入或计算不会把 `estimated` 变成 `actual`，用户确认也不会消除外部来源的不确定性。

当前购买工作台的自填输入只产生 `user-confirmed` 或 `estimated`；可计算的未来情景为 `forecast`，不能计算时为 `insufficient-data`，不产生 `actual`。

## 2. 指标共同字段

所有可展示指标至少要能追溯到以下上下文：

- 指标名称与稳定英文标识；
- 时间范围、时区和刷新时间；
- 货币、工作时间、周期和舍入口径；
- 原始来源或用户输入；
- 证据状态及其变更记录；
- 计算公式、假设和限制；
- 用户可更正、删除或重新计算的入口。

以上是产品级追溯要求。当前应用可查看购买公式、修正输入、清空会话并导出结果元数据；本地资料记录更新时间，收藏保存当时的输入和口径。应用不保存确认时间、状态变更或输入快照历史；导出时间不等于确认时间。这些追溯缺口仍未覆盖。收入看板、资料和收藏已通过自动检查及合成数据下的浏览器主路径验收，真实用户体验仍待验证。

## 3. 产品指标目录

当前应用包含收入看板的每秒、今日和本月收入估算，以及购买工作台的收入速率、工作时间等价、本月可用金额、购买后余量和购买影响；购买结果 ID、顺序和导出范围见 [PRD-0001](prd/PRD-0001-single-purchase-decision-workbench.md)。阶段一的日成本、单次使用成本以 [PRD-0004](prd/PRD-0004-purchase-council.md) 为准，功能尚未实现。净积累、目标进度、目标完成预测和订阅实现价值已移到文末历史指标，只用于阅读旧文档。Goal 进度切片已撤下，见 [PRD-0002](prd/PRD-0002-goal-progress.md)。

收入看板的“每秒收入估算”“今日收入估算”和“本月收入估算”已按 PRD-0003 接入代码；其分母按选定时区和当月计划工作区间计算，结果为 `estimated`，不表示实际到账。合成数据下的浏览器主路径已通过，真实用户体验仍待验证。

### 收入速率（Income Rate）

在用户选择的周期与工作量口径下，收入相对于工作时间或日历时间的速率。基本形式为：

```text
收入速率 = 约定收入 ÷ 对应时间口径
```

必须说明分母是工作时长、日历时长还是其他用户定义的时间。不能把月薪直接称为真实时薪。

### 工作时间等价（Work-time Equivalent）

把一个金额按收入速率或用户指定口径换算为时间：

```text
工作时间等价 = 金额 ÷ 收入速率
```

它描述经济代价的一个视角，不代表时间本身的全部价值，也不用于评价某项体验是否值得。

### 本月可用金额（Available Margin）

税后月收入减去用户确认已完整覆盖的月固定支出。税前收入、缺失或无效固定支出、未确认覆盖范围时保持 `insufficient-data`；未覆盖的成本不能视为零。

### 购买后余量（Purchase-after Margin）

本月可用金额减去这笔购买的价格。必须明确确认按本月付款；可计算时为 `forecast`，表示当前条件下的情景。

### 购买影响（Purchase Impact）

当前实现为购买后余量减去本月可用金额，只保留在 JSON 导出中；前提与购买后余量一致，可计算时固定为 `forecast`。它不重复计算固定支出，也不构成“应该购买”的建议。

### 单次使用成本（Cost per Use）

阶段一按 [PRD-0004](prd/PRD-0004-purchase-council.md)：购买价格除以用户填写的预计使用次数。缺少次数或持有天数时为 `insufficient-data`。它不代表体验价值，功能尚未实现。旧定义「已发生的拥有成本 ÷ 已记录使用次数」不再作为现行口径。

## 4. 北极星指标

现行北极星是用户自己收下的购买讨论：用户提交一笔犹豫，看到基于事实卡的倾向和改变条件，并自己选择五种决定之一。回访和共享真实回访是后续阶段，不是阶段一的成功前提。打开次数、讨论字数、模型调用次数和动画观看时长都不能代替这次决定。

阶段一尚未实现，因此这项使用的测量状态是 `insufficient-data`。不新增后台行为上报，也不为了计数引入账户。没有明确范围内的使用反馈时，不制造基线或市场结论。

月度价值闭环用户数是 0.2.0 的历史指标，定义留在 [RFC-0001](rfc/RFC-0001-income-understanding.md)，不再使用。

收入看板「能否看懂估算、再次打开是否免于重填」仍是已实现功能的体验问题，不是现行北极星。

## 5. 指标禁用规则

- 不展示用户之间的财富、收入、消费或“价值”排名。
- 不把连续使用、输入次数、通知点击或购买转化作为单独的价值证明。
- 不在没有来源或口径时填入零、平均值或系统默认值并伪装成事实。
- 不用一个综合分数替代用户自己的价值判断。
- 不把产品内部事件量直接称为用户收益；内部运营指标必须与产品结果分开并标注范围。

## 6. 历史指标

以下指标来自 0.2.0 及更早的对象清单。宪法 1.0.0 不再把目标、订阅或净积累当作现行对象。定义留在这里，便于阅读旧文档。

### 净积累（Net Accumulation）

在明确时间范围、货币和纳入范围内：可确认收入减去可确认成本。它不是总资产、净资产或投资收益，不能用于人与人比较。未覆盖的收入或成本不得静默视为零。

### 目标进度（Goal Progress）

在用户定义的目标基准、当前状态和时间范围下，描述已经完成的部分与剩余部分。无法确认基准时标为 `insufficient-data`。对应功能已按 PRD-0002 撤回。

### 目标完成预测（Goal Completion Forecast）

按用户选择的节奏估计目标可能完成的时间。必须标明 `forecast`，不得承诺结果。

### 订阅实现价值（Subscription Realized Value）

用户在某个周期里对订阅的使用和自己的判断。不能只用使用次数推导价值。

### 固定成本负担（Fixed Cost Load）

指定周期内固定成本相对于可用收入或可用余量的关系。分子、分母和周期必须同时可见。阶段一的事实卡只在用户填写固定支出时计算余量，不单列这项负担指标。
