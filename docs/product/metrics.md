# 值观指标定义

**版本：** 0.1.1
**更新日期：** 2026-09-03

本文件定义产品结果的表达口径，不设置未经验证的数值目标，也不存储真实用户数据。指标用于帮助用户理解和复盘，不用于财富排行、行为操控或对个人进行“人生总分”评价。

## 1. 证据状态

每个指标必须带一个证据状态。状态描述的是数据来源与确定程度，而不是好坏等级：

| 状态 | 英文标识 | 使用条件 | 展示要求 |
| --- | --- | --- | --- |
| 实际 | `actual` | 有来源、时间和口径明确的已发生数据 | 展示来源、时间范围和可更正入口 |
| 用户确认 | `user-confirmed` | 用户主动核对或批准的记录 | 记录确认时间与用户可撤回/修改状态 |
| 估算 | `estimated` | 由已知输入按明确假设推导的近似值 | 展示假设、计算方法和近似性质 |
| 预测 | `forecast` | 针对未来的情景或模型推断 | 展示范围、依据、有效期和不确定性 |
| 数据不足 | `insufficient-data` | 缺少必要来源、口径或覆盖范围 | 不输出确定性结论，说明缺少什么 |

状态不是自动升级的：导入或计算不会把 `estimated` 变成 `actual`，用户确认也不会消除外部来源的不确定性。

当前购买工作台的自填输入只产生 `user-confirmed` 或 `estimated`；可计算的未来情景为 `forecast`，不能计算时为 `insufficient-data`，不产生 `actual`。

## 2. 指标共同字段

所有可展示指标至少要能追溯到以下上下文：

- 指标名称与稳定英文标识；
- 时间范围、时区和刷新时间；
- 货币、工作时间、周期和舍入口径；
- 原始来源或用户输入；
- 证据状态及其变更记录；
- 计算公式、假设和限制；
- 用户可更正、删除或重新计算的入口。

以上是产品级追溯要求。当前购买工作台可查看公式、修正输入、清空会话并导出结果元数据，但只处理固定 CNY 月度会话，不保存确认时间、状态变更或输入快照历史；导出时间不等于确认时间。这些追溯缺口不能视为已经交付。

## 3. 产品指标目录

当前购买工作台只实现收入速率、工作时间等价、本月可用金额、购买后余量和购买影响，具体结果 ID、显示顺序和导出范围见 [PRD-0001](prd/PRD-0001-single-purchase-decision-workbench.md)。下列固定成本负担、净积累、目标、订阅和单次使用成本是产品概念定义，不代表当前功能；Goal 进度切片已撤下，见 [PRD-0002](prd/PRD-0002-goal-progress.md)。

### 收入速率（Income Rate）

在用户选择的周期与工作量口径下，收入相对于工作时间或日历时间的速率。基本形式为：

```text
收入速率 = 约定收入 ÷ 对应时间口径
```

必须说明分母是工作时长、日历时长还是其他用户定义的时间。不能把月薪直接称为真实时薪。

### 工作时间等价（Work-time Equivalent）

把一个金额按收入速率或用户指定口径换算为时间：

```text
工作时间等价 = 金额 ÷ 收入速率
```

它描述经济代价的一个视角，不代表时间本身的全部价值，也不用于评价某项体验是否值得。

### 本月可用金额（Available Margin）

税后月收入减去用户确认已完整覆盖的月固定支出。税前收入、缺失或无效固定支出、未确认覆盖范围时保持 `insufficient-data`；未覆盖的成本不能视为零。

### 购买后余量（Purchase-after Margin）

本月可用金额减去这笔购买的价格。必须明确确认按本月付款；可计算时为 `forecast`，表示当前条件下的情景。

### 购买影响（Purchase Impact）

当前实现为购买后余量减去本月可用金额，只保留在 JSON 导出中；前提与购买后余量一致，可计算时固定为 `forecast`。它不重复计算固定支出，也不构成“应该购买”的建议。

### 固定成本负担（Fixed Cost Load）

指定周期内固定成本相对于可用收入或可用余量的关系。分子、分母和周期必须同时可见；当其中一方不足时标为 `insufficient-data`。

### 净积累（Net Accumulation）

在明确时间范围、货币和纳入范围内：

```text
净积累 = 可确认收入 − 可确认成本
```

该指标不等于总资产、净资产或投资收益，不能用于人与人比较。未覆盖的收入或成本不得静默视为零。

### 目标进度（Goal Progress）

在用户定义的目标基准、当前状态和时间范围下，描述已经完成的部分与剩余部分。目标可以是金钱、时间、体验或选择余量；无法确认基准时标为 `insufficient-data`。

### 目标完成预测（Goal Completion Forecast）

基于用户选择的节奏和明确假设，对目标可能完成时间建立情景：

```text
预测完成时间 = 当前剩余量 ÷ 选定的预测速率
```

必须明确这是 `forecast`，并允许用户修改速率、暂停或删除预测；不得承诺结果。

### 订阅实现价值（Subscription Realized Value）

用户在指定周期内对订阅使用、结果和主观重要性的复盘记录。不能只用使用次数推导价值；没有用户定义或足够结果时标为 `insufficient-data`。

### 单次使用成本（Cost per Use）

在用户选定的拥有成本与使用次数范围内：

```text
单次使用成本 = 纳入范围的拥有成本 ÷ 记录的使用次数
```

成本范围、使用定义和未使用状态必须可见。这个指标不包含体验、情感、社交或长期意义等无法由成本公式替代的价值。

## 4. 北极星指标

当前北极星指标是 **月度价值闭环用户数（Monthly Value Loop Users, MVLU）**：在一个自然月内，至少完成一次“基于个人数据获得洞察 → 记录、确认或调整具体决定 → 在之后记录结果、反馈或复盘”闭环的去重用户数。

概念计算式：

```text
月度价值闭环用户数
= 当月完成「证据 → 理解 / 推演 → 用户决定 / 行动 → 复盘」的去重用户数
```

该指标定义已经由产品宪法采用；它的基线、目标、稳定采样方式和对真实帮助的预测效度仍未验证，因此当前测量状态为 `insufficient-data`。在开始量化前，必须通过用户研究确认“完成”是否代表真实帮助，而不是增加点击或打卡；打开页面、停留时长、通知点击或自动生成内容不能单独构成完成。

## 5. 指标禁用规则

- 不展示用户之间的财富、收入、消费或“价值”排名。
- 不把连续使用、输入次数、通知点击或购买转化作为单独的价值证明。
- 不在没有来源或口径时填入零、平均值或系统默认值并伪装成事实。
- 不用一个综合分数替代用户自己的价值判断。
- 不把产品内部事件量直接称为用户收益；内部运营指标必须与产品结果分开并标注范围。
