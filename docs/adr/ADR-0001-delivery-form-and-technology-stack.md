## 1. 决策摘要

**已批准：**`PRD-0001` 的首个形成性研究原型采用 `React + TypeScript + Vite` 构建为纯客户端静态资源，由研究者控制的设备使用锁定版本的 `vite preview` 在本机或受控局域网内提供；Node.js 24 LTS 与 npm 只参与构建、测试和本地静态服务，不进入浏览器运行时。

浏览器运行时只包含 React、React DOM 和项目代码。计算、证据状态、会话修订与导出序列化保持框架无关的纯 TypeScript；不引入应用后端、浏览器持久化、Service Worker、PWA、Router、外部状态库、UI 组件库、远程字体、CDN 资源、分析、会话重放或错误上报。当前不批准任何云托管商；以后启用云托管必须修订本 ADR 或创建新 ADR，并重新证明访问元数据、用途、权限、保留和删除边界。

本 ADR 已为 `Accepted`，但它只满足 `PRD-0001` 要求的三项架构前置决策中的第一项，不单独构成 `Implementation Authorized`，仍不授权初始化框架、创建 OpenSpec、编写实现或向参与者分发原型。

## 2. 背景与问题

[`PRD-0001`](../product/prd/PRD-0001-single-purchase-decision-workbench.md) 已获批准，只授权开始具体 ADR。仓库截至 `2026-08-21` 仍没有可运行应用、依赖清单、构建产物、业务 API、数据库或生产部署；[`RESEARCH-0001`](../research/RESEARCH-0001-single-purchase-decision-protocol.md) 仍为 `Draft`，不得招募、收集研究记录或向参与者分发原型。

本决策服务 Now 阶段的单案例购买决策任务，以及原型内的 `Capture → Normalize → Understand → Simulate → Decide`。原型需要支持多步骤输入、五类证据状态、局部失败降级、可展开依据、用户决定、本地导出交接、桌面与移动浏览器、键盘和 VoiceOver，同时守住以下已批准边界：

- 原始收入、工时、购买价格、固定成本、覆盖说明、价值期待、决定依据、复盘条件和派生财务结果只存在于当前浏览器内存；
- 除用户明确触发的本地 JSON/Markdown 下载外，产品数据不发送网络、不写浏览器持久化、不进入日志、遥测或研究记录；
- 刷新、关闭或退出后原型数据不可恢复；
- 原型不是正式产品基础，不引入账户、身份、同步、数据库、通知、AI、PWA 或生产托管；
- 交付形态必须可停止、可替换、可复现，并能在托管边界不能证明时 fail-closed。

本 ADR 中的证据状态说明如下，避免把工程判断写成已验证事实：

| 状态 | 当前证据 |
| --- | --- |
| `actual` | 上位治理文档、已批准的 `PRD-0001`、当前无应用/依赖/构建的仓库事实，以及云托管商公开文档能够直接证明的行为 |
| `user-confirmed` | Alune 于 `2026-08-21` 确认推荐方向，并明确批准本 ADR 为 `Accepted`；该批准不代表实现或运行时验收已经完成 |
| `estimated` | React 相比原生 DOM 能降低本原型状态同步维护风险，以及最小依赖边界能降低供应链负担；这些是待验证工程判断 |
| `forecast` | 技术栈预计能满足性能、可访问性和可复现构建要求；实现前不能写成已通过 |
| `insufficient-data` | 实际包体、依赖数量、性能、浏览器兼容、VoiceOver 质量、网络/存储行为、本地服务日志行为和操作负担均尚无运行时证据 |

需要回答的问题是：在不提前实现、也不把研究原型误当正式产品架构的前提下，选择哪种交付形态和前端技术栈，才能以最小可控边界完成后续实现和验收。

## 3. 决策驱动因素

- [x] **产品任务与价值循环对齐：**只服务单案例购买决策的形成性研究，不扩大到完整账本、Goal、账户、同步、AI 或正式产品。
- [x] **隐私与数据主权：**敏感会话数据仅在浏览器内存；用户主动下载是唯一产品数据出口；没有静默持久化或运行时外发。
- [x] **可解释性与用户控制：**UI 状态必须与纯 TypeScript 领域结果一致，能够展示来源、公式/规则接口、单位、周期、证据状态、生成时点、假设和失败原因。
- [x] **历史口径与可重现性：**每批构建可关联 Git commit、构建摘要、依赖锁、Node/npm 版本、配置版本和后续计算/导出规则版本；不把静态资源缓存当作产品历史。
- [x] **可迁移、可导出与退出：**领域逻辑不依赖 React；原型可立即停止服务；用户已下载文件的控制边界必须如实说明。
- [x] **安全边界与最小权限：**不含后端、身份、第三方运行时代码、分析或外部资源；默认仅绑定 loopback，LAN 只在受控研究场景显式启用。
- [x] **可靠性、可运维性与成本：**单一静态产物、锁定工具链、无生产基础设施；首次失败可直接停止，后续可恢复完整的已验证产物和配置。
- [x] **无障碍与性能：**正式支持 PRD 指定的桌面 Chrome、macOS Safari、iOS Safari 和 Windows Chrome；满足键盘、VoiceOver、减少动态和 `3s / 100ms / 500ms / 1s` 实验室预算。
- [x] **供应链与可审查性：**直接依赖最小化、版本锁定、无 CDN/动态远程代码，构建和测试依赖可形成清单并审查安装脚本、许可证和安全通告。

## 4. 候选方案

### 4.1 交付形态候选

| 方案 | 满足驱动因素 | 用户/数据影响 | 复杂度/成本 | 兼容/迁移/回滚 | 风险 |
| --- | --- | --- | --- | --- | --- |
| A. **研究者控制的本地/LAN 静态服务（推荐）**：Vite 构建 `dist`，锁定版 `vite preview` 只服务该产物 | 不需要应用后端或第三方托管商；可在同一静态产物上测试桌面和 iOS Safari | 产品数据留在参与者浏览器内存；静态服务器只应收到资源请求；LAN 元数据不得持久化 | 复用构建工具，无额外服务依赖；需要受控设备、网络和会话操作清单 | 首次失败停止服务；后续恢复完整已验证产物、配置和依赖锁；不迁移产品数据 | Vite 明确不把 `preview` 定义为生产服务器；LAN 暴露、缓存、请求日志和研究操作负担仍需验证 |
| B. 云静态托管：Cloudflare Pages、GitHub Pages 或 Netlify | 都能分发静态 HTML/CSS/JS，但当前公开证据不能完整满足 FR-24/AC-25 | 托管方会处理或可能处理 IP、User-Agent、访问时点等基础设施元数据 | 远程访问方便；需要账户、合同、权限、日志和删除治理 | 可撤下或回滚部署，但托管方副本与日志删除必须单独证明 | 当前无法证明“关闭日志或最多 7 天且可完成删除 readback、仅 Alune 查看、无二次使用”，因此 fail-closed 不选 |
| C. 可直接 `file://` 打开的单文件包 | 理论上不需要本地 HTTP 服务或云托管 | 可减少服务器元数据 | 需要额外单文件打包/内联方案；当前 Vite 静态模块、Safari 下载和 CSP 兼容证据不足 | 可替换文件；已分发旧文件不能远程召回 | 可能新增插件和供应链，且跨浏览器行为当前为 `insufficient-data` |
| D. 独立静态服务器二进制或容器 | 可以只服务静态产物 | 仍需控制绑定、日志、缓存和本地网络 | 增加安装、签名、升级和跨平台依赖 | 可替换服务器与产物 | 对一次性研究原型增加不必要的运维和供应链面 |
| E. 服务端 Web、PWA、原生/桌面应用 | 可能支持未来账户、持久化或安装 | 会扩大敏感数据、存储、权限、备份和删除边界 | 最高 | 需要全新迁移和退出设计 | 直接超出 `PRD-0001`；本 ADR 不允许 |
| 不做/维持现状 | 不引入新风险 | 没有原型、没有参与者数据 | 0 | 无 | 阻塞三项 ADR 与后续 `Implementation Authorized` |

### 4.2 前端技术栈候选

| 方案 | 满足驱动因素 | 用户/数据影响 | 复杂度/成本 | 兼容/迁移/回滚 | 风险 |
| --- | --- | --- | --- | --- | --- |
| A. **React + TypeScript + Vite（推荐）** | React 的声明式组件和状态模型适合多步骤表单、局部状态失效和可测试 UI；Vite 输出可静态托管的产物 | 框架本身不要求后端或持久化；所有资源必须本地打包 | 比原生 DOM 多 React/React DOM 和插件依赖，但不需要 Router、状态库或 UI 库 | 领域与导出层保持纯 TypeScript，可替换 UI；静态产物整体回滚 | React 优势是工程判断而非已测事实；副作用或依赖误用仍可能造成外发/陈旧状态 |
| B. Vanilla TypeScript + Vite | 运行时框架依赖最少，直接使用语义 HTML/DOM | 容易审查静态产物和网络边界 | 需要自行维护渲染、焦点、错误关联、事件清理和组件约束 | 框架锁定最低 | 本 PRD 的复杂状态和无障碍路径可能形成较高的命令式维护风险 |
| C. Svelte + TypeScript + Vite | 编译器生成浏览器代码，并提供部分编译期无障碍提示 | 不要求应用后端；可输出静态资源 | 增加 Svelte 编译器、Vite 插件和框架语义 | 领域层可迁移，UI 需要重写 | 当前没有维护熟悉度、包体或可访问性实测证据；编译警告不能替代人工验收 |
| D. React 元框架或全栈框架 | 可提供路由、SSR 和服务端能力 | 容易引入服务器执行、预取、远程请求或更复杂缓存 | 明显超过本期需要 | 正式产品可能复用，但当前迁移收益未经验证 | 为未来假设提前扩大边界，拒绝 |
| 不做/维持现状 | 无依赖 | 无原型 | 0 | 无 | 不能执行已批准研究计划 |

### 4.3 当前外部证据

- Vite 官方说明生产构建以 `index.html` 为入口并输出适合静态托管的 bundle；`base` 可以使用相对路径；`vite preview` 只用于本地预览，不应当作生产服务器。
- React 官方说明 `createRoot` 可把完整客户端应用挂载到浏览器 DOM；这不要求服务端渲染。
- Vite 只转译 TypeScript，不执行完整类型检查，因此技术栈必须单独运行 `tsc --noEmit`。
- Playwright 官方明确说明自动化无障碍检查只能发现部分问题，不能替代键盘和辅助技术人工验收。
- GitHub Pages 官方明确说明访问 Pages 站点时会记录访客 IP；Cloudflare 和 Netlify 的公开文档也没有提供满足本 PRD 的逐项目 7 天删除 readback 证明。因此本 ADR 不能把任一云托管商写成已通过。

上述资料已在 `2026-08-21` 批准 readback 中重新核验，只支持技术可行性、版本兼容性和当前风险判断，不是本原型已经通过构建、隐私、可访问性或性能验证的证据；首次实现前及后续复审时必须再次核验。

## 5. 决定

### 5.1 已批准选择（Accepted）

批准以下完整、不可拆分的选择：

1. **交付拓扑**
   - Vite 生成一个纯静态 `dist` 产物；不生成或部署 Functions、Workers、SSR、API、数据库、Service Worker 或 PWA manifest。
   - 研究者在受控设备上使用项目锁定版本的 `vite preview` 服务已构建的 `dist`。默认只绑定 loopback；只有跨设备或 iOS Safari 验收需要时，才显式绑定经过 readback 的研究者控制 LAN 地址。
   - LAN 会话不得使用公共、酒店、访客或无法说明日志/管理边界的网络。URL 不包含研究编号、参与者标识、购买内容、查询参数或其他敏感信息。
   - 该服务仅用于 `PRD-0001` 的受控形成性研究和验收，不是生产托管，不对公众长期开放。
   - 当前不选择云托管商。未来使用任何云托管、访问网关或远程分发服务，必须修订本 ADR 或创建新 ADR，并在启用前批准。

2. **浏览器运行时**
   - `react@19.2.8`、`react-dom@19.2.8`、编译后的项目代码和本地静态资源；React 与 React DOM 精确匹配，初始化时不得使用浮动版本。
   - 领域计算、证据状态、会话修订语义和导出序列化使用无 React 依赖的纯 TypeScript 模块。计算公式/数值口径和导出 schema 分别由后续具体 ADR 决定，本 ADR 不提前定义。
   - 应用状态只存在当前 JavaScript 内存；不引入 Router、外部状态库、UI 组件库、图标包、远程字体、远程脚本或运行时插件。
   - 样式使用项目本地 CSS 和系统字体；所有图像、图标和其他资源随构建产物自托管。

3. **构建与依赖**
   - 构建基线为 `Node.js 24.19.0` LTS（Krypton）及其官方捆绑的 `npm 11.17.0`。Node.js/npm 不进入浏览器运行时；Node.js 24 不再处于受支持 LTS 时触发复审。
   - 使用 TypeScript 严格类型检查、Vite 静态构建、`package-lock.json` 和 `npm ci`。直接依赖写明用途，传递依赖由 lockfile 固定。
   - 构建产物不包含源码、source map、真实/近似个人数据、研究记录、开发日志或测试截图。
   - 禁止从 CDN、远程 ESM、动态脚本注入或运行时包管理器加载代码。任何新增运行时依赖都必须审查数据流、网络能力、安装脚本、许可证、维护状态和安全通告。

4. **测试栈**
   - `tsc --noEmit` 用于类型检查；Vitest 用于纯 TypeScript 规则和状态单元测试；React Testing Library 用于按用户可见语义测试组件。
   - Playwright 用于目标浏览器流程、网络捕获、浏览器存储、下载和失败路径；axe 只作为自动化无障碍检查的一部分。
   - 桌面键盘、macOS VoiceOver 和 iOS VoiceOver 必须人工验收；自动化结果不能代替人工结论。
   - 所有自动化和截图只使用 PRD 批准的合成 fixture，不加入真实收入、工时、购买或身份信息。

5. **浏览器侧安全默认值**
   - 静态响应必须采用能够阻止运行时外连、表单提交、嵌入和远程资源的 CSP/安全头；精确配置在实现任务中机械化，但不得放宽本 ADR 的零外发边界。
   - 不注册 Service Worker，不访问 Cookie、localStorage、sessionStorage、IndexedDB、Cache Storage、剪贴板或 URL 状态；不接入分析、错误上报、会话重放、第三方字体或外部模型。
   - 本地/LAN 静态服务不得持久保存访问日志。若工具、终端、操作系统或网络环境会产生包含 IP、User-Agent、访问时点或 URL 的持久记录，必须停止该交付方式，完成处置并重新评审。

### 5.2 为什么选择它

- 相比云静态托管，本地/LAN 交付避免在当前证据不足时把参与者 IP、User-Agent 和访问时点交给无法证明 7 天删除 readback 的第三方；它是 PRD 已批准的 fail-closed 路径。
- 相比 `file://` 单文件包，本方案复用 Vite 已定义的静态构建与预览路径，不为尚未验证的浏览器兼容额外引入单文件打包插件。
- 相比独立静态服务器，本方案不增加第二套服务依赖；`vite preview` 的“非生产服务器”限制通过严格限定为受控研究而被接受，而不是被忽略。
- 相比 Vanilla TypeScript，React 的声明式 UI 更适合本 PRD 的多步骤状态、局部失效和错误/焦点反馈；新增依赖面通过不采用 Router、状态库和组件库来约束。
- 相比 Svelte，React 的选择基于本次维护与测试风险判断，而不是未经证实的性能优势；实际包体、速度和无障碍质量继续标为 `insufficient-data`。
- 把领域、证据状态和导出逻辑保持为纯 TypeScript，使该研究原型不会自动成为正式产品架构，也保留替换 UI 框架的出口。

### 5.3 适用边界

本决策只适用于：

- `PRD-0001` 的单案例购买决策形成性研究原型；
- 无账户、无身份、无持久化、无同步、无应用后端的单浏览器会话；
- 研究者控制设备、loopback 或边界已核验的本地 LAN；
- PRD 指定的首轮浏览器、设备、键盘、VoiceOver 和合成性能验证。

本决策不适用于：

- 正式产品、公开生产部署、远程自助访问或长期托管；
- 账户、身份认证、服务端 API、数据库、持久化、同步、通知、多人协作、AI、文件导入、公开分享或真实用户遥测；
- 研究存储 A/B、正式同意系统、联系方式或研究观察采集；
- 计算精度、舍入、状态传播实现和导出 schema/MIME/命名的具体合同。

任何上述范围进入实施前，必须依据上位文档判断新 PRD、RFC、ADR 或本 ADR 修订；不得把本研究栈默认为正式产品栈。

## 6. 产品、数据与信任影响

### 6.1 数据状态与历史口径

- 本技术栈不能改变 `actual / user-confirmed / estimated / forecast / insufficient-data` 的产品语义，也不能把 UI 确认动作、React 状态或研究观察升级为产品财务 `actual`。
- 领域模块是数据状态、依赖关系和失效语义的唯一计算入口；React 只渲染显式结果，不在组件内复制或另行推断证据状态。
- 用户修改输入后，依赖结果必须立即失效并等待重新确认、重算；旧值只按后续 ADR 批准的最小会话修订合同保留在内存，不能继续参与当前结果。
- 当前没有跨会话历史、迁移或恢复。构建元数据只证明软件产物，不是产品数据状态，也不能证明用户结果正确。
- 计算/规则版本和导出格式版本由后续具体 ADR 固定；本 ADR 只要求构建能够携带并展示这些版本，不定义其值或 schema。

### 6.2 可解释性与用户操作

- React UI 必须从同一纯 TypeScript 结果对象读取值、来源、状态、单位、周期、依赖、规则版本、生成时点、假设、限制和 `insufficient-data` 原因。
- 简明观察不得切断“查看依据”、返回修改、重新确认、重算、退出和主动导出路径。
- 刷新、关闭或退出会丢失当前会话，界面必须在输入前说明；不得暗示存在自动保存、恢复、同步或服务端副本。
- 用户下载的 JSON/Markdown 文件进入用户设备后，原型不能召回、修改、删除或同步；技术栈不能用“回滚成功”掩盖已下载文件仍存在。
- 本地/LAN 交付不改变研究同意边界。原型内确认不能替代产品外正式研究同意和脱敏观察授权。

### 6.3 隐私与安全边界

允许的数据流只有：

```text
版本化静态资源 ──本地/LAN 读取──> 浏览器
                                      │
用户输入 ──> 当前页面内存 ──> 纯 TS 领域结果 ──> React 展示
                                      │
                                      └──用户明确确认──> 本地 JSON/Markdown 下载

禁止：浏览器/应用后端、第三方、遥测、研究记录 <── 任何原始输入或派生结果
```

- 静态服务器只允许提供已验证构建中的 HTML、CSS、JavaScript 和本地资源；不接收表单、事件、导出内容或产品数据。
- 默认绑定 loopback。LAN 模式仅在研究者控制设备和网络上按会话启用；端口、接口、进程、终端输出和网络环境在会话前后 readback。
- 研究会话不得使用公共或无法说明监控、代理、DNS 注入、流量记录和设备管理边界的网络。加载完成后不需要互联网连接；任何意外外部请求都视为关键隐私/信任事件。
- CSP 至少应实现 `default-src 'self'`、`connect-src 'none'`、`form-action 'none'`、禁止对象和外部嵌入，并限制脚本、样式、图像和字体为随构建提供的必要来源；最终头部需要在目标浏览器实测。
- 禁止把敏感值放入 URL、DOM 调试属性、错误消息、console、终端输出、截图、source map、构建日志或自动测试报告。
- 构建阶段可以联网取得已批准并锁定的依赖，但构建环境不得包含参与者数据；正式研究构建完成后必须能以断网方式运行和验收。
- 产品外研究存储 A/B、联系方式、正式同意和封闭字段观察不进入本应用、构建产物或技术栈。

## 7. 后果

### 正面后果

- 在云托管边界无法证明时采用 fail-closed 的本地交付，不把便利优先于隐私契约。
- 单一静态产物可在 macOS、Windows 和 iOS Safari 目标路径复用，并能关联完整构建证据。
- React 负责声明式 UI，领域与导出语义保持纯 TypeScript，降低陈旧 UI 和框架锁定同时发生的风险。
- 不引入 Router、状态库、UI 库、远程字体或运行时服务，缩小依赖、网络和可审查范围。
- 无持久化产品数据，停止、替换和首次回滚路径明确。

### 负面后果与接受的取舍

- `vite preview` 不是生产服务器；本决定因此不能直接扩展为正式发布或远程长期访问。
- 研究者必须控制设备、网络、绑定地址、进程和构建版本，本地/LAN 会话的操作负担高于发送公网 URL。
- React 与相关测试工具增加构建依赖和供应链面；当前没有包体、性能或维护优势的实测证据。
- 没有持久化、恢复或远程停止机制；页面已经加载后，停止静态服务器不能清除浏览器内存，必须让参与者关闭/刷新页面。
- 已下载文件和已复制的本地静态产物不能远程召回，回滚只影响后续会话。
- 自动化无障碍检查不能证明 VoiceOver 和真实理解质量，必须保留人工验收成本。

## 8. 迁移、兼容与回滚

### 8.1 迁移/回填

无。当前仓库没有应用、用户数据、构建产物、客户端或历史规则需要迁移/回填。本 ADR 不授权创建产品数据迁移、研究数据存储或兼容层。

如果后续实现意外产生任何产品数据副本，不得把它当作迁移输入；应立即暂停、定位、删除并验证不可恢复，按关键隐私/信任事件处理。

### 8.2 兼容策略

- 首轮正式支持范围沿用 PRD：验收时当前稳定版桌面 Chrome（macOS/Windows）、macOS Safari 和 iOS Safari；桌面键盘及 macOS/iOS VoiceOver。Firefox、Android 和 NVDA 不在首轮承诺内。
- Vite `build.target` 必须以记录下来的目标浏览器版本为依据；不得为了未经批准的旧浏览器范围默认加入远程 polyfill 或 legacy 插件。
- 本地静态产物、依赖锁、Node/npm、配置和构建摘要作为一个不可拆分的研究版本；不能只替换单个 JavaScript 文件。
- 当前没有旧数据、旧客户端、导入或外部连接。用户下载文件的兼容合同由导出 ADR 决定，本 ADR 不提前承诺。
- 正式产品若采用不同技术栈，应迁移纯 TypeScript 领域合同并重新验证 UI；不得把 React 原型兼容性视为正式产品承诺。

### 8.3 回滚与恢复

1. **首次构建或首次研究会话**：立即停止 `vite preview`、关闭绑定端口、撤下构建入口，并要求已打开页面的参与者关闭或刷新；不存在可恢复的产品数据。
2. **后续构建**：恢复到上一份整体已验证的 Git commit、静态产物、产物摘要、依赖锁、Node/npm、构建配置、规则版本和导出版本；完成版本、网络、存储和关键 AC readback 后才能重新开放。
3. **配置或供应链问题**：同时回滚配置、锁文件和产物，不能只替换页面文件；发现依赖或构建环境被污染时重新从受信环境构建并比较摘要。
4. **隐私/状态/导出错误**：立即停止全部分发和导出；定位并删除意外副本；修复后重跑相关原型验收和独立挑战。代码回滚不能修复或召回用户已经下载的文件。
5. **LAN 暴露或日志异常**：停止服务、断开研究网络、检查进程/端口/终端/日志位置和受影响范围；无法证明处置完成时保持暂停。
6. **责任与证据**：Alune 是停止、恢复和风险接受 DRI。恢复记录只使用合成数据、版本和非敏感技术证据，不包含参与者输入或研究记录。
