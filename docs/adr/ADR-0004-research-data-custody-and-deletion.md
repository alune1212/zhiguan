## 1. 决策摘要

本 ADR 只固定 `RESEARCH-0001` 存储 A/B 的保管与删除边界，不扩张到正式产品持久化、原型分发、托管日志或独立挑战者治理存储。当前已确认：不建立恢复副本；A/B 使用两个独立的 `ASIF`、APFS、AES-256 加密磁盘映像和不同密码；各自保存一份由 `/usr/bin/sqlite3` 管理的独立 SQLite 数据库；镜像放在已确定的本机非同步目录；密码只作离线纸质保管；操作权限仅授予 `alune`；SQLite 使用最小临时文件、单写事务和不跨库附加的运行合同；挂载、同步/备份 fail-closed、证据保存、撤回、到期、暂停/终止、整体销毁和最终声明边界均已固定。操作载体、最小合成演练、条件缺失语义、信任事件集合、重识别口径和批准顺序也已确定；准确 DDL、命令和决策 readback 已形成并完成非持久化验证。Alune 于 `2026-09-01` 接受本 ADR；实际路径、同步/备份和删除仍待另行授权的合成演练证明，本次接受不构成演练、AC-18、研究协议或招募授权。

## 2. 背景与问题

`RESEARCH-0001` 要求 A 只保存联系方式、同意/撤回状态及随机研究编号映射，B 只保存随机研究编号和封闭字段观察；两者必须独立加密、仅 Alune 访问、无默认同步/备份，并能完成撤回、到期与研究停止删除 readback。现有 ADR-0001 明确排除研究存储 A/B，ADR-0003 也不覆盖研究数据加密容器。

仓库规则把持久化、访问控制、加密、密钥、备份、删除和保留列为启用前的 ADR 门禁。该选择一旦承载逐人研究记录，迁移会产生副本和删除义务；A/B 隔离、无恢复副本与可用性之间也存在真实取舍，因此需要单独 ADR，不需要改变产品边界的 RFC。

当前事实状态：

- `actual`：`RESEARCH-0001` 仍为 `Draft`，AC-18 未通过，`Recruitment Authorized=false`；本机只读盘点显示 FileVault 已开启，当前没有 Time Machine 目的地或 Data 卷快照，macOS 原生磁盘映像工具与 `/usr/bin/sqlite3` 可用；管理员组除系统 `root` 外只有 `alune`，SMB、SSH 和屏幕共享服务均已禁用；runbook 的 A/B DDL 已通过 SQLite `:memory:` 语法、合法 fixture、五类跨字段非法写入拒绝、级联与三段删除断言检查，但这不是实际路径或删除证明。
- `user-confirmed`：Alune 于 `2026-08-31` 接受本 ADR 的窄范围、无恢复副本、A/B 独立加密域、本机准确根目录、离线纸质密码保管和“仅 Alune 访问”的操作定义；于 `2026-09-01` 接受 `ASIF` 镜像、密码生成/输入/销毁、SQLite 随机研究编号、最小三表结构、SQLite 运行合同、跨库 ID 交接、AC-18/AC-19 字段边界、私有 CLI 挂载、同步/备份 fail-closed、脱敏证据、撤回与到期删除、暂停/终止、整体销毁、最终声明、Markdown runbook、三条合成 fixture、条件缺失与阶段顺序、信任事件集合、A 合成 DDL 边界、重识别口径和分层批准顺序。
- `insufficient-data`：尚未创建 A/B，尚无实际路径、权限、加密、同步/备份或删除演练证据。

## 3. 决策驱动因素

- [x] 产品任务与价值循环对齐：仅支持产品外 `Review` / `Learn` 形成性研究，不新增产品能力。
- [x] 隐私与数据主权：联系人映射与观察字段分离，逐人数据最小化且可撤回、到期删除。
- [x] 可解释性与用户控制：保留、删除触发和 readback 必须可说明，不能把逻辑删除表述为法证擦除。
- [x] 历史口径与可重现性：研究字段和缺失语义遵循协议固定的封闭 schema。
- [x] 可迁移、可导出与退出：不为研究者建立导出或恢复副本；边界失效时暂停研究并删除适用数据。
- [x] 安全边界与最小权限：A/B 使用独立加密域和不同密码，仅在需要时解锁。
- [x] 可靠性、可运维性或成本：优先复用本机原生能力，不为小规模形成性研究引入新依赖或云服务。

## 4. 已确认决策

### 4.1 适用范围

本 ADR 只覆盖：

- 存储 A：联系方式、同意/撤回状态、回访安排和随机研究编号映射；
- 存储 B：随机研究编号和 `RESEARCH-0001` 第 6 节允许的封闭字段观察；
- 两者的工具、位置、权限、密钥、同步/备份、保留、删除和 readback。

不覆盖正式产品数据存储、原型导出文件、原型分发与托管访问日志、独立挑战者完整记录或任何原话、录音、录像、截屏。进入这些范围必须重新判断 PRD/RFC/ADR。

### 4.2 无恢复副本

A/B 不建立云端、Time Machine、外置介质或其他人工恢复副本。容器损坏、密码丢失、边界无法证明或数据不可读时，不从猜测、旧文件或其他来源重建逐人记录；立即暂停研究并按关键隐私/信任事件处理。接受的取舍是可用性降低，以减少副本、访问和删除面。

### 4.3 A/B 独立加密域

A/B 必须使用两个独立加密容器、两个不同密码和两份独立 SQLite 数据库。不得把两者放在同一加密卷、同一数据库、同一文件的不同表或同一工作簿的不同工作表中。随机研究编号是唯一允许的跨库关联键；B 不得包含可读身份线索。

工具栈固定为 macOS 原生 `diskutil image` 和本机 `/usr/bin/sqlite3`；不安装第三方加密、密码库、表格或数据库工具。

### 4.4 实际位置与无默认同步/备份

A/B 的根目录固定为 `/Users/alune/Library/Application Support/Zhiguan Research/RESEARCH-0001/`。该目录不得迁入仓库、iCloud Drive、Desktop、Documents、`~/Library/CloudStorage`、共享目录或其他同步根。

创建时为根目录设置持久 Time Machine 排除。每次解锁前后必须 readback：Time Machine 无目的地、Data 卷无快照、根目录仍被排除且不位于已知 File Provider 同步根。仅有排除标记不构成无本地快照证明；任一检查失败即暂停，不解锁或继续写入 A/B。

### 4.5 密码保管

A/B 使用不同的高熵密码。Alune 在不保存日志的 Terminal 窗口中分别运行 `openssl rand -base64 24`，直接把输出抄写到两张独立密封纸条，随后清除滚动缓冲并关闭窗口。仓库和 readback 只记录“离线纸质保管已验证”，不记录密码或具体物理位置。

创建与挂载镜像时使用 `diskutil image` 的隐藏交互提示；不把密码交给 Codex，也不放入 argv、环境变量、Keychain、密码管理器、文件、终端历史或剪贴板。最终容器删除 readback 通过后，由 Alune 物理销毁对应纸条并只记录完成日期和结果。

### 4.6 仅 Alune 访问

根目录权限为 `0700`，镜像和数据库文件为 `0600`，所有者为 `alune`，不得存在授予其他主体的 ACL。A/B 只在操作期间挂载，完成后立即卸载；SMB、SSH 和屏幕共享必须保持禁用。新增非系统管理员、启用远程服务或任一权限 readback 失败时暂停研究。

该边界不声称抵御系统 `root`、恶意软件或已被控制的解锁会话；这些是明确接受的残余风险。若未来要求抵御这些风险，改用专用离线设备并重新评审本 ADR。

### 4.7 镜像格式与容量

A/B 各使用一个单文件 `ASIF` 稀疏镜像，逻辑上限 `1 GiB`，内部文件系统为 APFS，加密为 AES-256。物理占用随实际数据增长；不得改用实际占满容量的 `RAW` 或产生多个 band 文件的 `UDSB`。镜像创建、挂载、检查和卸载只使用当前 macOS 的 `diskutil image`。

### 4.8 研究编号与最小 schema

研究编号由 SQLite 使用 `lower(hex(randomblob(16)))` 生成，固定为 32 位小写十六进制文本并以 `CHECK` 约束；主键冲突时整笔事务回滚并重试。研究编号只作 A/B 关联键，不作为认证秘密。

A 只有一张 `STRICT participant` 当前状态表，保存联系方式、材料版本、研究同意与观察授权状态及时间、撤回状态、回访安排和保留截止日。runbook 中的 A DDL 只用于 AC-18 合成演练；真实状态含义、联系渠道和撤回确认由 AC-19 决定，变更后必须重跑隔离与删除 readback。

B 只有一张 `STRICT observation` 表及一张保存多个有限事件代码的 `trust_event` 子表。阶段必须按顺序到达；第三阶段未完成时解释检查按 `RESEARCH-0001` 第 6 节条件使用 `NULL`，第四阶段未完成时决定类别为 `NULL`，且 `undecided` 不得代替未到达。信任事件以集合表示：无子行为 `none`，独占的 `not-observed` 子行表示未可靠观察，其他子行只保存唯一代码；级别由协议推导，不重复存储。

两库均不得添加授权历史、备注、原因、多个联系方式或自由文本。

尚未到达回访时，B 的回访字段可暂时为 `NULL`；进入聚合前必须转为协议允许的封闭值，或由 `review_result_category=not-reached` 明确未到达。具体列名、类型、枚举和跨字段约束必须逐项映射 `RESEARCH-0001` 第 4～6 节，不得扩大其语义。

### 4.9 SQLite 运行合同

每次连接 A 或 B 后、执行任何业务读写前，必须设置并 readback：`foreign_keys=ON`、`journal_mode=DELETE`、`synchronous=EXTRA`、`secure_delete=ON`、`journal_size_limit=0`、`temp_store=MEMORY`。任一值不符即停止，不得继续读写。

每次写入或删除使用 `BEGIN IMMEDIATE` 开始单一事务；失败必须回滚并暂停处置。不得使用 WAL、`VACUUM INTO`、`ATTACH` 或其他会创建持久副本、共享数据库连接或额外 sidecar 的方式。逐人或批量删除成功提交后必须在对应数据库执行原地 `VACUUM`；准确删除顺序与 readback 在后续决策中固定。

### 4.10 A/B 挂载与研究编号交接

常规联系与同意操作只挂载 A，观察录入只挂载 B。只有建立 B 记录、撤回或到期/停止删除需要关联两库时，才允许在完成解锁前后检查后短暂同时挂载 A/B；完成后立即卸载两者。

跨库交接不得使用 `ATTACH`、第三个数据库、临时文件、剪贴板、日志、命令参数或环境变量。研究编号只允许在关闭 shell tracing 的本地进程内，经标准输入参数短暂传递，完成后立即清除。建立 B 记录失败时保留 A 映射并暂停；删除 B 或其 readback 失败时同样保留 A 映射，不得先移除唯一可定位关系或确认删除完成。

### 4.11 AC-18 与 AC-19 字段边界

A 只保存一个不区分渠道的当前 `contact_value`，不得增加联系方式类型、多个联系方式、历史值、备注或自由文本。AC-18 合成演练只使用 `case-001@example.invalid` 一类保留域占位值；这不选择或授权真实招募、联系、撤回或确认渠道。

真实联系渠道、撤回联系路径、参与者确认方式和正式同意语义由 AC-19 决定。B 的列、枚举和约束只按 `RESEARCH-0001` 第 6 节机械化，不需要新的产品含义；任何不能映射到协议封闭字段的需要均先修订协议。

### 4.12 挂载、索引与系统残留

A/B 固定挂载到根目录下的 `.mount-a` 与 `.mount-b`；底层挂载目录和挂载后卷根均为 `0700`。使用显式挂载点和 no-browse 模式，只允许通过本地 CLI 与 `/usr/bin/sqlite3` 操作。写入任何记录前，卷内设置 `.metadata_never_index`，并 readback Spotlight 索引为禁用。

不得用 Finder、Quick Look、预览、表格或文本编辑器打开卷或数据库，不得经过 Trash。挂载期间必须有人值守；卸载前确认没有打开句柄，卸载后确认挂载点为空且卷不再挂载。

本合同不声称能法证清除 RAM、位于 FileVault 保护系统卷上的 swap 或系统缓存，只禁止研究流程主动创建这些边界之外的副本。若必须抵御该残余风险，应暂停并改用经重新评审的专用离线设备。

### 4.13 同步与备份 fail-closed

创建时、每次解锁前和每次卸载后都必须完成同一组 readback：根目录规范化真实路径不经过 symlink；A/B 所有者、mode 和 ACL 符合本 ADR；Time Machine 无目的地且未运行、根目录明确被排除；`tmutil` 与 `diskutil apfs` 均显示 Data 卷无相关本地快照；全部 File Provider、同步和备份配置可枚举，且没有规则覆盖根目录或更宽的 Home 范围。

任一命令不可用、排除结果为 `UNKNOWN`、枚举不完整，或出现作用域可能覆盖根目录的未知代理时，均不得创建、解锁或写入 A/B，并按关键隐私/信任事件暂停。连接但作用域明确不覆盖根目录的 provider 不单独构成失败。当前根目录尚不存在，Time Machine 排除为 `UNKNOWN`，File Provider/代理枚举也尚未完整，因此该证明仍为 `insufficient-data`。

### 4.14 AC-18 脱敏证据

后续合成演练在 `evidence/research/` 保存带日期的 AC-18 Markdown readback。证据只包含工具和格式版本、无秘密的检查命令、脱敏后的状态、合成记录数量、删除数量、结果、限制和明确的“仅合成数据”声明；不得包含密码、研究编号、联系方式、数据库页、设备序列号或完整原始终端 transcript。

### 4.15 单记录撤回删除

AC-19 定义的撤回路径触发删除后，立即停止未来联系；从 A 取得研究编号后只在进程内保留，并在内存中取得受影响聚合的旧分母。先删除 B 的目标 `observation`，由外键级联删除其 `trust_event`，提交后执行 `VACUUM` 和 B readback；再用剩余 B 记录重算适用聚合并记录不含研究编号的新旧分母；最后删除 A 的目标记录，提交后执行 `VACUUM` 和 A readback，再卸载两卷。

任一步失败即暂停，保留尚存 A 映射且不得宣称删除完成。匿名的新旧分母只写入适用的聚合结果；持久操作摘要只允许保存触发类型、完成日期、受影响数量和结果，不得保存研究编号、联系方式或逐人内容。参与者确认渠道仍由 AC-19 决定。

### 4.16 到期批量删除

同一参与者在 A 的“最后一次计划回访后 30 天”和 B 的“实验最终结论形成后 30 天”中，以较早的适用截止日作为 A/B 成对清理日。删除前冻结写入，只在进程内形成到期研究编号集合；先在一个 `BEGIN IMMEDIATE` 事务中批量删除 B 的到期 `observation` 并级联其 `trust_event`，提交、`VACUUM` 和 readback 后，再以同样方式删除 A 的对应记录并 readback。

正常到期不改变已经通过非识别化复核的最终聚合，也不把按期删除误记为撤回或流失。最终聚合若不能安全形成，则删除相关结果或标为 `insufficient-data`，仍不得延长逐人数据期限。截止日缺失、冲突或无法证明时暂停，不用默认日期猜测。

### 4.17 暂停与终止

权限、同步/备份、快照、删除或其他边界证明失败时进入 `pause`：立即停止写入并卸载 A/B，不创建恢复副本；暂停不延长既有删除期限。事件处置只使用协议允许的事件代码、版本、数据类别和非识别化数量。

只有 Alune 明确终止研究，或边界无法恢复而必须终止时，才执行终止流程：冻结已经安全的不可识别聚合；不能安全形成结论时删除相关结果或标为 `insufficient-data`；随后立即执行 B→A 成对删除与容器销毁，不等待正常保留期限。

### 4.18 容器整体销毁

只有研究终止，或 A/B 均为空且不再授权继续采集时，才整体销毁容器。先确认数据库已关闭、无打开句柄，且根目录内容严格符合已批准 allowlist；再依次卸载 B、A，并以两个明确的绝对路径直接删除 B、A `ASIF`，不得经过 Trash、使用 glob 或递归删除。最后只删除已确认为空的挂载点和根目录。

出现未知文件或目标不匹配时立即暂停，不用广泛删除掩盖意外副本。两个镜像和限定边界的 postflight 全部通过后，才由 Alune 销毁两张密码纸；任一步失败均记为 `not-proven`，不得重建数据或宣称整体销毁完成。

### 4.19 持久结果与最终声明

持久信息分为三类，不得合并为逐人操作日志：

- 不可识别聚合结果只保存协议允许的指标、宽分档、证据状态，以及撤回时匿名的新旧分母；
- 删除操作摘要只保存触发类型、完成日期、受影响数量和结果；
- AC-18 合成证据遵循第 4.14 节，不保存秘密或逐人值。

记录删除 readback 必须显示目标 `observation`、级联 `trust_event` 与 `participant` 行均为零，`integrity_check=ok`、`foreign_key_check` 无结果，不存在 `-wal`、`-shm`、`-journal` 或其他 SQLite 临时副本，并确认两卷已卸载。整体销毁还必须显示两个镜像、挂载点、根目录和已知 Trash 匹配项均不存在，并再次通过同步、备份和快照 postflight。

满足这些条件时，只能声明：“在指定 macOS 主机、指定时间、已枚举的 A/B 容器路径及已检查的 SQLite、快照、同步与 Trash 边界内，逻辑删除已验证。”不得声明 SSD 法证擦除，也不覆盖 RAM、swap、系统缓存、系统 `root`、恶意软件、未知代理或未枚举副本。

### 4.20 操作载体

准确命令、DDL、合成 fixture、失败停止点和 readback 只写入一个版本化、不可执行的 Markdown [`AC-18 runbook`](../research/RESEARCH-0001-storage-runbook.md)。Alune 在关闭历史记录和 tracing 的本地 Terminal 中逐段执行经审查的命令；runbook 不包含密码、实际研究编号或逐人值。除该 runbook 与第 4.14 节的脱敏证据外，不新增脚本、应用封装、依赖或第二份操作文档。

### 4.21 最小合成演练

同一轮隔离演练只建立三条合成记录：一条 completed 且含非关键 `input-burden-friction` 的撤回目标；一条使用协议 `not-reached` 语义的到期目标；一条正常控制记录，在前两次删除中保持存在，最后由研究终止流程删除。联系方式只使用 `.invalid` 保留域，研究编号只在运行时生成。

演练还执行至少一次应被数据库约束拒绝并完整回滚的无效写入。依次验证撤回、到期、研究终止和容器销毁；结束后不保留 fixture、研究编号、完整 transcript 或 A/B 容器。

### 4.22 重识别风险口径

B 在 A 仍存在时只是 pseudonymized，不是 anonymous；随机研究编号、A/B 分离和静态加密都不改变这一分类，也不能在删除 A 后追溯性地把原 B 描述为匿名。复核必须逐项检查 B 的字段及组合能否透露身份线索、精确时点、原始输入、价值期待、决定依据、自由文本或足以重建原始会话的模式，并记录不能消除的研究者记忆与小样本风险。

持久结果不得包含逐人行、双字段以上交叉切片、交叉表或能隔离单个案例的单元格，包括可定位的 `N=1`。只保留协议要求的顶层门禁指标；非门禁的小样本类别使用不增加识别风险的宽分档。无法证明安全时删除该输出或标为 `insufficient-data`。不得把该复核描述为数学匿名性或对 Alune、系统 `root`、恶意软件及外部知识的不可重识别保证。

### 4.23 批准与执行顺序

本 ADR、draft runbook、准确 DDL/命令和决策 readback 已完成设计审查；Alune 于 `2026-09-01` 单独明确把 `ADR-0004` 改为 `Accepted`。接受 ADR 只批准架构合同，不授权创建、挂载、写入或删除 A/B。

ADR 获批后，必须再次取得一次性本机合成演练授权，并先通过环境 preflight，才可执行第 4.21 节。schema 审查、合成演练与重识别风险复核全部通过并形成证据后，才能另行把 AC-18 标为通过。AC-18 通过不改变 `RESEARCH-0001` 的 `Draft` 状态；AC-19、分发/日志边界、AC-27、具体日历和其余协议前置全部完成后，才能另行决定协议是否 `Accepted`，最后才可能完成 `Recruitment Authorized` readback。
