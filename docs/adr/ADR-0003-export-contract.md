# ADR-0003：当前工作流的一次性 JSON 导出

| 项目 | 内容 |
| --- | --- |
| 状态 | Accepted；取代本 ADR 在 2026-08-24 记录的双格式原型合同；2026-09-01 起仅覆盖购买工作台 |
| 日期 | 2026-09-01 |
| 范围 | 单次购买决策工作台 |

## 背景

旧原型为 JSON、Markdown、预览、修订历史、构建清单和兼容校验建立了完整合同。当前产品没有导入器、持久化历史或需要消费这些格式的外部接口，这套机制增加了维护成本，却没有推进用户的购买决策任务。

## 决定

- 购买决策只保留用户主动触发的一次性 JSON 下载；不保留 Markdown、预览层、导入、修订历史、构建清单或兼容框架。
- 只有用户点击确认查看当前结果后才允许导出；输入随后改变时必须重新计算。
- 界面用一个“我填写的数字里有大概数”选择统一标记用户直接填写的数字证据；开启时这些字段为 `estimated`，关闭时为 `user-confirmed`。作息换算的月工时始终为 `estimated`，不受该选择影响。导出的 `inputs.evidence` 仍按每个数字字段保留内部结构。
- 导出保持 `format` `zhiguan-purchase-decision@1`、现有旧字段和五项结果含义不变；`inputs` 增加 `work_time_basis`，记录 `mode`、`days_per_week`、`hours_per_day` 和 `conversion`（公式、52 周、12 个月、3 位小数、half-up 及两条时间范围假设）。直接填写月工时或尚未选择作息时，原始作息字段与换算规则为空；无效作息原样保留且结果诚实降级。
- 购买文件包含当前输入及证据状态、五个计算结果及不足原因、用户决定和依据；界面隐藏与购买价格重复的“购买影响”，但导出继续保留它。当前页面不采集复盘条件，页面导出的兼容字段 `review_condition` 为 `null`；导出函数仍会序列化调用方传入的非空值。
- 金额等精确值继续使用字符串分子/分母表达，不使用会丢失精度的 JSON number。
- 页面只在内存中创建 `Blob` 和临时 object URL，不上传、不持久化，也不声称浏览器已成功保存文件。
- `format` 当前为 `zhiguan-purchase-decision@1`；旧文件不反推作息，没有导入器或已知消费者时不维护旧原型兼容层。

## 结果

导出仍满足用户主动带走当前购买数据的需要，并继续删除未被产品使用的双格式和版本治理。将来只有在出现真实外部消费者、导入需求或持久化历史时，才定义新版本、迁移和兼容策略。

## 修订与回滚

2026-09-01，用户确认 Goal 增加输入负担且未帮助购买任务，按 PRD-0002 回滚条件撤下 Goal 界面与 `zhiguan-goal-progress@1` 导出；购买格式不变，也没有既有 Goal 数据需要迁移。此前 Goal、双格式与单购买格式仍保留在 Git 历史中。
