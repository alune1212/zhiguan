## 1. 决策摘要

**已批准：**`PRD-0001` 的研究原型采用一个无 React、DOM、网络、存储、日志和系统时间隐式依赖的纯 TypeScript 计算内核。原始货币使用 ISO 4217 小数位转换成 `BigInt` 最小货币单位，工时与除法派生结果使用约分后的 `BigInt` 有理数；所有领域计算保持精确，只在最终展示边界按明确规则舍入，不用 JavaScript `Number` 承载金额、工时或派生财务值，也不新增 decimal 或规则引擎依赖。

同一会话只允许一个用户确认的比较周期和一个用户确认的 ISO 4217 币种，不跨周期换算、不换汇、不推断税费。规则内核统一负责公式、依赖、五类证据状态、失败原因、失效和规则版本；React 只能渲染结果。敏感输入、精确结果、修订事件和旧结果最小快照只存在当前浏览器内存，刷新、关闭或退出即清除。

本 ADR 已为 `Accepted`，但只满足 `PRD-0001` 三项架构前置决策中的第二项。导出 schema/格式仍由后续 ADR 决定；在三项 ADR 和 OpenSpec change 均获批准前，不构成 `Implementation Authorized`，仍不授权初始化框架、编写实现或向参与者分发原型。

## 2. 背景与问题

[`PRD-0001`](../product/prd/PRD-0001-single-purchase-decision-workbench.md) 已固定以下产品语义，本 ADR 不重新讨论：

- 用户选择周、月、年或自定义比较周期；收入、工时和固定成本使用同一周期，不要求精确起止日期，不自动分摊或跨周期换算；
- 每个会话只使用一种 ISO 4217 币种，不换汇；CNY 只能是界面建议，不能被静默确认为用户选择；
- Income Rate 与 Work-time Equivalent 可采用税前或税后收入并持续显示税口径；只有税后收入能进入覆盖范围内可用余量和购买影响；
- 原始金额和工时的空值、零、负数、非数值、非有限值或超限值均无效；派生余量可以为零或负数，不能被截为零或改写成错误；
- 产品财务输入只接受 `user-confirmed` 或 `estimated`，派生结果遵循 `insufficient-data > forecast > estimated > user-confirmed` 的保守传播；产品财务值不产生 `actual`；
- 用户修改已确认输入时，旧结果立即失效；重新确认后生成新结果，只在当前内存保留最小确认/修订事件，刷新、关闭或退出后全部清除。

[`ADR-0001`](ADR-0001-delivery-form-and-technology-stack.md) 已要求计算、证据状态和会话修订由纯 TypeScript 模块负责，并将浏览器运行时直接依赖限制为 React、React DOM 与项目代码。本 ADR 需要在不初始化框架、不编写实现的前提下，关闭 `PRD-0001` 第 11 节留下的计算架构问题：数值表示与限额、舍入、比较周期引用、时区来源、ISO 4217 口径、公式依赖、状态传播、规则版本、失败降级及本次会话修订语义。

## 3. 决策驱动因素

- [x] **产品任务与价值循环对齐：**只服务单案例购买决策的 `Capture → Normalize → Understand → Simulate → Decide`，不扩展为账本、税务、投资或财务建议系统。
- [x] **隐私与数据主权：**计算是无 I/O 的内存内纯函数；敏感值不进入 URL、网络、持久化、日志、遥测、异常文本或第三方。
- [x] **可解释性与用户控制：**每个结果可回溯到输入、公式、单位、币种、周期、税口径、状态、规则版本、生成时点、假设、限制和修正路径。
- [x] **历史口径与可重现性：**精确值不被展示舍入污染；规则、货币表、失效和修订事件均带不可变版本/来源。
- [x] **可迁移、可导出与退出：**领域合同不依赖 React；精确值可用十进制或分子/分母字符串交给后续导出 ADR；清空当前会话即可退出。
- [x] **安全边界与最小权限：**无新运行时依赖、无动态规则、无远程数据、无 `eval`、无隐式系统默认值；输入和中间值有明确资源限额。
- [x] **可靠性与局部降级：**字段失败只停止依赖结果，不复用旧值、不填默认值、不回退浮点、不把规则错误伪装成零。
- [x] **反焦虑与语义边界：**负余量保持有效且平静解释；计算只提供观察，不评分、不推荐购买、不把时间换算成人生价值。

## 4. 候选方案

### 4.1 数值表示

| 方案 | 满足驱动因素 | 用户/数据影响 | 复杂度/成本 | 兼容/迁移/回滚 | 风险 |
| --- | --- | --- | --- | --- | --- |
| A. **货币定点 `BigInt` + 派生 `BigInt` 有理数（推荐）** | 金额加减和除法结果均可精确重现；无新增依赖；展示前不舍入 | 不会因二进制浮点或中间舍入悄悄改变结果 | 需要自建受限解析、最大公约数、约分、舍入和错误合同 | 纯 TS、框架无关；可整体回滚规则版本；导出需字符串化 | 自建数值内核若缺少边界/性质测试会产生高影响错误 |
| B. JavaScript `Number` | 实现最短 | 小数与大整数可能产生不可见误差；不同计算次序可能影响边界舍入 | 最低 | 迁移到精确类型时需重验全部结果 | 不满足精确、可解释和可重现要求，拒绝 |
| C. 只用最小货币单位整数 | 金额加减精确 | Income Rate 和 Work-time Equivalent 的除法会截断或迫使提前舍入 | 低至中 | 仍需补充另一种除法表示 | 不能完整表达本期公式，单独采用时拒绝 |
| D. 第三方 decimal 库 | 可获得成熟十进制 API | 结果仍需自行固定精度、舍入和序列化语义 | 中；新增依赖、许可证与供应链审查 | 需要先修订 `ADR-0001` 的直接依赖边界 | 当前需求可用原生能力满足，不接受新增依赖 |
| 不做/留给组件自行计算 | 无初始领域模块 | 不同页面可能展示不同数值和状态 | 表面最低、长期最高 | 无统一回滚单元 | 直接违反 `ADR-0001`，拒绝 |

### 4.4 展示舍入

| 方案 | 可重现性 | 用户理解 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| A. **最终展示时统一 `half-away-from-zero`（推荐）** | 规则简单、正负对称、可用整数余数实现 | 常见“四舍五入”预期；可在依据中写明 | 与财务系统常见 half-even 可能不同，必须显示规则 | 选择 |

| D. 截断 | 简单 | 系统性偏向零 | 会把非零小值显示为零 | 拒绝 |

### 4.5 当前外部证据

- [ECMA-262](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-number-type) 将 JavaScript `Number` 定义为 IEEE 754 binary64；[BigInt](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-bigint-type) 可表达任意精度整数，但整数除法会截断。因此推荐保留分子/分母，而不是直接做 BigInt 除法。
- [ISO 4217](https://www.iso.org/iso-4217-currency-codes.html) 定义货币代码，SIX 是其官方维护机构。本决定固定 [SIX List One XML](https://www.six-group.com/dam/download/financial-information/data-center/iso-currrency/lists/list-one.xml) 的构建内快照：文件声明发布日 `2026-01-01`，于 `2026-08-21` 读取，大小 `47,463` bytes，SHA-256 为 `838dfb991648cf36df939edd5fe3811737962b75a32252847d239cedd1e291c9`；其中有效小数位为 `0 / 2 / 3 / 4`，`N.A.` 不构成可计算精度。
- [IANA Time Zone Database](https://www.iana.org/time-zones) 提供可版本化的时区标识与规则；本期只保存 IANA 标识帮助解释生成/确认时点，不用时区推导比较周期。

这些资料只证明规范性质和本决定已固定的快照，不证明原型实现、跨浏览器行为、计算正确性或用户理解已经通过。

## 5. 决定

### 5.1 已批准选择（Accepted）

以下内容作为一个不可拆分的规则合同获批；实现不得只选择其中便利的部分。

#### 5.1.1 纯函数与边界

- 计算内核是无 React、DOM、网络、浏览器存储、文件、console、locale、随机数和隐式系统时钟依赖的纯 TypeScript 模块。
- 所有时点、时区、周期、币种表和规则版本由调用方作为显式、不可变输入传入；同一输入和规则版本必须产生相同领域结果。
- 金额、工时、速率、余量和派生值的领域运算禁止使用 `Number`、`parseFloat`、`NaN`、`Infinity` 或 Number/BigInt 混算。`Intl.NumberFormat` 只能格式化内核已经生成的展示十进制字符串，不能决定领域精度或舍入。
- 内核不抛出带输入值或堆栈的用户可见错误；预期失败返回稳定原因码。意外异常在边界转换为 `rule-execution-failed`，相关当前结果为 `insufficient-data` 且值为 `null`，不得回退到旧结果、零值或浮点计算。

#### 5.1.2 规范化数值表示与限额

原始字段在任何 `trim`、正则或 BigInt 构造前先检查长度，最多 64 个 UTF-16 code units；超限直接返回 `numeric-limit-exceeded`。通过原始长度门禁后才去除两端空白，先识别正负号以返回具体原因，再只接受 ASCII 十进制语法 `(?:0|[1-9][0-9]*)(?:\.[0-9]+)?`。不接受正号、负数、指数、分组分隔符、全角数字或隐式 locale 解析。规范化和资源边界如下：

| 类型 | 规范化与范围 | 内部精确表示 | 无效行为 |
| --- | --- | --- | --- |
| 收入、购买价格、固定成本汇总 | 正数；整数部分最多 15 位；小数位不超过所选货币的 ISO minor unit；输入 token 最多 32 个字符 | `{ currencyCode, minorUnit, minorUnits: bigint }`；规范十进制补齐 minor unit | 空、零、负数、超限、多余小数、未知/不支持币种均只停止依赖结果 |
| 工作小时 | 正数；整数部分最多 6 位、小数最多 3 位，即最大 `999999.999` 小时；token 最多 16 个字符 | 约分的 `{ numerator: bigint, denominator: bigint, unit: "hour" }` | 空、零、负数、非法或超限只停止依赖结果；不默认工时 |
| 派生有理数 | 分母必须大于零；每次约分后分子、分母各不超过 128 个十进制数字 | 规范化为分母为正、最大公约数为 1；零只表示为 `0/1` | 超限或除零返回稳定失败，不截断、不回退 |

补充规则：

- 原始金额/工时的零值无效，严格继承 AC-05；派生余量的零值和负值有效。
- 货币表只接受上述固定 SIX 快照中同时具有大写 ASCII 三字母代码 `[A-Z]{3}` 和整数 minor unit `0 / 2 / 3 / 4` 的条目；`N.A.`、缺失、重复代码精度冲突或未知代码均 fail-closed。
- 构建期从固定快照生成去重映射；同一代码的重复国家条目必须给出一致 minor unit，否则构建验证失败。运行时不访问 ISO、SIX、locale 或任何远程服务。
- 该快照的不可变标识为 `iso4217-list-one@2026-01-01#sha256:838dfb991648cf36df939edd5fe3811737962b75a32252847d239cedd1e291c9`。会话货币上下文和每个金额输入/结果都保存这个 `currencyTableSnapshotId`；完整来源 URL、发布日、读取日、bytes 与 SHA-256 作为同一构建元数据可读，不用“当前 ISO 表”代替版本。
- CNY 可排在选择列表前部，但在用户明确确认前，币种上下文保持未确认，依赖结果为 `insufficient-data`。
- 用户改变币种时，所有金额输入和依赖结果立即失效并等待以新币种重新录入/确认；不得保留同一数值、换汇或只替换币种代码。展示可附加本地货币符号，但 ISO 三字母代码必须始终可见。
- BigInt 和有理数不能作为裸 JSON number 或裸 BigInt 进入导出；精确序列化使用十进制字符串或分子/分母字符串，具体字段由导出 ADR 固定。

#### 5.1.3 比较周期、时间单位与时区

- 会话比较周期为 `{ kind: week | month | year | custom, customLabel, revision }`。`customLabel` 只描述用户自己的周期名称，不收集精确起止日期或持续天数。
- 每个收入、工时、固定成本和购买周期归属都显式引用当前 `revision`；只有引用完全相同才可共同计算。相同文字但不同修订不视为同一已确认周期。
- 用户改变周期时创建新的内存内修订号，立即使所有相关确认和结果失效；不得自动复用、分摊或转换旧值。重新确认前，当前依赖结果为 `insufficient-data`，原因是 `input-reconfirmation-required` 或 `period-mismatch`。
- 计算时间单位固定为 `hour`。本期不换算为工作日、自然日或默认每日工时，也不采集日历天数。
确认、修订和结果使用完整、显式的时间上下文；字段不得合并或从展示字符串反推：

| 字段 | 合同 |
| --- | --- |
| `occurredAtUtc` | 调用方提供的 UTC ISO 8601 instant，表示确认、修订或结果生成动作发生的设备时点 |
| `recordedAtUtc` | 调用方提供的 UTC ISO 8601 instant，表示该动作写入当前内存状态的设备时点；即使通常与 occurred 相同也单独保存 |
| `clockSource` | 固定为 `device-clock`；不得宣称网络或权威时间 |
| `timeZoneId` | 用户选择或浏览器观察到的 IANA 标识；无法取得时为 `Etc/UTC` |
| `utcOffset` | 动作发生时的显式 `±HH:MM`；UTC fallback 为 `+00:00` |
| `timeZoneSource` | `browser-observed | user-selected | utc-fallback` |
| `timeZoneConfirmation` | `observed | user-confirmed | unconfirmed`；fallback 为 `unconfirmed` |

- 浏览器观察到的 IANA 时区可以作为可见建议，用户可以接受或修改；取不到有效标识时使用 UTC 并明确标为 fallback。时区不参与本期公式，因此未确认时区不阻断数值结果，但必须在“查看依据”中展示来源/警告。
- 改变时区不重写旧事件的时点，也不改变精确数值；新结果使用新时区元数据。
- 财务输入的发生范围由用户确认的 `periodRef` 表达，确认时点是记录/确认时间；本期不采集虚假的精确交易发生时点。系统修订事件分别保留设备来源的发生时点与记录时点，即使两者在当前原型中通常相同也不合并字段。

#### 5.1.4 精确公式与依赖

设收入最小货币单位为 `I`，购买价格为 `P`，完整固定成本汇总为 `F`，货币小数位因子为 `S = 10^minorUnit`，工时有理数为 `Hn/Hd`。所有公式先检查依赖可用性，再做精确整数/有理数运算：

| 公式 ID | 精确公式 | 必要依赖与边界 | 当前结果状态 |
| --- | --- | --- | --- |
| `income-rate` | `(I × Hd) / (S × Hn)` 主货币单位/小时 | 收入、工时、同一周期/币种、税口径已声明；税前或税后均可 | 非未来；按输入传播 `user-confirmed` 或 `estimated` |
| `work-time-equivalent` | `(P × Hn) / (I × Hd)` 小时 | `income-rate` 的原始依赖 + 购买价格；必须直接使用原始精确输入，不能复用已舍入 Income Rate | 非未来；按依赖传播 `user-confirmed` 或 `estimated` |
| `coverage-available-margin` | `I - F` 最小货币单位 | 税后收入；固定成本汇总有效、覆盖为完整且有非空覆盖说明；同一周期/币种 | 非未来；按依赖传播 `user-confirmed` 或 `estimated` |
| `purchase-after-margin` | `(I - F) - P` 最小货币单位 | 安全可用的 baseline + 用户确认购买计入当前周期 | 未来情景，固定为 `forecast` 并列出全部 estimated 依赖 |
| `purchase-impact` | `purchase-after-margin - coverage-available-margin = -P` | 只有 baseline 与 purchase-after 均安全可用时生成 | 未来情景，固定为 `forecast` |

- 税前收入路径仍可生成前两项并持续标明 `before-tax`；后三项为 `insufficient-data`，原因 `tax-basis-not-after-tax`。
- 固定成本缺失、部分、未知或“完整但无覆盖说明”不影响前两项，只停止后三项。
- 用户未确认购买计入当前周期时，Work-time Equivalent 仍可生成；`purchase-after-margin` 与 `purchase-impact` 停止。
- 派生余量为零或负数时仍是有效精确结果；界面用“在已确认覆盖范围内为零/低于零”平静说明，不截断、不羞辱、不把它扩张解释为净资产或支付能力。

#### 5.1.5 证据状态、可用性与失败原因

工作流可用性和产品证据状态分开建模；`pending-reconfirmation`、`stale`、`invalid-input` 不是第六种证据状态。每个当前结果按以下固定顺序求值：

1. 任一关键依赖缺失、未确认、无效、超限、周期/币种冲突、税口径不允许、覆盖不足或规则执行失败：值为 `null`，证据状态为 `insufficient-data`。
2. 结果描述未来购买情景：证据状态为 `forecast`；同时列出所有 `estimated` 依赖，不能因此改为 `estimated`。
3. 非未来结果存在任一 `estimated` 关键依赖：证据状态为 `estimated`。
4. 非未来结果的全部关键输入均为 `user-confirmed`：证据状态为 `user-confirmed`。
5. 研究层观察或系统事件的 `actual` 不进入产品财务依赖图；本规则集不得输出产品财务 `actual`。

每个结果返回稳定的公式 ID、可用性、精确值/`null`、展示值、单位、币种、`currencyTableSnapshotId`、周期引用、税口径、证据状态、依赖引用、估算依赖、原因码、假设、限制、规则版本、完整时间上下文和舍入元数据。原因码不含用户原始值，至少包括：

```text
missing-income
missing-work-hours
missing-purchase-price
missing-fixed-cost
comparison-period-unconfirmed
currency-unconfirmed
tax-basis-unconfirmed
input-unconfirmed
invalid-decimal
zero-not-allowed
negative-not-allowed
fraction-exceeds-currency-minor-unit
numeric-limit-exceeded
unsupported-currency
currency-mismatch
period-mismatch
input-reconfirmation-required
tax-basis-not-after-tax
fixed-cost-coverage-incomplete
fixed-cost-coverage-description-missing
purchase-period-unconfirmed
division-by-zero
rule-execution-failed
```

若同时存在多个问题，按“上下文（周期、币种）→ 公式依赖顺序 → 输入合法性 → 产品门禁 → 规则故障”返回去重后的全部原因；首项是稳定 primary reason。UI 将代码映射为非敏感、可操作文案，不能直接显示堆栈或输入值。

#### 5.1.6 展示精度与舍入

- 下游公式只读取未舍入的最小货币单位或有理数；展示值永远不能回流计算。
- 舍入模式统一为 `half-away-from-zero`：比较 `2 × |余数|` 与分母，达到或超过一半时把绝对商增加 1，再恢复符号。实现不得借助浮点数。
- 金额结果按该货币 minor unit 展示；本期金额加减本身已精确到该单位，不产生额外小数。
- Income Rate 展示 `min(4, max(currencyMinorUnit, 2))` 位小数。
- Work-time Equivalent 以小时为唯一主单位，展示 2 位小数；精确非零但舍入后为 `0.00` 时显示 `<0.01 小时`，不伪装成零。
- “查看依据”和后续导出必须同时保留精确值、展示值、显示位数、`half-away-from-zero` 与 `rounded: true | false`。本地分组和小数符号仅属展示，不改变规范十进制字符串。

#### 5.1.7 规则版本与会话修订

- 首个获批合同使用 `rulesetId: purchase-decision-rules` 与 `rulesetVersion: 1.0.0`，合并显示为 `purchase-decision-rules@1.0.0`；规则 ID/版本与应用构建版本、Git SHA、货币快照版本、导出格式版本分开记录。
- 公式、依赖、状态优先级、输入精度/限额、舍入、周期/时区语义、既有原因码含义或货币 minor unit 的改变是 breaking semantic change，提升 major；只新增不改变既有结果的新公式/原因码提升 minor；不改变语义的解释文案或元数据修正提升 patch。货币列表新增代码至少提升 minor，删除代码或改变既有 minor unit 提升 major。
- 已接受版本不可原地改写；一个构建和一次会话只能使用一个不可变规则版本，不能从远端取得或在会话中静默切换。
- 用户开始编辑已确认输入时，立即移除依赖结果的“当前”资格并进入 `pending-reconfirmation`；旧结果只可作为内存内最小历史快照，绝不能继续参与当前计算。
- 未确认按键不创建修订事件。用户确认修改后，创建一条 `confirmed-input-revision`：该事件在独立的系统事件命名空间标为 `eventStatus: actual`，只表示确认事件确已发生，不改变任何字段的财务证据状态；同时记录顺序号、用户触发者、完整时间上下文、字段、修改前后规范值与受限原始十进制文本、证据状态、周期引用、币种/单位、确认时点、被失效结果 ID、旧结果最小快照和规则版本。
- 用户取消尚未确认的编辑时，丢弃草稿且不创建修订事件；不得把旧结果对象重新标为当前。依赖结果继续保持 `pending-reconfirmation`，直到用户重新确认仍保留的原输入并由同一不可变规则版本生成一个带新时间上下文的新结果；值未改变时不伪造“修订”事件。
- 旧结果最小快照只含公式 ID、精确/展示值、单位/币种、周期/税口径、证据状态、依赖引用、舍入元数据、规则版本、`currencyTableSnapshotId` 和完整时间上下文，不复制整页、研究观察或无关文本。所有事件只存在当前浏览器内存，刷新、关闭或退出后不可恢复。
- 导出 ADR 必须明确承接当前快照、精确字符串、规则/货币快照版本和本次会话确认修订语义；本 ADR 不决定 JSON/Markdown 字段名、schema、MIME、文件名或下载实现。

### 5.2 为什么选择它

- `Number` 的二进制表示和安全整数边界不适合把“同样输入、同样规则、同样结果”作为信任合同；货币定点与有理数把误差来源限制在明确的展示舍入。
- 单独使用货币整数无法精确表达速率与工时除法；分子/分母避免 BigInt 除法截断，也确保 Work-time Equivalent 不依赖已舍入的 Income Rate。
- 当前固定公式数量很少，带类型纯函数比通用规则引擎更可审查，也不突破 `ADR-0001` 的直接依赖白名单。
- 周期修订引用比精确日历或自动归一化更忠实于用户选择，既不增加输入负担，也不制造跨期推断。
- 固定的官方货币快照、显式时区来源和不可变规则版本能解释结果产生时采用的口径，同时避免运行时网络与“当前默认值重写历史”。
- 工作流失效与五类证据状态分开，既能立即移除旧结果，又不会发明 `stale` 等未经产品批准的证据类别。

### 5.3 适用边界

本决策只适用于：

- `PRD-0001` 的单案例、单浏览器、单会话研究原型；
- 一组收入、工时、购买价格和可选固定成本汇总；
- 单一用户确认周期、单一 ISO 4217 币种、税前/税后显式口径；
- Income Rate、Work-time Equivalent、覆盖范围内可用余量和一次购买情景影响；
- 当前内存中的输入、派生结果和已确认修订。

本决策不适用于：

- 换汇、汇率、跨周期归一化、税务推断、通胀、利息、分期、订阅摊销、市场价格、概率模型或 AI；
- 账户、账本、目标余额、净资产、支付能力、信用、投资、正式财务建议或财富评分；
- 跨会话历史、数据库、同步、导入、远程规则、动态插件、正式审计账簿；
- 导出 schema/格式/下载、研究观察存储、生产遥测或正式产品计算架构。

进入上述范围前须按上位文档判断新 PRD、RFC、ADR 或本 ADR 修订；不能把研究原型规则默认为正式产品规则。

## 6. 产品、数据与信任影响

### 6.1 数据状态与历史口径

- 产品财务输入的 `user-confirmed`/`estimated`、派生结果状态、工作流可用性和系统事件来源分别存储，互不静默升级。
- 每个当前结果都能追溯到精确输入、公式/依赖、币种、周期、税口径、规则/货币快照版本和设备生成时点；展示舍入不能覆盖精确值。
- 修改后的旧结果不再是当前事实，只在本次会话修订事件中作为最小快照保留。刷新/关闭后没有跨会话历史，也不能声称能恢复或重算过去结论。
- 新规则版本不重解释旧快照；若需要跨版本比较、迁移或重算，必须先创建新 ADR。

### 6.2 可解释性与用户操作

- 用户能看到公式、输入、单位、币种、比较周期、税前/税后、状态、估算依赖、规则版本、生成时点、舍入和不足原因，并能返回修改、重新确认、忽略结果、退出或主动导出。
- 结果只描述数学关系和用户已确认覆盖范围；不把 Work-time Equivalent 说成人生价值，不把负余量说成失败，不把购买情景写成建议或承诺。
- 字段失败只停止依赖结果；例如缺少固定成本不阻止 Income Rate/Work-time Equivalent，未确认购买周期不阻止 Work-time Equivalent。
- 超限提示使用“超出本原型可计算范围”，而不是暗示用户金额/工时不合理。

### 6.3 隐私与安全边界

允许的数据流只有：

```text
用户确认输入 + 显式上下文 + 固定规则/货币表
                    │
                    ▼
             纯 TypeScript 内存计算
                    │
                    ├──> 当前结果与查看依据
                    └──> 当前会话最小修订快照

禁止：网络、浏览器持久化、日志、遥测、异常上报、第三方、远程规则
```

- 内核不得读取或写入网络、Cookie、localStorage、sessionStorage、IndexedDB、Cache Storage、URL、剪贴板、文件、console 或研究记录。
- 原始值、规范化值、派生值、修订前后值和原因上下文都视为敏感；只在当前内存按完成计算/解释/主动导出所需最小范围访问。
- 原因码、错误提示、性能测量和测试报告不得包含真实输入或派生结果；全部验证只用 `SYN-01`–`SYN-05` 或新增合成边界 fixture。
- 规则失败时 fail-closed；禁止通过远程服务、日志、默认值、旧结果或浮点路径兜底。
- 用户主动下载后的数据控制边界、临时对象撤销和格式安全由导出 ADR 进一步固定；本 ADR 不声称能召回已下载文件。

## 7. 后果

### 正面后果

- 原始十进制输入和派生除法均有精确、可复现的领域表示。
- 公式、状态、失败原因、舍入与版本有单一入口，React 无权另行解释。
- 不新增运行时依赖、远程货币/规则服务或持久化，维持 `ADR-0001` 的最小供应链与隐私边界。
- 周期/币种变更会机械失效依赖，减少旧值误用。
- 负余量、数据不足和估算依赖有明确、非评判性的表达路径。

### 负面后果与接受的取舍

- 需要自行实现并严格测试解析、有理数、最大公约数、约分、边界和舍入；代码量高于直接使用 `Number`。
- BigInt 不能直接作为 JSON 值，需要导出 ADR 固定字符串合同。
- 输入只接受受限 ASCII 十进制，不自动解释分组符号、科学计数法或 locale 数字；界面必须提前说明。
- 时区和时点来自设备，只能解释会话，不是权威时间证据。
- 固定 ISO 快照不会自动获得新货币或小数位变更；更新必须显式版本化和复审。
- 本期只显示小时，不自动换算工作日；这是避免隐含“每日工时”假设的刻意取舍。

### 未决风险

| 风险 | 可能性 | 影响 | 缓解/监测 | 触发新 ADR 的条件 |
| --- | --- | --- | --- | --- |
| 自建有理数或舍入实现错误 | 中/待测 | 高 | 表驱动、性质、边界、tie 与独立参考向量；任一差异停止分发 | 改用第三方 decimal/规则引擎或改变数值模型 |
| 超大输入消耗 CPU/内存 | 低 | 中 | trim/解析前原始长度上限、规范 token 位数上限、分子/分母各 128 个十进制数字上限、性能预算、fail-closed | 必须支持更大范围或批量计算 |
| ISO 快照过期或条目解释错误 | 低/随时间增加 | 高 | 固定 URL/发布日/摘要；构建映射一致性测试；首次实现前和复审日 readback | 代码/minor unit 变化、需历史货币或 FX |
| 设备时钟/时区错误 | 中 | 中 | 显示 `device-clock`、IANA/offset/来源和 UTC fallback；允许修改 | 计算开始依赖实际日期、时区或权威时间 |
| 舍入值被误当精确值 | 中 | 高 | 精确值隔离、`rounded` 元数据、依据中显示精度和模式、禁止展示值回流 | 对接会计/支付系统或改变舍入规则 |
| 状态/原因规则被组件复制 | 中 | 高 | 领域模块为唯一入口、架构检查和组件测试只断言领域输出 | 需要多规则引擎或服务端计算 |
| 修订快照过多造成内存或隐私负担 | 低/待测 | 中 | 只记确认事件和最小快照；设置会话上限并在 OpenSpec 中机械化；刷新清除 | 需要跨会话历史、恢复或批量导入 |
| 规则版本分裂导致结果不可比较 | 低 | 高 | 单构建/单会话单版本、版本矩阵、整体回滚、禁止静默更新 | 并行支持多个规则版本或历史重算 |

## 8. 迁移、兼容与回滚

### 8.1 迁移/回填

无。当前没有应用、计算代码、产品数据、规则版本或历史结果需要迁移/回填。本 ADR 不授权创建数据库、跨会话兼容层或历史重算工具。

未来若替换数值实现，必须保持既有规范十进制/有理数测试向量可读，并通过新的 ADR 说明是否结果等价；不得静默重解释已经展示或导出的旧规则版本。

### 8.2 兼容策略

- 浏览器必须原生支持本 ADR 所需 BigInt；不支持时阻止该构建/会话，不回退到 Number。
- 规则版本、ISO 快照、构建版本和导出格式版本独立但一同出现在结果依据；兼容矩阵由实现证据和导出 ADR 固定。
- 纯 TypeScript 输入/输出合同不依赖 React，未来可以替换 UI；替换不得改变精确公式、状态或舍入结果。
- 当前无旧客户端、外部连接、导入或持久化。用户已下载文件的解析兼容由导出 ADR 决定。

### 8.3 回滚与恢复

1. 首次实现若任一公式、状态、精度、舍入、货币映射、失效或隐私验证失败，立即停止分发并撤下构建；不存在产品数据回填。
2. 后续规则错误必须恢复上一份**整体已验证**的 Git commit、静态产物、依赖锁、配置、规则版本和 ISO 快照；不能只替换页面、公式或货币表中的单一文件。
3. 恢复后重新执行 SYN-01–SYN-05、精度/边界/状态表、网络/存储/日志、修订失效和构建摘要 readback，证据未通过前保持暂停。
4. 出现外发、持久化、日志泄漏、状态升级或错误结果时按关键隐私/信任事件处理；定位并删除意外副本，无法证明处置完成时不恢复研究。
5. 代码回滚不能召回已下载文件。必须记录受影响构建、规则版本和 ISO 快照，并按导出 ADR 的用户通知/退出边界处置。
