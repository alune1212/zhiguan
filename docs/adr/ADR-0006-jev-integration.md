# ADR-0006：Jev 接入边界（讨论草案）

状态：开发实验已批准；尚未批准产品接入。

## 已确认事实

- 用户要求安装 TypeSafe Python SDK，并讨论 Jev 如何融入当前购买工作台。
- 已添加最小 Python 依赖清单，安装 `typesafe-sdk==0.7.0`；SDK 导入通过。方案确认后已完成 20 次虚构样本远程调用，详见[首轮结果](../jev-experiment-results.md)。
- 当前产品仍以 React/Bun 和浏览器内存态运行；策略与架构规定不联网、暂不接入 AI。安装开发依赖不代表改变这些边界。
- Jev 处理文本并返回类型化判断与概率，不生成自由文本解释；类型正确不代表判断正确。

## 已选实验方向

验证“从一句购买描述整理待确认输入”：代码提取原文候选数字，Jev 判断各候选对应收入、价格或其他字段。没有候选或含义不明时保留空缺，不自动填零或猜测。实验只输出供核对的结果，不进入产品计算流程。

本轮不开展价值期待的澄清问题实验，不判断购买是否值得。

## 已确认的首轮决策

1. 范围：先用虚构中文样本做开发实验，再决定是否接入产品；当前不推进产品联网能力。
2. 首要任务：减少数字输入，从一句购买描述整理待确认字段，用户逐项核对后使用现有计算逻辑。
3. 字段范围：月收入、税前/税后口径、购买价格；作息和固定支出不进入本轮。
4. 验证方式：20 条虚构中文样本，覆盖明确表述、缺失、多金额、约数、否定与改口；逐字段核对，记录误填和漏填。出现无依据填值或把歧义直接确定，就不进入产品接入阶段；通过本轮也不自动批准产品接入。
5. 实验形式：手动运行 Python 命令行脚本，输出候选字段、对应原文和待确认项；先验证理解准确性，再决定前端交互。

## 已确认的实验执行边界

只发送虚构样本文本及字段判断问题；每条样本一次请求，三个字段一同判断，最多 20 次推理请求，关闭自动重试。模型错误与服务失败分别记录，不以失败结果补零。模型输出均为待确认输入，约数保留 estimated 含义，置信度不替代用户确认。密钥通过 TYPESAFE_API_KEY 环境变量提供，不写入仓库或结果文件。

正式接入前继续确认最少上传字段、用户授权、服务端密钥、失败降级和验证标准；依据回答更新本 ADR 及必要的产品文档。当前不建立后端、不上传用户数据、不把模型判断写成用户决定。

## 运行方式

项目根目录 `.env` 设置 `TYPESAFE_API_KEY`，文件已被 Git 忽略。仅运行命令行实验时加载，不交给前端。

```sh
uv run --locked scripts/jev_experiment.py --self-check
uv run --locked --env-file .env scripts/jev_experiment.py --run --output tmp/jev-results.jsonl
```

第二条命令会产生真实 API 请求。输出文件须不存在，避免覆盖旧记录；每次手动重跑都会产生新请求。脚本只接受固定的 20 条虚构样本，不接收个人财务文本。结果包含预期、候选字段、原文位置、置信度、模型返回和请求标识；完整匹配与服务成功分别判断。当前不把数字原文转换为金额，不建立产品自动填表路径。

首轮 19/20 条完整匹配，59/60 个字段匹配；一次明确收入金额漏填，无依据填值和歧义强行确定均为零。没有自动重试或针对失败样本重跑。保留实验边界，尚不据此批准产品接入。
