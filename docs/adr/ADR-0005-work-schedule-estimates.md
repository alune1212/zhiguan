# ADR-0005：明确作息估算及其导出依据

**状态：** Accepted，2026-09-03；用户已确认输入、时间范围、估算公式和增量导出方案。

为减少自行统计月工时的负担，允许用户主动选择每周 5 天、每天 8 小时或每周 6 天、每天 8 小时，也可填写每周平均天数与每日平均小时，或直接输入月工时；不预选作息。作息按「每周天数 × 每天小时 × 52 ÷ 12」估算月工时，不逐月扣除节假日、请假或添加临时加班；每日平均小时包含经常性加班，不含通勤与休息。周天数须大于 0 且不超过 7，日小时须大于 0 且不超过 24，支持现有工时精度内的小数；非法或不完整作息只让依赖工时的结果降级，不补零或旧值。

换算复用现有精确有理数处理，归一化月工时一次性四舍五入到小数点后三位，再进入现有月度计算；小到归一化为零的输入不得继续计算。作息工时始终为 `estimated`，用户确认或取消大概数选择也不提升为事实；收入、支出和购买金额仍保持各自证据状态，未来余量仍为 `forecast`。直接填写月工时保留原有精度和证据语义。结果仍以小时展示，并提供作息、换算、舍入和适用范围说明。

保留 `zhiguan-purchase-decision@1`、`inputs.work_hours`、现有证据字段及五项结果含义，只在 `inputs` 增加 `work_time_basis`：记录输入方式、原始每周天数和每日小时，以及含 52 周、12 个月、三位小数、四舍五入和时间范围说明的换算规则；直接输入或尚未选择时无换算规则。无效输入原样保留且结果诚实降级，不将依据塞入用户备注或结果级 `source`。这是明确的增量字段扩展，不建设新版本、迁移或兼容框架；旧文件仍是原有月工时输入记录，不替旧文件推断作息。

本决定补充 ADR-0002 的显式周作息归一化例外，并取代 ADR-0003 中会把自动估算工时统一切回 `user-confirmed` 的选择行为；其余计算、内存态和用户主动下载边界不变。若新入口增加理解负担或不能如实保留估算依据，可撤回作息入口，恢复直接输入月工时；不改写已经下载的记录。
