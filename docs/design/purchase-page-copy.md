# 单次购买页面文案基线

**状态：** 已确认并接入代码的购买文案基线；合成数据下的浏览器主路径已通过，真实用户体验仍待验证

**版本：** 0.2.0

**更新日期：** 2026-09-22

**适用范围：** `PRD-0001` 单次购买决策页

本文件记录单次购买工作台的文案与页面层级，不再定义首页入口。由新收入看板进入的购买流程已接入代码，复用与口径说明以已批准的 [PRD-0003](../product/prd/PRD-0003-income-dashboard.md) 为准；旧 @1 文件和历史验证继续保留。

本文件记录当前页面的文案和信息层级。按结果正负、输入状态切换句子属于界面呈现，不改变输入项、计算规则、状态含义、决定代码或导出格式。

## 1. 表达原则

- 像一个冷静、可靠的人说话，直接把事实讲清楚。
- 先回答用户的问题，再解释数字从哪里来。
- 不要求用户理解“工作时间等价”“预测”“数据不足”等产品术语。
- 不替用户判断买不买，也不评价收入、支出或决定。
- 大概数、未来情况和缺失信息直接写进句子，不只靠标签或颜色表达。

文中的 `{变量}` 代表页面根据本次输入和计算结果替换的内容，不会原样显示给用户。

### 4.1 区块标题

**结果**

### 4.2 主要结果：工作时间

**结论**

根据工作时间的来源使用以下句子：

| 工作时间来源 | 结论 |
| --- | --- |
| 作息换算 | 按平时作息估算，这笔钱约相当于你工作 {工作时间} 小时的收入。 |

| 直接填写且未勾选大概数 | 按这些数字，这笔钱相当于你工作 {工作时间} 小时的收入。 |

**展开入口**

> 怎么算出来的

**展开说明**

作息换算时先显示：

> 按每周 {每周天数} 天、每个上班日 {每日小时} 小时估算。每周天数 × 每天小时 × 52 ÷ 12，月工时四舍五入保留三位小数。本次按每月 {工作时间} 小时换算。

随后继续显示：

> 先用月收入除以每月工作时间，算出每小时收入；再用购买价格除以每小时收入。{收入口径说明}

作息填写不完整或无效时，换算说明显示：

> 作息填写完整且有效后才能换算。

作息换算说明还显示以下两条适用范围：

> 典型周平均到月，不逐月扣除节假日、请假或添加临时加班。

> 每日平均小时包含经常性加班，不含通勤与休息。

| 情况 | 文案 |
| --- | --- |

## 5. 缺失数据阶段

### 5.1 基本结果暂时算不了

输入项旁继续显示第 3.3 节中的具体错误。结果区根据问题类型显示一句，不重复罗列所有错误。

| 情况 | 结果区文案 |
| --- | --- |
| 仍有内容没填 | 还缺{字段列表}，所以现在算不了{结果名称}。 |
| 有内容格式不对、为 0 或超出范围 | 先改正{字段列表}，才能计算{结果名称}。 |
| 两种情况同时存在 | 上面标出的内容还没填好，所以现在算不了{结果名称}。 |

`{字段列表}` 只列出该结果依赖的错误字段，使用“每月收入”“工作安排”“每月工作时间”“购买价格”“每月固定支出”“税前或到手的选择”等用户可读名称，不显示代码字段名。未选择作息或自定义作息无效时，基本结果的字段列表使用“工作安排”；自定义字段旁的错误提示具体使用“每周上班天数”和“每天工作小时数”。`{结果名称}` 在两项基本结果中分别为“买它要花多少工作时间”和“每小时收入”。

未选择作息且未使用直接填写入口时，基本结果的完整提示例如：“还缺工作安排，所以现在算不了买它要花多少工作时间。”

### 5.2 本月剩余金额暂时算不了

只有用户主动开启余量后，才显示相关结果与提示。开启前主动提供的固定支出信息可以保留待核对，但不因此触发追问或结果展示；单独填写“你希望它带来什么”也不会开启余量。

| 情况 | 文案 |
| --- | --- |
| 收入选择了税前金额 | 你填的是税前收入，所以现在算不了本月剩余金额。请重新填入税后（到手）收入，并选择“税后（到手）”，再查看结果。 |
| 仅缺少固定支出数字 | 还缺每月固定支出，所以现在算不了本月剩余金额。没有固定支出可以填 0。 |
| 固定支出范围未确认、只包含一部分或不确定 | 还需要确认固定支出已经填全，才能计算本月剩余金额。 |
| 未确认本月付款，或选择不在本月付款 | 还需要确认这笔购买算进本月，才能计算买完后还剩多少。 |
| 固定支出范围未确认为全部，且购买未选为本月付款 | 还需要确认固定支出已经填全，并确认是否按本月付款来算，才能计算买完后还剩多少。 |

税前收入提示优先；否则先处理缺失或无效的数字、收入口径，再提示覆盖范围或购买月份确认。数字与收入口径问题沿用第 5.1 节的三个句式，`{结果名称}` 分别为“本月剩余金额”或“买完后还剩多少”。例如仅固定支出有误时，购买前结果显示“先改正每月固定支出，才能计算本月剩余金额。”

缺失时不显示 `0`、旧结果或推测值，也不单独显示“数据不足”标签。

固定支出范围提供“包含本月全部固定支出”“只包含一部分”和“不确定”选项；只有确认包含全部时才能计算本月剩余金额。付款状态提供“本月付款”和“不在本月付款”选项；选择本月付款后才计算买完后还剩多少。无法归入上述原因的不可用结果使用“上面的信息还没填好，所以现在算不了{结果名称}。”

导出中的 `review_condition` 继续作为兼容字段保留；当前页面没有对应输入项，因此不新增文案。

## 7. 当前界面层级

页面按下面的顺序组织：

1. 主标题和一句说明。
2. 首先显示一句话输入“先说说这次购买”，用户主动发送后才整理信息；“手动填写”入口始终可用并编辑同一份草稿。切到手动模式后，可随时返回一句话补充。
3. 对话整理后，用户可在摘要前开启本月剩余金额；只有主动打开后才显示相关输入或追问。
4. 对话整理后显示“我整理的信息”及可编辑摘要，用户一次整体确认；手动模式直接显示收入、价格、收入口径和作息输入，余量输入保持可选，并使用同一确认按钮。
5. 工作时间结论作为主要结果。
6. 每小时收入和本月剩余金额作为补充结果，并说明计算方式和限制。
7. 用户自己的决定与下载。

正式状态、计算公式和导出字段继续保留在数据层。页面只把它们翻译成用户能直接理解的句子。
