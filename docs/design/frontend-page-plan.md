# 值观前端页面方案

**状态：** 页面方案已确认；2026-09-23 用户确认 Q1–Q3 全部采用推荐。静态概念稿与现有 React/shadcn 界面已交付；浏览器验收结果及未覆盖项见[前端验收记录](frontend-acceptance.md)。

**依据：** [DESIGN.md](../../DESIGN.md)、[品牌指南](brand.md)、[收入看板 PRD](../product/prd/PRD-0003-income-dashboard.md)、[业务术语](../../CONTEXT.md)。产品边界和计算含义沿用现行文档。

本文“收入首页”指收入看板作为默认入口；值观的产品类别仍是“个人价值流 / Personal Value Flow”。辅助指标统一使用“本月收入估算”“每秒收入估算”，每秒收入估算是当前口径下的收入速率。

## 已确定的设计基础

- Apple 风格、浅色、系统无衬线字体、shadcn/ui；颜色、字号与控件规范遵循 DESIGN.md。
- 首次只有到手月收入必填，默认作息可见、可修改；主动保存后进入收入首页。
- 首页以今日收入估算为主，本月收入估算与每秒收入估算为辅；详细计算依据和设置按需展开。
- 购买分析是次级入口，继续支持一句话输入、手动切换和既有决定流程；收藏保持当时的结果与口径。
- 当前功能仅在此浏览器保存；输入失败、未保存、冲突与损坏都必须有可见状态和恢复路径。

## 已确认的页面组织

### 收入首页

首屏让用户依次看见“今天估算了多少”“当前按什么时段计算”“怎样查看依据或继续操作”。主数字居中，所有细节区域保持左对齐；先按手机短时查看的场景定稿，桌面完整适配。

| 区域，从上到下 | 内容与层级 | 交互 |
| --- | --- | --- |
| 轻量顶栏 | 左侧“值观”，右侧“收藏”“设置”；无侧栏 | 收藏进入已有列表，设置定位并展开首页下方的设置区域 |
| 主数字区 | 当前日期、标题“今日收入估算”、完整金额、工作/休息状态 | 数字直接更新，不需要点击或保持页面常开；主金额附近常显“按设定作息估算，非实际到账” |
| 辅助数字组 | “本月收入估算”“每秒收入估算”，字号显著小于主金额 | 桌面并排；窄屏按数值长度并排或上下排列，完整显示单位 |
| 轻操作行 | “计算依据”“算一笔购买” | 前者展开紧邻的计算说明，后者进入购买分析；使用轻量控件，避免主数字与购买按钮争夺注意力 |
| 可展开的解释与设置 | 公式、月份、时区、工作日和时段；收入与作息编辑 | 设置保留草稿、取消和主动保存；保存前说明重算范围 |
| 本地资料说明 | 资料更新时间、此浏览器保存范围 | 备份、恢复、清空集中在设置内的资料管理分组 |

主数字区不套大卡片，辅助数字不拆成三个同等大小的指标卡。首页不增加增长曲线、进度环、收益排行或虚构历史。保存异常与冲突提示显示在主内容之前，不能藏在折叠区域。

### 首次使用

单列窄表单，简短标题沿用“先看见时间与收入”。金额输入、默认作息说明、“保存并开始”和本地保存说明形成一组。详细作息保持折叠；从已有备份恢复的入口清楚可达。无输入时不展示虚构的个人收入预览。

### 收入与作息设置

保留首页下方可展开的设置区域。依次呈现收入、每周工作日与每日时段、特殊日期与时区、备份与删除；字段使用清楚的标签和就近错误。进入设置不更改现有值，保存后才重算；取消保留此前有效资料。手机沿用纵向表单，避免在小弹层中编辑长作息。

### 购买分析

采用左对齐的任务布局：一句话描述 → 按需补充 → 可编辑摘要 → 结果与可选决定。手动填写作为随时可用的切换入口。结果以工作时间等价为主，金额与比较月份为辅；收藏与下载就近排列。桌面和手机保持一致的阅读顺序，临时改动与基础资料的区别清楚可见。

### 购买收藏

采用纵向列表。每项先展示购买对象、当时工作时间等价、金额和收藏时间，再展开依据及决定。重新试算与删除位于该项详情内，避免把历史结果误认为按最新资料计算。没有收藏时显示一段用途说明与购买入口。

## 必须覆盖的状态

| 状态 | 页面表现 |
| --- | --- |
| 工作时段 | 金额按计划时间更新，状态文字说明“当前工作时段” |
| 午休、下班或休息日 | 保留有效金额，显示“休息时间 · 暂停增长”；不显示惩罚或催促文案 |
| 有效零值 | 正常显示金额零，保留口径，不当作故障 |
| 数据不足 | 数字位显示 `—`，就近列出原因和修正入口，不保留旧结果冒充当前值 |
| 未保存、存储不可用 | 明确指出本次仅临时使用，保留当前输入 |
| 资料冲突或损坏 | 原内容不被默认值覆盖；突出既有重新载入或备份恢复路径及影响说明 |

## 第一轮：已确认的决定

用户以“全部按推荐”确认以下三个选择，已用于概念稿和当前界面实施。

| 编号 | 讨论项 | 确认结果 | 影响 |
| --- | --- | --- | --- |
| Q1 | 首页主数字居中，还是整页左对齐 | 主数字居中，说明与设置左对齐 | 决定首页的视觉重心及阅读节奏 |
| Q2 | 操作入口按任务分布，还是全部集中在顶栏 | 顶栏放收藏与设置，数字下方放计算依据与购买入口 | 决定首屏轻重与操作的发现路径；两种方案均保留设置的折叠行为 |
| Q3 | 优先以手机短时查看，还是电脑浏览为主要设计场景 | 手机短时查看优先，桌面同样完整适配 | 决定首先定稿的视口与细节密度，不取消任何宽度的可访问性要求 |

本轮关键选择已达成共同理解，暂无阻塞页面方案的未决问题。实施规划见 [redesign-frontend-with-shadcn](../../openspec/changes/archive/2026-09-23-redesign-frontend-with-shadcn/proposal.md)。现有术语含义清楚，本轮没有新增业务术语或需要 ADR 的不可逆决定。
