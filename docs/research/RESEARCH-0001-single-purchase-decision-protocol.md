## 1. 目的与授权边界

本研究验证：稳定收入知识工作者能否用少量个人输入理解一项真实购买、形成自己的决定，并在之后通过人工回访复盘判断依据。

原型内只实现 `Capture → Normalize → Understand → Simulate → Decide`；`Review` 与 `Learn` 由产品外人工研究完成。研究协议不能把原型描述为完整产品，也不能授权账户、持久化、同步、通知、AI、完整账本或公开发布。

本协议只有在以下条件全部满足后才能从 `Draft` 改为 `Accepted`：

1. `PRD-0001` 已批准；
2. 原型已达到 `Prototype Accepted`；
3. 本协议第 10 节标为“协议批准前置”的七项均已关闭，研究治理组 AC-18、AC-19 与 AC-27 的证据已链接；
4. 独立人类挑战完成，关键意见全部解决，具体研究日历已同时写入本协议和 Issue #1。

第 10 节最后一项 Alune 最终 readback 不是协议 `Accepted` 的前置条件。协议获批仍不自动授权招募；只有协议已为 `Accepted` 后，Alune 再完成 `Recruitment Authorized` 的完整 readback，才构成招募授权。

## 2. 研究设计

- **研究类型**：形成性研究，不做统计性市场推断。
- **目标参与者**：有相对稳定收入、以知识工作为主、不希望维护复杂账本，且正在考虑一项真实购买的个人。
- **第一批**：3–4 人，用于发现阻塞性的理解、信任、输入负担和交互问题。
- **门间评审**：只允许修改 PRD 已定义的文案、顺序、解释和局部交互；若需要改变数据语义、隐私边界、核心对象或范围，停止并重新判断 PRD/RFC/ADR。
- **第二批**：3–4 人，使用修订后的固定构建验证，并对愿意继续参与者完成人工回访。
- **通过条件**：沿用 PRD 的 `C_core` 定义；第二批同一组参与者至少形成 3 个完整闭环案例，关键隐私/信任事件为 0。
- **结论期限**：第二批最后一次计划回访完成后 7 个自然日内记录继续、修订、停止或退回研究的结论。

## 3. 同意、退出与可选授权

### 3.1 必须分开的授权

1. **参与研究与使用原型**：说明研究目的、当前会话内存处理、刷新/关闭清除、用户主动本地导出、静态托管访问元数据、人工回访和退出方式。
2. **封闭字段脱敏观察**：说明第 6 节允许记录的字段、两类存储、访问者、保留与删除期限。未授权时不得记录观察，也不得计入研究样本。
3. **额外内容**：原话引用、录音、录像和截屏分别采用独立、默认关闭的可选授权；拒绝任何一项不影响前两项参与资格。

原型内的会话边界确认不能替代正式研究同意。所有说明使用平静、具体、可退出的语言，不暗示拒绝会带来损失。

本协议 `0.2.0` 只定义上述可选授权的分层原则，不授权实际采集原话、录音、录像或截屏。若后续确有必要，必须先修订协议，明确与存储 A/B 分离的加密位置、访问者、最短保留期限、删除 readback 和结果使用边界，并重新完成独立人类挑战与 `Recruitment Authorized`；在此之前，即使参与者表示愿意，也不得采集。

### 3.2 退出与撤回

- 参与者可在任何步骤停止原型或研究，不需要说明理由。
- 收到撤回请求后立即停止未来联系，并在 7 个自然日内删除所有仍可通过研究编号关联的适用记录。
- 删除前仍可关联到该参与者的聚合必须重新计算，并记录撤回前后分母变化；不能静默只从完成者中移除。
- 逐人记录和映射已经按期删除、无法重新关联个人后，只保留在研究说明中预先披露的不可识别聚合结论。
- 撤回联系路径、执行者、参与者确认方式和非识别化操作 readback 格式必须在招募前填写；当前均为待定。不得为了证明删除而继续保留研究编号或创建第三个逐人数据集。

## 4. 数据隔离与访问

研究操作使用两个独立的加密存储，不得合并为同一文件的不同工作表：

| 存储 | 允许内容 | 禁止内容 | 访问者 | 映射规则 |
| --- | --- | --- | --- | --- |
| A：联系与同意 | 联系方式、同意/撤回状态、可选授权、回访安排 | 原始财务输入、价值期待全文、决定依据全文、派生财务结果 | 仅 Alune | 随机研究编号与联系人映射只存在于此 |
| B：封闭字段观察 | 随机研究编号及第 6 节的封闭字段 | 联系方式、同意原文、自由文本、原始金额/工时、精确操作时间、截图、录音录像 | 仅 Alune | 只保存随机研究编号，不保存可读身份线索 |

共同要求：

- 加密工具、固定存储位置、访问边界和删除方法已由 [`ADR-0004`](../adr/ADR-0004-research-data-custody-and-deletion.md) 确定；实际路径、权限、无默认同步/备份和删除 readback 尚未通过另行授权的合成演练证明，AC-18 仍未通过。
- 默认不启用云同步或备份；若候选工具无法证明这一点，不得使用。
- 两个存储都不得位于本仓库、GitHub Issue、原型、浏览器存储、普通日志或分析系统中。
- 研究编号使用无语义随机值，不编码姓名、日期、批次、设备或购买内容。
- AI 不得访问两个存储中的任何逐人数据，也不能成为研究授权或正式签字主体。

## 5. 保留、删除与审计

| 数据 | 最长保留期限 | 删除触发 | 删除证据 |
| --- | --- | --- | --- |
| 联系方式、同意和研究编号映射 | 最后一次计划回访后 30 天 | 到期或参与者撤回 | 存储 A readback；撤回时 7 天内完成 |
| 逐人封闭字段观察 | 实验最终结论形成后 30 天 | 到期或参与者撤回 | 存储 B readback；撤回时 7 天内完成并重算可关联聚合 |
| 不可识别聚合结论 | 可保留用于产品决策追溯 | 发现可重识别风险、口径错误或参与者权利冲突 | 更正或删除结果文档并记录原因 |
| 静态托管访问元数据 | 最多 7 天 | 到期、事件处置完成或研究停止 | 托管配置与日志删除 readback |

- 不建立默认备份。若操作系统或工具会自动备份，必须在招募前关闭或证明相关路径同样满足期限；否则更换工具。
- 删除动作必须现场完成存储 A/B readback。给参与者的确认不在其适用记录删除后另留副本；持久操作摘要只允许记录触发类型、完成日期、受影响记录数量和执行结果，不含研究编号、联系方式或原始内容，可作为不可识别的批次级治理结论保留，不创建第三个逐人数据集。
- 发生意外副本、越权访问、超期保留或删除失败时，立即暂停研究，按 PRD 的关键隐私/信任事件处理。

## 6. 允许的封闭字段观察 schema

以下是逐人观察记录允许出现的最大字段集合；具体字段名可在研究表中机械化，但不能扩大语义范围：

| 字段语义 | 允许值/粒度 | 来源状态 | 限制 |
| --- | --- | --- | --- |
| 随机研究编号 | 无语义随机 ID | 研究层 `actual` | 不编码身份或场景 |
| 批次 | `1` / `2` | 研究层 `actual` | 不含精确会话日期 |
| 四个宏观阶段结果 | `completed` / `aborted` / `not-reached` | 研究层 `actual` | 分别记录输入与期待、确认口径、理解与推演、决定与交接 |
| 解释检查项 | 来源、公式、证据状态、不确定性四项分别为 `true` / `false` / 条件性 `null` | 研究层 `actual` | `null` 只按下方阶段规则表示 `not-reached` 或 `not-observed`；不保存参与者回答原文 |
| 价值期待关联检查 | `passed` / `not-passed` / `not-reached` / `not-observed` | 研究层 `actual` + 参与者回答为 `user-confirmed` | 只判断能否把决定或不决定与自己的价值期待关联，不保存期待或回答全文 |
| 输入轮次 | `1` / `2` / `3+` / `not-reached` | 研究层 `actual` | 只记录到首次有效理解前的宏观输入轮次，不记录按键流或字段原值 |
| 首次阻塞阶段 | `none` / `stage-1` / `stage-2` / `stage-3` / `stage-4` / `not-reached` | 研究层 `actual` | 使用第 2 节四个宏观阶段，不保存自由文本原因 |
| 主动修正次数 | `0` / `1` / `2+` / `not-reached` | 研究层 `actual` | 不保存按键或字段原值；第一阶段未到达时使用 `not-reached` |
| 决定类别 | `purchase` / `wait` / `adjust-condition` / `do-not-purchase` / `undecided` / 条件性 `null` | 研究层 `user-confirmed` | `undecided` 只表示已到达决定阶段后的明确确认；未完成第四阶段时使用 `null`，不保存决定依据全文 |
| 输入耗时 | `under-5m` / `5-to-under-10m` / `10-to-under-20m` / `20m-plus` / `not-reached` / `not-observed` | 研究层 `actual` | 可现场计时后只保存分档，不保存精确起止时间戳 |
| 信任事件 | `none`、`not-observed` 或本节下方有限代码，可记录多个 | 研究层 `actual` 或参与者确认 | 不保存自由文本描述；关键事件立即暂停并按下方无逐人扩张规则处置 |
| 复盘结果类别 | `result-observed` / `feedback-only` / `no-result` / `not-reached` | 研究层 `actual` / `user-confirmed` | 不保存完整体验叙述 |
| 价值期待关系 | `changed` / `unchanged` / `unclear` | 研究层 `user-confirmed` | 不保存价值期待全文 |
| 判断依据修正 | `revised` / `confirmed-no-change` / `insufficient` | 研究层 `user-confirmed` | 不保存依据全文 |

禁止添加自由文本“备注”列。若研究确需引用原话，必须使用单独可选授权和独立存储，并先修订本协议；不得把原话放入封闭字段观察表。

缺失语义固定为：已到达且未发生使用 `none`，未到达使用 `not-reached`，已到达但无法可靠观察使用 `not-observed`，三者不得互换。

- 后一阶段只有在前一阶段为 `completed` 后才能为 `completed` 或 `aborted`；一旦某阶段为 `aborted` 或 `not-reached`，之后各阶段必须为 `not-reached`。
- 第三阶段为 `completed` 时，四个解释检查项都必须为布尔值；为 `aborted` 时，已可靠观察项使用布尔值，无法可靠观察项使用 `null=not-observed`；为 `not-reached` 时四项都使用 `null=not-reached`。
- 第四阶段为 `completed` 时，决定类别必须为一个封闭值；为 `aborted` 或 `not-reached` 时决定类别必须为 `null`。`undecided` 不得用来代替未到达或未观察。
- 第一阶段为 `not-reached` 时，输入轮次、输入耗时和主动修正次数都必须为 `not-reached`；第一阶段已到达（`completed` 或 `aborted`）时，三者不得使用 `not-reached`。
- 首次阻塞阶段必须等于第一个 `aborted` 阶段；没有 `aborted` 但存在 `not-reached` 时使用 `not-reached`；四阶段全部完成时使用 `none`。
- 第四阶段为 `not-reached` 时，价值期待关联检查必须为 `not-reached`；第四阶段已到达时不得使用 `not-reached`。第一阶段未到达时复盘结果也必须为 `not-reached`；第一阶段已到达后，复盘可暂时为空，聚合前必须解析为封闭值或 `not-reached`。

信任事件代码只允许：

- `unexpected-product-data-egress`、`unexpected-persistence-or-copy`、`sensitive-log-or-capture`、`evidence-state-overclaim`、`untraceable-or-stale-result`、`cannot-correct-exit-clear`、`coercive-or-shaming-decision`、`export-contract-breach`：均为 `critical`，立即暂停；
- `boundary-explanation-confusion`、`evidence-label-confusion`、`input-burden-friction`：均为 `non-critical`；
- 不能归入上述有限代码的事件不得写入自由文本“其他”，应暂停记录、先修订协议并重新评审 schema。

信任事件在 B 中使用集合语义：无子记录表示 `none`；一条 `not-observed` 记录必须独占；其他记录只保存唯一事件代码，同一代码重复发生不新增次数。级别由上方固定映射推导，不在 B 中重复存储。

事件处置不得形成第三个逐人数据集。存储 B 只保留事件代码和随机研究编号；需要联系参与者时，存储 A 只记录联系状态，不复制事件叙述。根因与恢复记录只能使用事件代码、构建/规则/配置版本、受影响数据类别和非识别化数量，不得包含研究编号、联系人、原始输入或参与者原话；若无法在这些边界内处置，研究保持暂停并删除不合规副本。

## 7. 静态托管与访问元数据

- 优先关闭静态托管访问日志。
- 无法关闭时，仅允许基础设施为了分发和安全产生 IP、User-Agent 与访问时点，最多保留 7 天。项目账户仅 Alune 可查看；托管方若因基础设施运营或安全而处理这些元数据，必须受合同/配置约束、不得二次使用，并在研究说明中披露。
- 禁止 Cookie、身份化 URL、参与者专属查询参数、分析脚本、会话重放、第三方字体追踪和产品数据请求。
- 访问元数据不得与研究编号、联系方式、原型输入、导出内容或观察记录关联。
- 上述范围、托管方、项目账户与管理员访问、处理目的、禁止二次使用、实际配置和删除 readback 必须写入正式同意材料与交付形态 ADR。
- 托管方不能满足任一边界时，改用受控本地分发，并在邀请前演练安装、退出和清除路径。

## 8. 研究日历

当前只批准相对顺序，不批准或承诺具体日期：

```text

  → 填写第一批具体日期
  → 第一批 3–4 人
  → 门间评审与范围内修正
```

具体招募、会话、门间评审、第二批、回访和结论日期只能在 `Prototype Accepted` 后确定，并必须在 `Recruitment Authorized` 前同时写回本节和 Issue #1。

## 9. 独立人类挑战

独立挑战者不是正式签字人；Alune 保留最终责任。挑战者必须是 Alune 之外、不是本原型实现作者、且对招募是否获批不存在直接利益冲突的人。挑战者只能查看合成数据、配置、网络/存储/日志 readback、协议和已脱敏治理证据，不得访问存储 A/B 或任何逐人数据。挑战者必须在招募前只读复核：

- 同意层级、退出和撤回是否可理解；
- 存储 A/B 是否实际隔离、加密、无默认同步/备份且只允许 Alune 访问；
- 原型是否无产品数据网络请求、浏览器持久化、敏感日志和分析；
- 静态托管日志是否关闭或满足 7 天上限，并可完成删除 readback；
- 用户主动导出是否包含敏感提示、取消、失败和本地文件控制说明；
- 撤回、到期删除、回滚和研究停止是否完成合成演练；
- 仓库和研究结果路径是否不含逐人数据或可识别内容。

挑战记录至少包含评审人身份、日期、复核范围、证据链接、意见级别和处置。完整记录保存在 A/B 之外的访问受控、加密治理位置，仅 Alune 与挑战者可访问，不得包含参与者数据；实验最终结论形成后最多 30 天删除完整记录并完成 readback。仓库只保存匿名评审标识、脱敏意见摘要和处置状态，不保存挑战者真实身份或受限证据链接。未解决关键意见阻塞协议 `Accepted` 与招募；非关键意见必须解决，或由 Alune 书面说明接受风险的原因与复审条件。
