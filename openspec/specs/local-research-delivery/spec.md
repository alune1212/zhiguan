# local-research-delivery Specification

## Purpose

为单案例购买决策形成性研究原型规定可复现、可停止、可审计的本地交付边界，使浏览器仅消费锁定版本的静态资源并在当前会话内工作，同时把网络、托管、依赖、无障碍、性能、日志、退出与回滚约束变成可验证的运行合同。

## Requirements

### Requirement: 交付物必须是可复现的纯静态研究构建

交付物 MUST 是由批准的源码、配置、锁文件和合成 fixture 生成的静态 HTML、CSS、JavaScript 与随包资源集合；它不得包含应用服务端代码、SSR/函数、数据库、研究记录、真实或近似个人数据、开发日志、测试截图或 source map。构建结果只能作为本研究原型的静态交付单元，不得被描述为正式产品运行时。

**Traceability:** FR-17、FR-24、FR-25；AC-15、AC-25、AC-26；ADR-0001 §5.1、§5.3、§8.2。

#### Scenario: 生成静态研究构建

- **WHEN** 研究构建在干净环境中使用批准版本、配置和合成 fixture 生成产物
- **THEN** 产物只包含可由静态资源服务提供的文件，且不包含应用后端、服务端执行、PWA/Service Worker 资源、研究数据或敏感构建输出

#### Scenario: 构建输入或产物含有未批准内容

- **WHEN** 构建检查发现真实/近似个人数据、研究记录、source map、开发日志、测试截图或非静态服务代码
- **THEN** 构建必须失败并阻止该产物进入本地或受控 LAN 研究会话

### Requirement: 工具链和直接依赖必须精确锁定并可重建

构建与验收 MUST 使用 Node.js `24.19.0` 及其捆绑 npm `11.17.0`。浏览器运行时直接依赖白名单 MUST 仅包含 `react@19.2.8` 与 `react-dom@19.2.8`；构建/类型直接依赖白名单 MUST 仅包含 `typescript@7.0.2`、`vite@8.2.2`、`@vitejs/plugin-react@6.1.0`、`@types/node@24.13.3`、`@types/react@19.2.18`、`@types/react-dom@19.2.4`；单元/组件测试直接依赖白名单 MUST 仅包含 `vitest@4.1.11`、`jsdom@30.0.1`、`@testing-library/dom@10.4.1`、`@testing-library/react@16.3.2`、`@testing-library/user-event@14.6.5`；浏览器/无障碍测试直接依赖白名单 MUST 仅包含 `@playwright/test@1.62.1` 与 `@axe-core/playwright@4.13.0`。React 与 React DOM 版本必须精确匹配；所有直接依赖必须使用精确版本，传递依赖必须由 `package-lock.json` 固定，安装必须使用 `npm ci`，不得以范围版本、浮动标签或白名单外直接依赖替代。

**Traceability:** FR-24、FR-25；AC-15、AC-25、AC-26；ADR-0001 §5.1.1。

#### Scenario: 使用批准锁文件安装

- **WHEN** 干净 checkout 以批准的 Node.js/npm 执行 `npm ci`
- **THEN** 安装结果必须严格来自 `package-lock.json` 与直接依赖白名单；锁文件缺失、漂移、版本不匹配或安装失败时不得继续构建或启动服务

#### Scenario: 出现白名单外或浮动直接依赖

- **WHEN** package manifest、锁文件或构建证据引入白名单外直接依赖、范围版本、远程 ESM、运行时包管理器或 React/React DOM 版本不匹配
- **THEN** 该构建必须被拒绝，并要求先完成 ADR-0001 的触发式复审

### Requirement: 浏览器运行时必须保持纯客户端且无产品数据服务

浏览器运行时 MUST 只处理当前页面内存中的会话数据和随构建提供的本地资源；不得依赖应用后端、业务 API、数据库、身份认证、同步、跨会话恢复、Router、外部状态库、UI 组件库、Service Worker、PWA manifest、Cookie、Web Storage、IndexedDB、Cache Storage、剪贴板或分析/错误上报/会话重放。除用户明确触发的本地 JSON/Markdown 下载外，不得把原始会话数据或派生结果交给任何应用、研究或第三方服务。

**Traceability:** FR-15、FR-16、FR-17、FR-23、FR-24；AC-13、AC-14、AC-15、AC-22、AC-23、AC-25；ADR-0001 §1、§5.1、§6.3。

#### Scenario: 浏览器加载并完成一次合成会话

- **WHEN** 浏览器完成静态资源加载并执行输入、计算、查看依据、决定和导出预览流程
- **THEN** 会话状态只能存在当前页面内存，且流程不需要后端、账户、数据库、持久化存储、同步、PWA 安装或远程服务

#### Scenario: 运行时尝试引入未批准能力

- **WHEN** 构建或浏览器行为出现服务端 API、Service Worker、PWA manifest、分析/错误上报、会话重放、远程插件或默认持久化
- **THEN** 该原型必须停止交付且不得标记为 `Prototype Accepted`，直到适用的 PRD/ADR/OpenSpec 变更完成批准并重新验证

### Requirement: 本地交付必须默认 loopback 且受控 LAN 只能显式启用

研究服务 MUST 默认使用项目锁定版本的 `vite preview` 提供已构建的静态产物，并严格绑定 `127.0.0.1:4173`；端口冲突、自动换端口、广泛绑定或无法核对构建版本时 MUST 失败关闭。`vite preview` 仅可用于研究者控制的本地/受控 LAN 研究和验收，绝不能称为生产服务器。跨设备或 iOS Safari 验收时，LAN 模式 MUST 仅绑定已核验的研究者控制地址与 `4173`，并禁止 `0.0.0.0`、公共网络、酒店网络、访客网络或无法说明管理/日志边界的网络。云托管、公开 URL、长期远程访问和任何未批准的静态托管均属于未批准范围。

**Traceability:** FR-24；AC-01、AC-15、AC-25；ADR-0001 §4.1、§5.1、§5.1.2、§5.3。

#### Scenario: 默认 loopback 启动

- **WHEN** 研究者在单设备上启动已核验的研究构建
- **THEN** 服务只能监听 `127.0.0.1:4173` 且启用 strict port；端口不可用或实际监听地址/构建标识不符时服务不得开放

#### Scenario: 受控 LAN 验收

- **WHEN** 跨设备或 iOS Safari 验收获得明确授权并核验设备、接口、网络和开始/结束时点
- **THEN** 服务只能短时绑定指定研究者控制 LAN 地址的 `4173`，URL 不得包含研究编号、参与者标识、购买内容、查询参数或其他敏感信息，会后必须关闭服务

#### Scenario: 试图使用公共或云托管路径

- **WHEN** 交付配置要求 `0.0.0.0`、公共/访客网络、云静态托管、公开 URL 或把 `vite preview` 作为生产服务
- **THEN** 交付必须被拒绝并保持停止；只有新增或修订并获批准的 ADR 才能重新定义该边界

### Requirement: 静态响应必须提供安全头并禁止缓存

静态服务对 HTML、脚本、样式、图像、字体及其他静态响应 MUST 提供 `Cache-Control: no-store`，并提供至少能阻止运行时外连、表单提交、对象加载和嵌入的 CSP：`default-src 'self'`、`connect-src 'none'`、`form-action 'none'`、`object-src 'none'`、`base-uri 'none'`、`frame-ancestors 'none'`；脚本、样式、图像和字体只能来自构建内必要资源。服务还 MUST 提供不低于 `X-Content-Type-Options: nosniff` 与 `Referrer-Policy: no-referrer` 的安全默认值，不得通过缓存、代理或头部放宽零外发边界。

**Traceability:** FR-17、FR-24；AC-15、AC-25；ADR-0001 §5.1.2、§6.3。

#### Scenario: 响应头满足批准边界

- **WHEN** 浏览器请求研究构建的文档或静态资源
- **THEN** 响应包含 `Cache-Control: no-store`、规定的 CSP 和安全默认头，且资源来源只落在同一静态服务及构建内必要资源

#### Scenario: 安全头或缓存策略不合格

- **WHEN** 任一静态响应缺少 `no-store`、CSP 放行外部连接/表单/对象/嵌入，或资源由远程来源提供
- **THEN** 该构建不得进入研究会话，且必须在修复并重新验证前保持停止

### Requirement: 静态资源之外必须零网络请求且不得写浏览器持久状态

在初始文档及其同源静态资源加载完成后，原型 MUST 不产生任何同源应用请求或外部请求；不得使用 `fetch`、XHR、WebSocket、Beacon、表单提交、动态远程模块、第三方字体、CDN、远程脚本、外部模型或分析请求传输会话数据。原始输入、派生结果、决定和复盘条件 MUST 不进入 Cookie、Web Storage、IndexedDB、Cache Storage、URL、服务端、普通日志或剪贴板。

**Traceability:** FR-15、FR-17、FR-23、FR-24；AC-14、AC-15、AC-23、AC-25；ADR-0001 §5.1、§6.3。

#### Scenario: 网络捕获完成主流程

- **WHEN** 使用合成 fixture 完成主流程、异常流程、查看依据和两种格式预览，并检查浏览器网络捕获
- **THEN** 仅允许加载当前静态服务提供的文档和构建资源，不得出现应用接口、外部域名、遥测、分析、错误上报或包含产品数据的请求

#### Scenario: 检查浏览器状态和导出路径

- **WHEN** 在输入、修改、取消导出、成功导出和失败重试后检查 Cookie、Web Storage、IndexedDB、Cache Storage、URL 与剪贴板
- **THEN** 除用户明确选择的本地下载文件外不得存在会话数据副本，且导出失败不得通过网络或持久化兜底

### Requirement: 访问日志和终端输出必须不持久化且不含敏感值

本地或受控 LAN 静态服务 MUST 不持久保存访问日志；不得重定向或配置文件日志。终端输出只能包含非敏感的启动、版本、停止和错误信息，MUST 不包含收入、工时、购买价格、价值期待、决定依据、派生结果、研究编号、参与者标识、URL 敏感字段或原始请求元数据。若服务、终端、操作系统或网络环境产生无法关闭或无法验证处置的持久 IP、User-Agent、访问时点、URL 或输入记录，交付 MUST fail-closed。

**Traceability:** FR-17、FR-24；AC-15、AC-25；ADR-0001 §5.1.2、§6.3、§8.3。

#### Scenario: 正常会话的日志检查

- **WHEN** 研究者在会话前后检查服务进程、终端、工作目录和可能的日志位置
- **THEN** 不存在持久访问日志或敏感终端输出，且检查结果只保留非敏感技术证据

#### Scenario: 发现持久元数据或敏感输出

- **WHEN** 工具或环境产生无法关闭、无法删除验证或包含会话敏感值的日志/终端记录
- **THEN** 必须立即停止服务和研究会话，处置并验证意外副本；无法证明完成处置时不得恢复交付

### Requirement: 目标浏览器、键盘和 VoiceOver 路径必须可完成

原型 MUST 在验收时当前稳定版桌面 Chrome（macOS 与 Windows）、macOS Safari 和 iOS Safari 上支持四阶段核心流程及导出入口，并必须可仅用键盘完成；macOS VoiceOver 与 iOS VoiceOver 必须能理解标题、标签、输入错误、焦点、状态、单位、证据状态、导出敏感提示、取消、失败和成功反馈。自动化无障碍扫描只能作为补充，不能替代键盘、桌面和移动 VoiceOver 的人工验收。

**Traceability:** FR-01、FR-18、FR-23、FR-25；AC-01、AC-16、AC-23、AC-26；ADR-0001 §3、§5.1.1、§9.1。

#### Scenario: 目标矩阵中的核心流程

- **WHEN** 在固定版本的目标桌面/移动浏览器中使用合成 fixture 依次完成说明、输入确认、理解/推演、决定和导出入口
- **THEN** 每个目标浏览器都能完成流程，键盘路径不依赖指针或颜色，且读屏能获得同等的状态、错误和操作反馈

#### Scenario: 自动扫描通过但人工路径失败

- **WHEN** 自动化 axe 或浏览器检查通过但键盘或 VoiceOver 无法定位控件、理解状态或完成导出
- **THEN** 不得把原型标记为验收通过，必须按人工可访问性失败处理

### Requirement: 非必要动态必须减少并尊重用户的减少动态偏好

界面 MUST 尊重 `prefers-reduced-motion`，并对非必要动画、闪烁、自动轮播、倒计时、强制等待和依赖动态效果理解状态的交互提供静态或减少动态表现。任何关键数值、错误、导出结果、退出路径和决定状态 MUST 不以动画、颜色、声音或时限作为唯一传达方式，不得用动态效果制造催促或焦虑。

**Traceability:** FR-18、FR-19；AC-16、AC-17；ADR-0001 §3、§5.1.1。

#### Scenario: 启用减少动态偏好

- **WHEN** 浏览器或操作系统启用减少动态设置并完成主流程
- **THEN** 非必要动态被移除或显著减少，所有数值、状态、错误和操作反馈仍以可读文本和可操作控件提供

#### Scenario: 状态只能通过动态效果表达

- **WHEN** 关键状态、错误或决定结果只能通过动画、颜色、声音或倒计时被识别
- **THEN** 该交互必须被视为不合格，直到补充不依赖动态的可访问表达

### Requirement: 合成会话必须满足固定实验室性能预算

在 ADR-0001 记录的目标设备、网络配置和最大允许会话数据下，性能验收 MUST 只使用批准的合成 fixture，并分别满足：首个可用界面不超过 `3s`，输入后的计算与状态更新不超过 `100ms`，导出预览不超过 `500ms`，单一格式生成不超过 `1s`。测量过程 MUST 不引入真实用户性能遥测、分析事件或会话追踪。

**Traceability:** FR-25；AC-26；ADR-0001 §3、§5.1.1、§9.1。

#### Scenario: 最大合成会话性能测量

- **WHEN** 在记录的目标设备、网络和最大合成会话数据下测量首次可用、输入重算、导出预览和单格式生成
- **THEN** 四项耗时分别不超过 `3s`、`100ms`、`500ms` 和 `1s`，并生成不含个人数据的可审计性能证据

#### Scenario: 性能测量试图外发或收集真实数据

- **WHEN** 性能工具、构建或运行时试图发送真实用户事件、网络遥测、分析或会话追踪
- **THEN** 测量必须停止并判定为违反隐私边界，不得以性能达标抵消该失败

### Requirement: 每个研究构建必须带有可核验标识和摘要

每个可启动的研究构建 MUST 具有不含敏感输入的构建标识，并提供覆盖静态产物、`package-lock.json`、Node.js/npm、构建配置以及适用规则/导出版本的 SHA-256 摘要证据。构建标识至少能够关联批准的 Git commit、构建版本和生成时点；研究会话前 MUST 核对标识、锁文件、配置和产物摘要，任一不一致时不得启动服务。

**Traceability:** FR-24、FR-25；AC-01、AC-15、AC-25、AC-26；ADR-0001 §3、§5.1.2、§8.2。

#### Scenario: 版本一致的构建启动

- **WHEN** 会话前核对构建页面/证据中的标识、Git commit、Node.js/npm、锁文件、配置、规则/导出版本和 SHA-256 摘要
- **THEN** 所有值一致时才允许按本 capability 的 loopback 或受控 LAN 边界启动服务

#### Scenario: 产物摘要或版本不一致

- **WHEN** 产物、锁文件、配置、构建标识或摘要与已批准证据不一致，或标识包含输入/参与者/购买敏感信息
- **THEN** 服务必须保持停止并要求恢复完整已验证构建单元，不得只替换单个页面文件或绕过核对

### Requirement: 供应链必须在安装前后完成可审计的 fail-closed 检查

依赖供应链 MUST 以精确版本和 `package-lock.json` 为准，且必须对直接/传递依赖、许可证、安装脚本、来源/完整性与安全通告进行可审计检查。任何白名单外直接依赖、未说明的安装脚本、许可证冲突、未处置的关键安全通告、无法解释的传递依赖漂移或无法重现的 `npm ci` 结果 MUST 阻止构建和研究交付；浏览器运行时不得加载未随包审计的远程代码。

**Traceability:** FR-24、FR-25；AC-15、AC-25、AC-26；ADR-0001 §3、§5.1.1、§7、§9.1。

#### Scenario: 供应链审计通过

- **WHEN** 干净环境完成 `npm ci`，并对解析后的依赖图、许可证、安装脚本、来源完整性和安全通告形成审计证据
- **THEN** 只有无未处置关键风险、无白名单外直接依赖且与锁文件一致的构建才可继续

#### Scenario: 供应链审计发现关键风险

- **WHEN** 审计发现未处置关键漏洞、许可证冲突、恶意/未说明安装脚本、来源完整性不明或直接依赖越界
- **THEN** 必须 fail-closed，停止构建和服务，并在复审或批准替代依赖前不得交付

### Requirement: 会话结束必须清除运行状态并留下安全退出证据

用户刷新、关闭页面或主动退出时，应用 MUST 清除当前页面内存和临时下载资源且不可恢复。研究会话整体结束、取消或发生关键失败时，研究者还 MUST 关闭所有原型页面、停止服务进程、关闭监听端口，并检查 Cookie、Web Storage、IndexedDB、Cache Storage、URL、终端和工作目录没有会话数据残留。已由用户下载的 JSON/Markdown 文件是用户设备上的外部副本，原型 MUST 明确不能召回、修改、恢复或删除该副本；关闭服务不得被描述为已删除用户下载文件。

**Traceability:** FR-14、FR-16、FR-17、FR-23；AC-14、AC-15、AC-23、AC-25；ADR-0001 §5.1.2、§6.2、§8.3；ADR-0003 §7、§8。

#### Scenario: 页面刷新只清除应用会话

- **WHEN** 用户在研究会话中主动刷新、关闭页面或退出原型
- **THEN** 当前页面内存状态和临时下载资源 MUST 不可恢复，浏览器持久状态保持为空；应用不得声称该页面动作已经停止研究者控制的静态服务或删除已下载文件

#### Scenario: 研究者正常结束整体会话

- **WHEN** 研究者确认本次研究会话整体结束或取消
- **THEN** 研究者 MUST 关闭剩余原型页面、停止服务进程并确认 `4173` 端口关闭，完成浏览器/终端/工作目录 readback，同时如实保留已下载文件由用户控制的边界

#### Scenario: 关键隐私或信任失败

- **WHEN** 检查发现意外外发、持久化、敏感日志、错误导出或 LAN 暴露
- **THEN** 必须立即停止服务和全部研究分发，关闭端口并定位/处置意外副本；在根因、范围、修复和相关验收未完成前不得恢复

### Requirement: 回滚必须恢复完整的已验证研究交付单元

回滚 MUST 同时恢复上一份已验证的 Git commit、静态产物及其摘要、`package-lock.json`、Node.js/npm、构建配置、规则版本和导出版本；不得只替换单个 JavaScript/CSS 文件或依赖当前页面缓存。回滚完成后 MUST 重新核对构建标识、网络、存储、日志和适用验收条件；代码回滚不得被描述为可以召回用户已经下载的文件。

#### Scenario: 构建或配置回滚

- **WHEN** 当前构建、配置、依赖或静态交付出现可复现错误且上一份整体已验证单元可用
- **THEN** 必须整体恢复上一份单元，重新完成版本、摘要、端口、响应头、网络、存储和关键验收 readback 后才可重新开放

#### Scenario: 已下载文件无法回收

- **THEN** 回滚只能影响后续构建和会话，必须明确既有文件仍由用户及其设备控制，原型不得声称能够远程删除或召回
