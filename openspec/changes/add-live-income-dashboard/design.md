# Design

## Context

动机见 proposal.md。当前 `App.tsx` 用 React 状态保存表单/确认/决定并提供 `createExportJson`；`calculation.ts` 用 BigInt、有理数和 `resolveWorkTime` 的 52/12 平均月工时；`assist-flow.ts` 控制有界字段与追问。现有测试主要为纯函数及服务端静态渲染，不能证明浏览器持久化或动态行为。依赖只有 React 与开发工具，没有日期、状态或存储框架。

RFC-0001、PRD-0003、ADR-0008 已记录 Q1–Q13，但仍是 Review；本次只创建 OpenSpec 规划。开始 apply 时先使已确认产品决定在上层文档生效，再改运行时代码；规划完成不能被写成产品验收或 RFC Implemented。

## Goals / Non-Goals

**Goals:** 一条共用精确计算路径、可复算的日历依据、一个本地状态文档、不可被资料更新改写的收藏；在现有组件和测试上直接扩展。

**Non-Goals:** 不引入账户/后端存储、云同步、状态管理框架、通用事件历史或持续后台任务；不把旧购买文件转换为无法追溯的新资料。

## Decisions

### 1. 将日历计算作为纯领域函数接入现有精确计算

新增小型 `src/domain/income.ts`，接收资料与显式 `now`，返回当月总工作秒数、今日/本月已过去秒数、速率/累计与不足原因。沿用 `calculation.ts` 的金额校验、有理数和证据状态；仅提取必要共用函数，不复制金额算法或建立计算策略框架。

资料保存 CNY 月收入、IANA 时区、具体星期集合、每日时段（开始、结束、明确的结束日偏移 0/1）、日期覆盖、默认/用户修改来源及更新时间。特殊日期以开始日期的工作安排为准，跨午夜时段按自然日/月边界裁切计入，计算月首时包含前一日可能跨入的时段；同一天及相邻日重叠均拒绝。日期覆盖工作日采用相同每日时段。

用原生 Date 与 Intl 获取保存时区的日历信息，时段端点转换必须反向验证并识别唯一候选；不存在或重复的本地时刻明确降级，不采用宿主时区或悄悄猜夏令时偏移。用普通日期、跨日/月、DST 缺失/重复的固定样例验证转换后再接 UI。先不引入日期库；不能可靠解析的输入按 spec 拒绝或降级，不能牺牲正确性求兼容。

分母是当月所有有效工作区间的秒数，分子是与今日/月初到 now 区间的交集；金额保持精确分有理数。普通累计显示两位小数，速率增加展示位数或显示小于阈值，不要求每次刷新都跳一分钱。`now` 来自当前时刻，定时器只触发重绘，不累加钱、不持久化计时器。

替代方案：全年平均工时不能保证每月累计等于月薪；逐 tick 累加会在后台挂起时漂移，所以不采用。

### 2. 首页与购买共享资料，但草稿不反写

`App.tsx` 管理首填/看板/设置/购买/收藏的直接视图状态；必要时提取 `IncomeDashboard` 和资料表单，避免路由或状态框架。原购买组件保留计算、确认和决定能力，`AssistInput` 变为购买内按需打开。

进入购买时复制当前资料和当月日历依据到草稿。增加显式日历工时输入变体，`calculateDecision` 使用总秒数的精确有理数小时，不先转成三位小数小时字符串。用户不改比较条件时，首页和购买时薪一致。若用户主动选择现有直接月工时或小数周作息作为单次比较覆盖，保留旧校验/公式但明确标出“本次比较使用不同工时口径”，不更改资料；这用于兼容现有手动和对话能力，不作为新主流程。

已保存资料是一种可追溯来源，不要求模型从本轮话语重新识别。默认 8 小时只来自可见产品设置，不得被标成模型从“双休”推断的事实。明确改口使草稿结果/决定失效，保留原有等待响应隔离；任何不能映射成具体日历的对话作息保留为单次比较覆盖，不猜星期或写回资料。

购买确认与收藏均不强制做决定，收藏旧结果与当前草稿分开。清空购买草稿与清空全部资料使用不同动作，避免原 `clear()` 语义误删。

### 3. 单文档本地保存与完整替换

新增 `src/domain/local-data.ts`，直接使用一个带版本/revision 的 localStorage 文档：最新 profile、favorites。不要建 repository 接口或通用迁移引擎。对读写、导入、删除使用同一校验/序列化路径；捕获权限/配额错误，写入成功才更新“已保存”状态。

在浏览器原生 Web Locks 独占锁内重读 revision，再执行一次 setItem/removeItem；revision 不符要求重载。storage 事件只通知，不自动覆盖未保存草稿。若环境不能提供受保护的写入能力，明确降级为临时使用而非承诺可靠保存；测试模拟不可用路径。此选择避免仅检查 revision 后同时写入造成丢失，不增加同步服务。

读取损坏或未知版本保留原串，提供备份原内容或清空入口；不默认覆盖。恢复先校验完整文件，再展示替换范围，确认后在同一写锁中检查基线并一次替换。取消、校验失败和提交失败均保持旧文档。清空成功后撤销所有未完成对话/草稿状态，晚到响应无权恢复它们。

收藏保留原输入/结果快照，不在启动时用最新规则重算。保存最新资料而非全部编辑历史满足低负担使用；不承诺本地加密和浏览器清理后恢复。

### 4. 新旧公开格式显式区分

`zhiguan-purchase-decision@2` 继续承载五项结果、决定代码、value_expectation、review_condition 和各字段 evidence；增加/明确 `comparison_month`、`time_zone`、`ruleset_version`、带模式的 `work_time_basis`。日历模式记录原始星期/时段/日期覆盖及精确总秒数；主动覆盖模式记录对应直接工时或原有周平均换算依据，不把不同来源都叫日历计算。精确值沿用字符串 numerator/denominator，不能用 JSON number 存大金额。

`zhiguan-local-backup@1` 外层包含 exported_at、profile 与 favorites；收藏包含 id、saved_at 和完整 @2 snapshot。校验格式版本、结构、精确数和 evidence；只恢复本版支持的数据，不执行文本或读取文件内链接。导出函数可以从 App 提取成直接函数供收藏和备份共用，不建格式注册器。

旧 @1 下载文件不更改，不自动导入、猜月份或升级。新 app 的导出走 @2；保留旧规则单元测试作为兼容事实，不要求继续提供双版本导出 UI。

### 5. 验证围绕真实风险

扩展既有 Vitest：日历纯函数的合成月份、休息/边界/DST/非法值；存储失败、完整恢复、revision 冲突和快照不变；购买同口径与主动覆盖、既有估算/余量/对话约束。SSR 测试只验证初始结构，不代替浏览器交互。

运行 `bun run check`，并在真实浏览器验证首次输入、刷新/重开、修改资料、收藏、备份往返、取消/失败与键盘窄屏/减少动态；网络观察确认看板与本地操作无 Jev 请求。无需为本变更重新调用真实模型，只有改变协议时才补现有 Python 离线检查。

## Risks / Trade-offs

- [估算被误认成到账] → 标题与简短依据持续可见，结果/收藏保持 estimated；不加资产累计、打卡或刺激性奖励。
- [时区或月边界算错] → 共用单一日历函数、可注入 now、唯一时刻验证，不能解析就降级。
- [localStorage 容量及共享浏览器隐私] → 不存聊天/逐秒日志，失败提示、备份和删除；不承诺加密或无限收藏。
- [旧主 spec 与新方向冲突] → 用完整 MODIFIED requirements 修订，不只追加平行规则；apply 首步同步治理，归档时按 OpenSpec 同步主 spec。
- [资料更新改变历史表象] → 看板明确按当前资料重算，收藏是冻结快照，更新前提示。

## Migration Plan

1. apply 开始先落实本变更引用的 RFC/ADR 决定和产品文档，保留旧版本/验证历史；未实施的项目仍标未实施。
2. 新持久化为空时走首次设置，不恢复不存在的内存会话；旧下载文件保持用户控制。已有损坏/未知版本不自动迁移。
3. 依次接入日历、存储、看板及购买快照，在本机完成检查与浏览器验收后才描述为已实现；公开发布不属于本变更授权。
4. 如需回滚，先保留新版本的备份/清空出口，不自动擦除存储，不把 @2 转成 @1。新旧程序的数据隔离不得被当作用户资料已删除。
