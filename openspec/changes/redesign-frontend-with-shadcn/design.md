# Design

## Context

动机与范围见 [proposal.md](proposal.md)，页面顺序见[已确认页面方案](../../../docs/design/frontend-page-plan.md)，视觉值和控件约定以根 [DESIGN.md](../../../DESIGN.md) 为单一来源。

变更前，应用由 `src/main.tsx` 加载 `src/app/IncomeApp.tsx` 和 `src/styles/app.css`，使用 `setup / dashboard / purchase / favorites` 内部页面状态。购买交互在 `src/app/App.tsx` 与 `src/app/AssistInput.tsx`；计算、本地资料和快照已有独立领域模块。当时的依赖只有 React 与构建测试工具，尚未接入 Tailwind 或 shadcn/ui。

现有界面测试主要使用 `renderToStaticMarkup`；其中首次设置测试绑定旧 CSS class，购买测试明确断言「价格优先、对话折叠」。后者需随本次入口顺序变更更新，不能把旧断言失败误判为业务回归，也不能删除主动发送、证据与失败接续的保护。

## Goals / Non-Goals

**Goals:**

- 在现有页面与处理流程中接入统一主题和控件，保持一次资料编辑、一个购买草稿、原有确定性计算与保存事务。
- 将已确认的视觉层级落实为可测的导航、展开、焦点和异常反馈，并在有实际 CSP 的构建环境验收。

**Non-Goals:**

- 不新增路由、全局状态框架、表单框架、图表或第二套 UI；不借重设计拆分全部现有组件。
- 不迁移本地数据，不修改 API、金额与日历算法、备份和购买快照格式；不把未收藏的购买内容持久化。

## Decisions

### 1. 主题和组件只接入现有应用

按官方[已有 Vite 项目接入流程](https://ui.shadcn.com/docs/installation/vite)使用 Bun，选择 Radix 组件基底与 Lucide。Tailwind v4 编译入口合并进 `src/styles/app.css`；新增的 `components.json` 指向该文件。当前没有路径别名，实施时在 Vite 与现有单一 `tsconfig.json` 中新增一致的 alias，将 `@/*` 解析到 `src/*`。保留已有 React 插件、`base`、代理、测试和安全头，不整份覆盖模板配置。

根 DESIGN.md 的完整颜色值与 `@theme inline` 映射合并为一套主题，做法参照[官方主题文档](https://ui.shadcn.com/docs/theming)。采用 `src/components/ui` 下的官方源码组件与其实际必需的工具；统一 Button variants 和字段错误关联。只引入正在使用的控件，日期、时间、文件选择保留原生输入。项目已有 Node 类型依赖，无需重复添加。

未采用整站模板或并行样式入口：它们会带入无关结构并造成主题漂移。迁移结束删除已无消费者的旧样式；迁移期间必须检查旧全局选择器和 Tailwind 基础样式对尚未迁移页面的影响。

### 2. 首页采用开放主数字区，设置仍在页面内

按确认方案重排现有页面，而不改 `calculateIncome` 等领域输出。首页一个居中的主金额，两项辅助指标组成一组；说明和设置左对齐。估算限定、有效零与数据不足的区别常显；错误、未保存和冲突提示不藏进折叠区。

顶栏收藏按钮不再依赖收藏数量。设置按钮控制首页设置区域展开，待区域呈现后定位并将键盘焦点移到设置标题；减少动态模式不使用平滑滚动。计算依据在数字下就近展开，购买入口使用轻操作。返回页面后将焦点移到对应标题；收入每秒刷新不移动焦点、不逐秒播报。

沿用现有表单草稿、取消、校验与保存函数，展开设置本身不保存、不重算。未采用侧栏或长表单弹层：当前只有少量页面，页面内设置可保持手机阅读顺序和错误上下文。

### 3. 购买入口重排不改变对话能力

`App.tsx` 初始呈现一句话输入和清楚的手动入口；已有基础资料继续预填，用户无需重新描述。切换只改变呈现方式，复用现有草稿、字段证据和摘要确认；保持 `draftRevision`、请求取消和过期响应隔离。无需新建对话模型或草稿仓库。

只有用户主动发送才调用既有 API；手动填写可以完成完整任务。服务失败保留输入，继续提供手动接续。已填写资料不因切换提升证据等级；修改、确认、决定、收藏和导出仍使用原有处理流程。这里仅改变购买页内的输入顺序，不把对话放到收入首页或首次设置。

### 4. 收藏和确认弹层复用现有事务

收藏采用语义列表，信息来自已保存快照，详情按需展开。空态提供购买入口；若没有可用收入资料，先到基础设置，不创建虚构资料。重新试算继续使用原有逻辑产生当前购买草稿，历史快照不变。

将现有五类确认统一为带准确范围说明的 AlertDialog：保存已有资料并重算、覆盖恢复、清空、单项删除、重新载入并放弃编辑。取消为默认焦点。把同步确认替换为界面确认时，保留待确认的操作对象与版本；只有确认后才执行对应写入或放弃编辑。确认期间若资料已更新、操作已取消或页面已离开，不能用陈旧对象覆盖新资料；沿用 revision、Web Locks、busy 与操作失效检查。无需通用确认服务或操作队列。

### 5. 在真实安全约束下验证组件

当前 Vite dev 不设置 CSP，preview 使用 `style-src 'self'` / `script-src 'self'`，容器 Python 服务也限制为同源资源。使用本地编译 CSS 与系统字体，静态资源留在现有构建产物路径内。

先用本次实际需要的折叠、选择与确认控件检查 preview 和容器下的运行时样式、焦点及控制台，再扩展到全页面。发现组件内联样式或样式注入被拦截时，优先在本地组件源码中使用静态 CSS 或等价原生控件；不为组件默认效果扩大 CSP。具体兼容性需实际渲染验证，当前未声称通过。

## Risks / Trade-offs

- 全局样式与 Tailwind 基础样式互相覆盖 → 分页面迁移并检查字段、列表、焦点和提示；完成后清理无用旧选择器。
- Radix 交互通过静态测试但被 CSP 影响 → 分别在 preview 与 Docker 静态服务验证资源和交互，不能以 dev 代替。
- 确认弹层变为异步后出现陈旧写入 → 沿用事务版本和操作失效机制，检查取消、并发更新、失败后原内容保留。
- 居中大金额在窄屏溢出或挤压说明 → 验证 320 / 375 / 414 / 768px、桌面与 200% 缩放，用完整长金额和长中文合成数据；不得裁切或换成无提示的单位缩写。
- 静态图和结构测试不能证明可用性 → 概念稿仅确认布局，运行界面另检键盘、读屏语义、减少动态与保存反馈；真实用户验证仍单独记录。

## Migration Plan

1. 以确认页面方案制作手机与桌面概念稿，覆盖首次设置、正常首页、设置展开和关键异常状态；仅使用明确标注的合成数据。
2. 接入最小依赖和主题，先验证受 CSP 约束的基础交互；再迁移首次设置、收入首页、设置、购买和收藏。
3. 更新受入口与结构变化影响的测试，运行 `bun run check`，完成规定宽度、状态和 preview / Docker 浏览器验收；同步页面文案和实现状态。
4. 此变更无需数据迁移。回滚 UI 时一起恢复组件、配置和锁文件到变更前版本，保留浏览器资料；回滚演练与正式发布只有实际执行后才能标为完成。
