# Design

## Context

动机及范围见 proposal.md，七项用户选择见 ADR-0007。现有 App 持有输入与确认快照，AssistInput 另持三字段候选；applyAssistFields 仅写空白项，收入未同时填入时税口径不能更新。服务只接受 `{text}`，prepare/decode 使用封闭候选选择；金额转换只接受正数且按金额精度处理，不能直接复用于零固定支出及小数时间。

现有 generationRef 保护描述编辑和取消，但未覆盖所有父级草稿修改。App 以输入对象与提交对象相等判断结果有效，修改后旧决定仍留存，重新确认会使它再次进入导出。辅助约数保护目前只覆盖收入和价格。

本变更同时涉及前端草稿、内部 API 和外发数据范围，因此保留设计文档。主规格的绝对“不上传”已按用户要求修正为主动使用 Jev 会发送已告知范围内的内容；现行文档的三字段限制仍须在实施中明确替换，不能将旧限制与新规则并列为现行承诺。

## Goals / Non-Goals

**Goals:** 共用一份可编辑草稿和一次确认路径；字段证据与语义状态分离；可验证地限制上下文、追问及异步写回。

**Non-Goals:** 不建设通用聊天代理、历史事件库、动态生成问题、云端会话或新的导出协议；不推断价值期待和决定。保持既有金额计算、工时换算和本机运行方式。

## Decisions

### 1. 复用输入，增加小型会话状态

App 继续持有输入与确认状态；AssistInput 改为默认展示的对话编辑入口，手动控件编辑同一草稿。不保留“候选确认填入”与“表单确认计算”两套动作。增加当前问题、每字段追问/跳过状态、当前请求版本及字段原文依据；它们只存在内存中，不进入导出。

识别状态 present/estimated/missing/ambiguous/unsupported 与是否已确认分别记录；草稿不得因模型返回 present 就被展示为 user-confirmed。整体确认时才转换为现有 DecisionInput 证据结构。沿用原有纯计算模块，不增加状态机依赖或聊天框架。

### 2. 追问由必要输入决定

按收入、税口径、价格、工作时间来源及其缺项的稳定顺序选择第一个待解决字段；用户一次补充多项时一并整理。已有合法数据、跳过项及已耗尽澄清机会的项不再问。首次必要问题之后最多一次澄清；明确不知道/跳过立即停止该项。用户后来主动补充仍可更新，不自动重启耗尽的追问。

信息齐备或无可继续追问项时展示摘要；即使有缺失，仍允许确认并显示局部不足。余量采用独立显式开启状态；描述中主动给出的余量信息先保留，不触发余量追问。已足够计算的基础结果不因未补完余量而受阻。

问题和快捷选项采用少量固定文案。明确按钮本地更新；自由回答才调用 Jev。不用模型决定下一步，不引入生成式回复。直接月工时与每周作息均复用现有输入模式；只有明确改用另一口径才切换，两个口径冲突时询问，不能自行偏选。

### 3. 有界字段补丁与候选依据

扩展现有 `/api/assist`，前后端同时发布。请求包含当前 text、已知枚举 questionId，以及按问题裁剪的 context；服务端拒绝未知键和非法类型，不直接将客户端对象整包转发。保留当前回答 2000 字符限制、请求体 8192 字节上限与有界候选数；超限明确失败，不静默截断原文。上下文过大时提供当前字段直接修改，不能无提示扩大上传范围。

响应为允许字段集合内的补丁：每字段区分未提及保留、明确赋值、未解决；赋值带原文片段与来源标识，未解决不能携带确定值。数字从原文候选选取并由代码换算；税口径、作息表达和明确确认使用固定枚举判断并关联原文，不接受模型生成任意数字。候选不得漏掉合法的时间小数；金额校验继续与工时校验分离，固定支出单独允许零值。每周天数大于 0 且不超过 7、每日小时大于 0 且不超过 24，精度使用现有领域规则。

初始描述不带历史上下文。当前问题只带解释该回答所需的字段及依据，例如税口径问题关联当前月收入；无当前问题的改口可以带允许修改字段的紧凑快照与对应原文，不能带完整聊天记录。服务端按 questionId 白名单进一步裁剪；价值期待、决定理由、结果与密钥均不进入模型状态。仅用于识别指代的旧数据不得成为用户未提供的新值来源；相关字段无法唯一判断时返回未解决。

“双休”可映射每周五天，但不补每日八小时；“房租三千”不成为完整固定支出总额；“没有固定支出”可整理零总额，覆盖确认仍独立处理。只接受用户明确表述的覆盖与本月付款，不能让模型高置信度代替授权。语义判断仍可能错误，因此摘要确认和虚构样本核验都保留。

### 4. 更新、估算与结果失效集中处理

所有对话、快捷项和手动编辑均走同一草稿更新路径。明确改口可以更新非空字段并标出差异；未提及字段不清空。新歧义涉及已有字段时标记未解决，计算时不使用旧值回退；无法定位字段时将可能受影响字段标为待澄清，提供一次澄清或明确放弃本次修改。澄清耗尽后仍可确认摘要，但受影响字段进入不足结果，不能卡住全流程或把更新当成功。

按字段保存近似依据，与现有 evidence 映射；统一估算开关不能擦除已识别约数。显式改成新的精确值才可更新该字段依据，单纯重新确认、切换界面或编辑显示形式不提升证据。作息派生月工时始终 estimated。

输入实际改变时使确认快照失效并清空当前决定、理由与旧 reviewCondition，提示需重新决定；保留独立的用户价值期待。选择清空决定而非引入版本历史，是为了在既有导出格式下避免旧决定绑定新输入。重新确认后未重选决定时导出 null，而非旧代码；这适用于所有输入入口。

### 5. 请求版本与失败接续

复用 AbortController 和 generationRef，每次草稿编辑、切换入口、取消、清空及新请求均推进版本并取消旧等待。响应必须匹配发出时的版本，且通过字段、枚举、数值与来源片段校验后才能更新；迟到结果直接丢弃。

不自动重试。超时、服务不可用或无效响应保留当前回答和已有草稿，展示重试与手动补充。页面打开不探测 Jev；首次发送前就地说明处理方、内容与停止边界，主动发送是本次请求触发，不每轮弹窗。服务继续回环绑定、同源/Host 校验、密钥服务端加载和正文禁日志。

## Risks / Trade-offs

- 中文简写、指代和口径冲突识别不稳定 → 候选依据、字段独立验证、歧义降级及一次摘要确认；不将前三字段实验当成新增字段证据。
- 对话可能比按钮慢 → 明确选项本地处理；用相同虚构任务比较主动输入次数、确认次数与完成情况，不只数输入框。
- 上下文携带财务内容 → 前后端白名单及长度限制，网络断言检查未发送无关字段；不声称本地清空能撤回服务商请求。
- 默认对话在服务未运行时不可用 → 手动入口始终可达并继承草稿；本轮不建设部署/健康探测系统。
- 清空旧决定需用户重新选择 → 只在输入确有变化时清空并解释原因，避免带出错误关联。

## Migration Plan

1. 实施开始时同步产品文档和 ADR-0007 状态，明确替代 ADR-0006 的范围限制并保留其历史实验；不得回写旧实验结果。
2. 扩展内部 API、离线样本与前端会话。保留 `zhiguan-purchase-decision@1` 和现有字段结构，不导出对话或会话内部状态，无存储迁移。
3. 以新虚构样本逐字段验证，覆盖多轮上下文、否定改口、零支出、小数作息和歧义；单样本每轮一次请求，关闭自动重试，分别报告服务与内容结果。未运行真实模型时明确该交付验证缺口；发现无依据填值或歧义强行确定则修正后使用独立样本验证。
4. 完成 Bun 检查、Python 离线检查与键盘/窄屏交互及网络检查；固定完整示例应一次输入加一次整体确认到达结果，缺工时示例只追问所缺项。
5. 回滚时可切换手动流程或还原前后端同批改动；停止辅助服务后已加载页面的手动流程仍可完成。公开部署不在本变更范围。
